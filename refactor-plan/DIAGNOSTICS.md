# 驗證與診斷

本文整理各層驗證、問題內容與 UI 標記、保存及產碼門檻。責任已確認，診斷資料格式與生命週期 API 仍可細修。總覽見[重構計畫入口](README.md)。

## 驗證與問題歸屬

各物件負責自己的合法性：NodeType 提供節點規則，Network／Stage／Graph 檢查相應結構與能力，Generator 及宿主回報產碼、編譯與套用問題。

較上層的診斷能力收集、歸屬及更新問題，暫以 `Grape.diagnostics` 作入口示意。它不重寫每個物件的驗證規則，也不決定所有畫面如何顯示。

問題需可追溯回報來源、所屬物件與必要的接口、接線、Stage 或圖路徑。各層摘要仍保留真正原因，不能把子節點的錯誤複製成多筆無法對照的不同問題。

## errors 與 warnings

Grape、Graph、Stage／Network、Node、Edge、Source、Host／Binding 等可辨識實體，都應能按需要查詢自己的 `errors` 與 `warnings`。這些入口包含問題內容，不只是布林旗標。

**有對應問題內容，就有標記的依據。** 不另維護一份容易與內容不同步的 showError／showWarning 真相。自身問題與子層彙整可區分查詢，但問題的原始位置不能遺失。

節點圖示、接線顏色、狀態列、問題清單、浮動診斷面板及定位導航，是 UI 對同一批問題的呈現。不同物件可以有自己的便利查詢方式，共同問題入口保持一致。

診斷記錄的確切 ID、欄位、集合、聚合方式與型別尚未定稿；目前固定的是內容、歸屬、可追溯與標記來源的關係。

## 保存與產碼門檻

| 目前狀態 | 保存或匯出圖文件 | 產生程式碼 |
| --- | --- | --- |
| 沒有問題 | 允許 | 允許 |
| 有 Warning | 允許 | 允許 |
| 有 Error | 允許 | 阻止受影響圖／目標的產碼 |

圖可以處於不合法但可保存、可載入修復的狀態。Warning 用於仍可運行但有相容性、效能等限制的內容。有效 Error 只要存在於本次圖／目標，就不能以「節點目前未連到輸出」自行略過；其他圖的 Error 不阻擋無關工作。

產碼前或產碼途中發現 Error，都不交付該次結果。圖的保存成功、產碼成功與宿主套用成功分開回報。宿主之前的編譯失敗必須與對應結果／版本關聯，不能永久阻擋已修正圖的新產碼；確切過期與清除流程待定。

診斷本身通常是執行期間的結果，載入圖後重新驗證，不強制寫入圖文件。保存的是圖的實際內容。轉換時斷線等一次性事件可保留在轉換報告或 log，不能假定重新載入一定能重建完整原因；保存報告的方式未定。

## status 與 log

status 表達目前狀態與問題彙整；log 保存處理過程、時間與歷史上下文。兩者可引用同一問題或工作結果，並提供更完整的閱讀入口。

當問題解除，物件當前 errors／warnings 與標記應更新；歷史發生過的事情仍可在 log 查看。歷史 log 不充當目前產碼是否被阻擋的依據，也不等於 Undo 的 History。

各層 status／log 的公開 API、保存期限、版本淘汰及 UI 呈現另行設計。
