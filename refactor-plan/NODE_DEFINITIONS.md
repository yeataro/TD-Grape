# 節點模組與型別

本文記錄節點能力的模組化、初始化、引用與介面分工。NodeType 是後續討論採用的名稱，取代早期 NodeDefinition 暫稱。它仍是一份共用定義，不要求每種節點都建立不同的 TypeScript class。總覽見[重構計畫入口](README.md)。

## Node 與 NodeType

Node 是圖內實例，持有自己的 ID、name、label、位置、設定、實際接口與輸入值；它引用已初始化的 NodeType，並能查回定義名稱及來源模組。

```ts
node.name;                 // 圖內名稱
node.nodeType;             // 共用定義
node.nodeType.name;         // 定義名稱
node.nodeType.generator;    // 產碼行為的引用，具體契約待細化
```

同一 NodeType 可由多顆 Node 共用。定義中的接口規格與每顆 Node 上建立的 Input／Output 分開；模式、型別選擇等實例設定可影響實際接口。NodeType 更新後可重新演算與驗證實例，不因此把模組實作保存進圖。

## NodeModules 與註冊表

節點能力集中放在 `NodeModules` 目錄，使用一般 TS／JS 模組的 import 與共用契約。它是清楚可維護的原始碼組織方式，也保留日後分開提供更新包、第三方授權內容與使用者擴充的入口。

模組可以直接引用核心公開的型別與共用能力。簡單計算模組可讀取 JSON 等定義表建立物件；Swizzle、Voronoi、Source 等不適合該表格表達的能力，可在獨立 TS 檔案定義。所有來源交付相同契約的 NodeType，不要求每種功能都塞進同一資料格式。

```text
NodeModules 中的多個模組
    ↓ import 並初始化；可讀表格或引用既有物件
完成並登記的 NodeType
    ├─ 新增選單與查詢
    ├─ 圖內 Node 的建立與初始化
    └─ 驗證與 Generator 查詢行為
```

`Grape.nodeModules` 表達模組的管理與查詢入口，`Grape.nodeTypes` 表達初始化後可用的節點型別；具體集合 API 仍可細修。一個模組可提供多個 NodeType，也可能提供 DataType 或共用 UI，因此目錄與 nodeTypes 不必逐項對應。

註冊表負責持有、查找與登記，模組提供定義的建構與初始化。定義先初始化再使用，不因每次新增 Node 重新讀取整批來源。NodeBuilder／NodeCreator 等名稱不另形成一層必要架構；只有需要的共用建構能力才抽出。

本輪不建立完整外掛安裝器、熱重載、沙箱或依賴管理系統。開發期與未來打包後保留相同概念的擴充入口；載入失敗應能回報，具體生命週期待定。

## 共用規格與可擴充行為

每個 NodeType 都要能提供可查詢的身分與來源、設定、接口規格、適用圖種類／Stage，以及驗證和產碼所需的行為。共用的是契約，不要求行為實作都長成同一張公式表。

節點可引用可重用的型別推導、分量組合、模式選擇或介面建構能力。能力分類及每個小型 helper 的清單不必在現在窮舉；新增模組應可擴充，不能被既有節點列表綁死。

NodeType 可引用自己的 generator，由目標 Generator 調用。每次產碼的暫存、符號、依賴與輸出保存在該次工作上下文，不保存在所有實例共用的 NodeType 上，詳見[產碼與目標相容](GENERATION_AND_TARGETS.md)。

模組可提供結構型別，但必須交付給對應作用域的 DataType 登記入口，使編輯器與產碼器能查詢；不能只藏在某個節點的 GLSL 字串裡。身分、作用域及名稱碰撞原則見[接口與接線](TYPES_AND_CONNECTIONS.md)。

## 共用接口建構能力

固定接口與動態接口都是正式用法。簡單 Operation／計算節點可以由表格提供固定接口；Swizzle、Voronoi 等獨立定義的節點可以自行決定接口是否隨設定變化。以獨立物件實作，不等於必須使用動態接口。

核心提供共用的接口定義、建立與更新能力；模組決定要哪些接口、規格來自哪裡、何時需要更新。核心負責建立實際 Input／Output、所屬 Node、身分、驗證及變更通知，不把個別節點演算法集中成全域分支。

表格讀取器、手寫 NodeType 與 Subgraph 模組都可使用相同能力。實際接口保存在 Node 上；UI 查詢這些物件。共用能力的正式方法與更新契約尚未定稿，不強制所有 NodeType 都實作一個動態接口解析器。

正常接口編輯應保留未改變接口的穩定身分，名稱與排列順序不充當全部身分資訊。定義版本相容時的按序回退，是另一種處理情境；精確識別與保留規則仍待細化。

## 子圖共用型別與個別定義

Subgraph 模組提供共用 NodeType，負責依引用的子圖定義建立實例接口、驗證與產碼。各張 Graph 的子圖定義持有自己的接口規格及內部 Network。

```text
Subgraph 模組 → 共用 NodeType（行為）
                           ↑
                    子圖 Node 實例
                           ↓
              圖內子圖定義（接口規格與 Network）
```

NodeType 不另外持有每份子圖接口的可獨立修改副本。使用者新增子圖定義，不需要把它提升為另一個已註冊 NodeType。Node 實際的 Input／Output 由共用建構能力依引用規格建立，因此外部 Edge 和 Parameter 查詢仍沿用一般節點規則。

共用建構方法放在核心，Subgraph 模組引用它；不需要將同一套方法複製到每份子圖定義。共享修改、獨立副本與圖內／資源庫歸屬見[圖與編輯器](OBJECT_MODEL.md)。

## Parameter 與動態接口

NodeType 可指定 Input 是否提供 Parameter。基本編輯方式可來自 DataType 及接口 style，再補範圍、clamp 或特殊樣式；沒有 Parameter 的 Input 仍是正式接口。

設定可以選擇演算法、維度、模式及分量組成，並改變實際接口。模型負責列出合法設定與接口、驗證型別及接線；畫布與參數面板查詢同一份模型。

編譯期條件分支是可選的產碼手段，不要求所有節點都使用 ifdef 或塞入所有分支。確實需要受控編譯期分支時，由產碼器管理符號與條件名稱。設定造成接口變化時仍須經模型驗證，不能只靠 GLSL 預處理器處理。

## 模組自訂屬性與狀態

模組可以定義自己的設定與資料結構，並透過共用契約登記為可辨識、可查詢的屬性。型別、預設值與編輯 style 等資訊可供共用能力使用；不要求每份自訂資料都拆成封閉清單中的已知元件或獨立資源。

例如下拉選單可編輯一個整數設定，選項值與顯示標籤分開；選單外觀本身不表示它必須成為 Uniform 或 Input。模組可使用簡單屬性的共用方法，也可提供處理自己結構的行為。

可編輯的自訂狀態仍須能參與變更通知、保存與復原。登記一個屬性不會自動使任意巢狀 JS 修改可被觀察。模組與核心的正式修改、序列化及還原契約尚待定義；局部快照／還原 hooks 是討論方向，不在此固定名稱與實作。History 分工見[操作與更新](UPDATES_AND_HISTORY.md)。

## 模組持有 Shader helpers

Shader helper 的內容與引用由模組維護，同模組的 NodeType 可共用。Generator 收集實際需要的定義、安排依賴、配置合法且不衝突的名稱，並在相應 Shader 中避免同一 helper 重複輸出。

不同模組的同名 helper 不自動視為同一個函式，也不靠程式文字相似就合併語意。核心提供引用與組合所需的共用能力，不要求先建立收納全部 helper 內容的全域函式庫。引用身分、依賴與程式片段格式仍待細化。

## UI 與模型分開

Node、NodeType 的核心資料與運算能力不持有 DOM。模組可以另外提供相應的 NodeView／UI 實作，經由模型接口查詢及操作 Node；沒有畫面仍可建立、驗證及產碼。

官方提供可重用的基本節點外觀、主題、標題、內文、行列配置及參數控制項。自訂 UI 可沿用全部、部分或替換內容，例如自訂標題、內文或 Color Ramp 編輯器；需要回應的編輯器共同行為仍須遵守契約。細部互動與佈局契約尚未定稿。

嚴格共用的邊界是實際接口及其身分、型別、連線與模型規則。自訂視圖不能另造一套與模型不一致的接孔或私自繞過驗證。共用控制項由主題設定管理；自訂內容也可以提供自己的樣式，不能因視圖客製就把資料責任搬到 UI。

Color Ramp 是用來檢查擴充空間的案例；常數資料、Uniform／陣列及 Texture 等模式的取捨與自動切換尚未定案，不列為已實作或必須同時支援的規格。

整體 UI 的 Panel 模組、共用 Widget 與 Manager 分工見[UI 與佈局](UI_ARCHITECTURE.md)。NodeView 是節點的呈現能力，不因同樣可模組化就等同一個 Panel。

## 模組來源與缺少實作

圖保存 NodeType 的識別、來源模組資訊及實例資料，缺少模組時應能指出需要的來源，保留資料供日後修復。模組資訊應容納身分、版本、來源及授權描述；精確欄位待定。

缺少模組的診斷、安裝位置及使用者如何補齊是不同責任。現在不承諾自動安裝、下載或在圖內嵌入可執行模組。

定義更新時可提供相容處理；未提供時按接口順序對應並驗證，不能保留的連線要警告。方言節點由後加入的模組宣告轉換關係，詳細規則見[產碼與目標相容](GENERATION_AND_TARGETS.md)。
