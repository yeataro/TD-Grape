# 陣列與結構：後續工作計畫

日期：2026-09-18。狀態：設計與執行順序計畫，尚未實作本計畫的陣列／結構圖功能。本次請求是整理計畫，不啟動產品修改、TD 同步或背景持續工作。

## 先讀這一段

接下來先把已確認的操作固定下來，再建立圖、型別、來源與產碼共用的基礎，最後接上最小 UI 和 TD 真實來源。TOP 與 MAT 一起列入驗收；可用能力不因 UI 暫時不好做而被刪除。

已確認的操作是：指定元素型別與長度建立陣列；使用 `Array[i]` 取項，索引自動 Clamp；以 Replace 替換指定位置的一項。使用者自行定義結構的介面可以延後，現在的底層需能承接 TD 既有結構及未來自訂定義。

使用者現在不需要繼續回答抽象問題。工程盤點、資料模型、宣告依賴、跨 Stage 驗證及效能由開發端負責。之後只把初始化、沒有元素、Replace 越界三組尚未定案的行為，整理成可操作的例子一次 review。

既有高優先的搜尋排序可以先獨立收尾；矩陣異型算術是另一筆未完成工作。兩者不與陣列改動混成一次交付。Uniform 即時同步仍維持調查範圍。

## 1. 已核對的起點

- 主倉基線為 `85de47b`；最近產品交付是 0.8.90。依既有交付紀錄，Convert／Matrix Convert 分流、double 運算擴充、矩陣 UI 修正及拉線搜尋效能修正已同步 TD 並保存。本次整理未重新執行 TD 驗證，不能把歷史測試當作新增功能的驗收。
- 型別契約目前描述 38 種值型別及 sampler2D；一般陣列／具名結構尚未成為圖接孔的一般能力。Function、Subgraph、GLSL Code 邊界都需要實際接通，不能只增加一筆型別名稱。
- TOP Input 現在直接產生 `sTD2DInputs[index]`、`uTD2DInfos[index].res.zw`、`.res.xy`；這是現有便利入口，不是通用結構欄位機制。
- 目前 TOP 來源管理是 2D 路徑；不能把 TD 支援的所有資源種類寫成 Grape 已支援。
- 搜尋速度已修正，搜尋命中排序仍待實作。Matrix 四則異型簽名也仍待處理。
- 先前撤銷的額外整數傳輸精度限制維持撤銷；本計畫不重新加入，也不更改既有接線轉換策略。

依據：[開發狀態](../development/STATUS.md)、[型別契約](../architecture/TYPE_CONTRACT.md)、[TOP 來源](../features/TOP_SOURCE_INVENTORY.md)、[矩陣能力](../features/MATRIX_NODES.md)。

## 2. 已確認的產品決定

| 項目 | 已確認內容 | 尚未因此決定的部分 |
| --- | --- | --- |
| 陣列概念 | 同一元素型別的有序列表，元素不只限於純量／向量／矩陣；TD 既有結構也需要納入 | 個別宿主通道能傳哪些元素型別，需實測 |
| 建立 | 指定元素型別與長度，建立尚未填入使用者內容的陣列 | 「空」不是長度 0，也不等於已同意填零；初始化待確認 |
| 取項 | 名稱 `Array[i]`；輸入 `Array`、`i`；輸出依元素型別推導 | 未接線時的呈現、完整版面與搜尋別名仍由原型確認 |
| 取項邊界 | 有元素時，自動把索引限制在 `0` 到 `N-1`；適用內建來源與一般陣列 | 沒有元素時不能靠 Clamp 解決；此規則不自動改動 Matrix Get／Set |
| 編輯 | 先提供指定位置的 Replace | 精確節點名稱、初始化互動、Replace 越界行為尚未確認 |
| 自訂型別 | 使用者自訂結構的作者 UI 可以先延後；型別模型需保留擴充路徑 | 不代表本輪已授權完整型別編輯器或任意外部 GLSL 解析器 |
| TD 結構 | 必須考慮 TOP 與 MAT 的既有結構／來源，不能只處理 TOP | 各來源與 Stage／版本的可用範圍由盤點和驗證確認 |

Replace 建議沿用值流模型：輸出替換後的陣列，保持長度及元素型別，不回寫外部來源。這是執行方案；若之後需要寫入 Buffer 或 TD 來源，需另列明確能力，不能從「Replace」名稱暗自推出。

## 3. 責任與主次

共用型別模型是 Grape 對資料的描述與相容規則；其合法範圍仍受 GLSL、TD 及目標環境約束。UI 和建立圖的工具使用同一份規則，不能各自維護不同的型別允許清單。

| 層次 | 責任 |
| --- | --- |
| 型別定義 | 穩定的型別身分、欄位組成、欄位型別；陣列另有元素型別及長度描述。顯示名稱與型別身分分開 |
| 來源及提供者 | 資料／定義由誰提供、TOP／MAT／Stage 適用性、長度來源、可讀寫與資源限制 |
| 圖的運算內容 | 保存節點、接線、操作、數值及必要的型別／欄位引用，描述具體計算 |
| 圖文件 | 保存運算內容及重建它需要的定義；可同時帶有位置、展開狀態等編輯資訊，但這些不必參與產碼 |
| 圖建立工具 | 編輯器、程式或智能體透過同一契約建立及修改圖 |
| UI | 依契約呈現名稱、接孔、欄位選單、說明、編輯狀態與錯誤；UI 控制方式不成為新的型別規則 |
| 驗證與 GLSL 產生器 | 解析型別、檢查能力與環境、處理宣告依賴、生成合法 GLSL 和可定位的診斷 |
| TD 的 GLSL 編譯器 | 編譯產生好的 GLSL；不讀 Grape 的型別表或圖格式 |

這是責任劃分，不要求為每一層另建一套系統或立即拆分所有程式檔。

### 定義與宣告

工程方案記錄「定義提供方式與可用條件」，由產碼器依本次使用情況決定要輸出哪些宣告；不靠型別名稱前綴、也不只用一個永久的 `needsDeclaration` 布林值。

- TD 已提供的結構：圖與 UI 需要知道欄位；產碼在適用環境直接引用，不重複產生 `struct`。
- 由 Grape 管理的專案結構：定義保存一次；每份實際使用它的 Shader 按依賴順序宣告一次，未用到的定義不必輸出。
- 巢狀結構、名稱衝突、缺少提供者、不同結構身分及可用環境由共用機制處理。
- 未來外部 GLSL 定義也需要描述提供者，但完整匯入／解析 UI 不因此自動列入本輪。
- 型別定義、某個變數的宣告、外部 Uniform 的資料傳輸是不同責任；認得 `Sample` 不等於 TD 已供應一個 `Sample` 值。

型別表不是每個像素都會查詢的資料庫。它服務圖驗證及編譯，GPU 執行產生好的 GLSL。

## 4. 實作里程碑與交付物

下表是下一輪實作的建議順序，不代表本次已啟動。可獨立驗證的研究及 UI 原型可以並行；共享核心由一位整合者管理，避免子任務同時改同一份型別規則。

| 階段 | 工作及交付物 | 完成條件 |
| --- | --- | --- |
| A. 能力盤點 | 建立 TOP／MAT／Stage 的來源能力表；分開普通資料陣列、結構陣列、sampler 陣列與 Buffer | 每项區分文件支持、原生實測、Grape 已支援與未接通；不以名稱推測能力 |
| B. 共用型別與提供者模型 | 在既有型別契約上擴充陣列、具名結構、身分和提供者描述；選定保存與引用方式 | 原有 38 值型別行為保持；`vec3[4]` 與矩陣不同，不同結構不因欄位相同就誤接 |
| C. 圖與產碼通路 | 接通合法型別的 relay、Function／Subgraph、GLSL Code；生成和引用結構定義；處理宣告依賴與診斷 | 不依賴 UI 也能建立測試圖；自訂定義一次宣告、TD 定義不重複，Stage 不可用時清楚拒絕 |
| D. 操作原型與普通資料陣列 | 提供建立、`Array[i]`、單項 Replace 和結構欄位選取原型；以具體例子確認三項待決行為後接通產品 UI | 入口、接孔、Parameter、保存及產碼吻合；一次操作的 Undo 與失敗回復完整 |
| E. TD 真實來源 | 接入 TOP 資料／sampler 陣列、MAT 結構陣列及 TD 原生 Uniform Array；Buffer 逐類做合法能力驗證 | TOP Pixel、MAT Vertex、MAT Pixel 均有適用案例；使用原生數值／GPU結果驗證，而不只檢查 GLSL 字串 |
| F. 回歸與交付 | 核對既有數值／矩陣、保存重載、匯入複製、搜尋速度；分批同步 TD 並保存 | 新功能測試及相關既有回歸通過；使用者 Shader 保留；文件標明已交付與仍待驗證項目 |

每批需形成可用的完整通路，不能把「選單看得到型別」當作完成。一般資料陣列可先形成一筆可交付成果，TD 特殊來源按實測結果續接；這是交付順序，不是永久刪除能力。

現在就以手工建立的專案 `Sample { offset: vec2, weight: float }` 測試資料驗證擴充性：建立、陣列、取項、取欄位、跨 Function、宣告和保存都要使用共用路徑。這不需要先製作完整的使用者型別作者 UI。

### TOP 與 MAT 的代表案例

| 來源 | 元素／結果 | 端到端例子 |
| --- | --- | --- |
| TOP `uTD2DInfos[]` | `TDTexInfo` | 取項，再讀 `res`；與實際輸入解析度核對 |
| TOP `sTD2DInputs[]` | `sampler2D` | 選取來源再取樣；檢查有效數量及必要的非一致索引處理 |
| MAT `uTDMats[]` | `TDMatrix` | 取相機對應項目，再讀 `world`／`worldCam`；不把相機索引默認為永遠 0 |
| MAT `uTDCamInfos[]` | `TDCameraInfo` | 取項再讀 `nearFar` 等欄位 |
| MAT `uTDLights[]` | `TDLight` | 依實際可用來源數量取項及欄位，包含無燈光情況的診斷 |
| TD Uniform Array | 宿主通道實際支援的元素 | 由 CHOP 等原生載體改值，核對圖讀取及來源關係 |

這些案例需要完整來源能力盤點。不同資源的宣告、索引、可否按值傳遞／建構／替換不能以一張「全部可用」清單取代。GLSL／宿主不允許的操作需明示原因，不能生成看似可接、實際非法的圖。尤其 sampler 不是一般可任意複製和 Replace 的數值，執行期 Buffer 陣列也不能假裝具備普通固定陣列的所有函式傳遞能力。

## 5. 三組待 review 的具體行為

現在不要求使用者回答。先完成可展示的對照，再一次 review；未定案前可使用清楚標示的測試配置，不能悄悄變成產品預設。

| 待決事項 | 要展示的例子與建議 |
| --- | --- |
| 建立後尚未填入的元素 | 建立 `float[4]`、`vec3[4]`、`mat3[2]`。建議採確定的初始化，數值的零值／false／零矩陣作候選；不要把「空」默認成未定義讀值，也不要把零矩陣與單位矩陣混用。結構初始化需依欄位能力處理 |
| 沒有元素 | 對固定 0 來源，建議顯示「沒有可讀取的元素」，保留圖與上次成功結果，阻止新生成的非法存取。執行期可為 0 的來源需另外展示有守衛的處理及結果語意；不能用 `clamp(i,0,-1)`，不能為 sampler 隨便假造零值 |
| Replace 越界 | 展示替換最後一項、超過最後索引及負索引。建議先比較「與取項相同的 Clamp」和「不執行替換並明示」；使用者只確認了取項的 Clamp，不能直接視為已同意 Replace 的語意 |

圖內一般固定 GLSL 陣列的長度必須符合語言規則；「有 N 個尚未填入使用者內容的位置」和「沒有任何元素」要分清楚。陣列宣告長度也不同於使用者只想使用其中幾筆的有效資料數；有效筆數不由產碼器猜測，具體操作入口可另行設計。

## 6. 由開發端承擔的驗收

- **型別與宣告**：不同元素型別／長度／結構身分不誤接；依賴順序、重複宣告、名稱衝突和缺少定義均有診斷。TOP／MAT／各 Stage 按實際提供者驗證。
- **取項與 Replace**：N=1、首末項、負索引、過大索引、動態索引、不同整數表示及空來源；Replace 不改外部來源或其他分支值，結果長度／元素型別保持。其越界預期以之後確認的規則為準。
- **現有功能**：純量、向量、double、非方形矩陣、Convert 分流、Auto、來源引用與目前接線策略保持；矩陣 Get／Set 目前沿用 GLSL 原生索引，不能因陣列 Clamp 而順手更改。
- **整套圖**：Function／Subgraph／GLSL Code、保存重載、Undo／Redo、跨 Shader 複製、剪貼簿、型別缺失診斷及專案自訂定義的攜帶方式均實測。
- **搜尋效能**：新增型別後仍使用局部候選配對；文字搜尋不向 TD 逐候選查詢、不恢復整圖模擬；型別／來源定義變動能使快取正確失效。
- **GPU 成本**：固定長度直接成為編譯期界限；常數索引可提前計算；動態 Clamp 不承諾完全免費。比較高頻取項案例的生成碼與 GPU 時間，重用等價的索引計算。執行期長度依提供者取得，不掃描陣列計數。
- **TD 交付**：以隔離 fixture 取得數值結果，保留使用者 Shader；通過後同步內嵌來源與資源、核對 Master、保存正式 TOE，再報告哪些內容實際可 review。測試紀錄不得宣稱未實測的平台已通過。
