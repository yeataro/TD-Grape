# 共用預覽面板精簡筆記

2026-09-16。0.8.76 先移除影像下方整列；使用者後續確認合併上方路徑與控制，於 0.8.77 套用以下配置。

核心：路徑靠左，右側只有兩個小型無框圖示；不再分占控制列與路徑列。

- 開啟 Viewer：本機與遠端皆隱藏按鈕，保留既有 TD 原生 Viewer 呼叫能力。
- 重新連線／接管：14px 圖示、透明底、無外框；保留重新連線與取回共用預覽控制權的能力。
- 即時預覽：改成同樣大小的電源圖示。啟用時顯示紫色，停止會釋放此頁的 peer；選擇會保存。重新連線會再次啟用。
- 點擊範圍：桌面 28 × 24px；粗略指標裝置 32 × 28px，圖案本身維持 14px。
- 狀態：正常以標題列綠燈表示；斷線、失敗、被接管的訊息保留在影像內。原狀態文字保留為螢幕閱讀器通知，不占可見空間。
- 來源路徑：長路徑優先省略父層，保留最後兩段。點一下可展開完整可選取路徑，點外或 Esc 關閉。不搬到 Panel 標題列或分頁上。
- 解析度：維持影像內右下角，不另外占一列。
- 操作提示：不顯示常駐操作教學，Help 內說明保留並更新圖示操作方式。

解析度角標不攔截滑鼠／觸控事件。未來可評估「來源解析度 → 預覽解析度」的對照，以及 TOP Viewer 的通道檢視；待使用者定義後續 Viewer 能力再設計，本輪沒有新增這些功能，也沒有改動尺寸同步時機。

尺寸實驗已於 0.8.75 實作：Graph UI 預覽區拖曳期間只縮放現有影像，放開並穩定 350 毫秒後才更新 OP Viewer COMP／TOP 的尺寸；僅由目前取得連線的頁面提出更新。這不表示下列實際體感問題已解決。

使用者已回到手機環境，本次要求先記錄觀察，控制面板後續仍會調整。

- 狀態：待後續重現與量測，本輪不因這項觀察修改程式或等待時間。

## 暫存預覽畫面與 Lock 的修正方向（2026-09-16）

0.8.81 在 MAT 套用期間 Lock 擷取 TOP、暫停串流更新，完成後等待三個更新 callback 再恢復，以避開已重現的 OP Viewer TOP 擷取掛起。使用者認同暫停擷取的目的，但指出 Lock 的暫態可能在此時存檔而寫入 TOE，因此不接受將 Lock 視為正式的畫面暫存方案。當機回歸通過不代表這個保存副作用已解決；目前尚未驗證於暫停窗口存檔再重開的行為。

- 後續預覽預計由使用者的新 Viewer 取代 OP Viewer；目前這條原生擷取路徑的問題未必仍會出現，替換後需重新驗證。
- 若仍需保留上一幀，優先評估 Cache TOP，透過快取畫面的選擇／更新控制達成。這是使用者提出的方向，尚未實作或驗證；後續也需確認暫停期間不再觸發問題來源的擷取，以及存檔／重開不會遺留暫態狀態。
- 此次只記錄回饋，不變更現有 runtime、TOE 或版本；0.8.81 的 Lock 暫解仍存在，後續預覽修改需處理此限制。
