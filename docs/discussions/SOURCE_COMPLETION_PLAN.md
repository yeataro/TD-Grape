## 最新審查與原生證據

### 已確認的 UI 方向

- Common Sources 預置卡片預先可見，尚未建立時約半亮度、偏灰但保留類型色，仍可操作；首次新增／引用才初始化，之後使用同一來源。不得開啟面板便建立所有 Uniform。
- Custom Uniforms 保留 Values／Matrices／Arrays 三個 UI 分組；Uniform Array 的資料身分仍是 Uniform。一般新增入口不混入整份時間預置清單。
- 最新回饋傾向來源管理與圖上引用維持分開，避免將所有管理操作搬到引用節點。共用外觀及數值元件不代表兩者必須有相同右鍵動作；既有圖內數值編輯需求仍保留。
- 缺失狀態需在卡片收合時也能看到，不把長原因擠在名稱／型別同一行。偏灰背景、簡短獨立狀態列與警告圖示為設計方向，實際外觀待實作驗收。

## 缺失來源：建議規則，尚待本輪 UI 驗收

使用者已同意依本計畫執行。0.8.123 先完成既有卡片的獨立狀態提示、缺失來源停止新增引用及匯入失敗可見性；完整卡片外觀接續第二輪。

來源狀態至少區分：Common 預置尚未建立、可用、原有實體缺失、實體存在但配置／資料不合法或能力尚未支援，以及連線中斷而狀態未知。不能將後四者都當作「尚未新增」或空清單；也不能把所有配置錯誤都標成 GLSL 編譯失敗。

- 已有引用與接線保留，顯示不可用原因；不自動刪除、補零、建立替代來源或改接另一來源。
- 真正缺失的來源暫停新增引用，保留選取、Help 與適用的恢復／重新指定入口；此規則已確認，第一輪已實作新增引用的阻擋。
- 使用到缺失來源的有效輸出路徑，在套用 TD Shader 前攔截並指出來源／節點；未使用的缺失項目不應僅因留在清單便阻擋其他有效圖。須分開圖驗證、產碼與原生配置的範圍測試。
- 原碼引用不存在的識別名可能編譯失敗；有宣告但無有效資料時也可能通過編譯。因此不能只依 GLSL 編譯成功判斷來源是否可用。
- 現有套用流程已在圖產碼後、候選 Shader 部署前檢查使用到的 `sourceMissing` binding；沿用並補足診斷及各來源狀態覆蓋，不先宣稱所有失效情境都已攔截。
- 保留最後成功 Shader 程式不等於凍結畫面：使用者在 TD 移除已套用 Shader 依賴的資料，TD 仍可能報錯。UI 要如實呈現，不能承諾保留資料或最後畫面。
- 恢復依既有穩定來源識別與可確認的對應；模糊或衝突的同名來源不自動認領。來源管理面板處理恢復，圖上引用不各自持有另一份來源配置。

0.8.127 子步驟：CHOP Texture Buffer 以原生 `samplerBuffer` 引用，提供 Buffer Fetch（`texelFetch`，vec4）與 Buffer Length（`textureSize`，int）。沿用 Uniform 的原生來源實體管理，UI 單獨列為 Texture Buffers；不放入可填值的 Custom Uniform Arrays，不查詢 CHOP 樣本／長度來建立圖型別，不建立替代 CHOP。TOP／MAT 隔離原生驗證通過：讀取、長度、Expression 綁定、空路徑及儲存模式失配保護。TOP 另實際讀到 0.375 與長度 8；MAT 本次驗證產碼與原生編譯。已追蹤來源切換 Uniform Array／Texture Buffer 時保持舊宣告與接線、標明失配並阻擋使用中的來源；恢復原模式即可恢復原識別，不默默改型別。顯式採用新儲存模式與完整分類整理接續來源工作。

0.8.128 子步驟：新增 POP Buffer 來源管理與引用，兩個 uint 索引及取值／長度／Attribute Array Size 出口。只使用 Attribute 定義 metadata，不讀回 POP 的數值或點資料；僅查長度時不產生 Attribute 取值指令。輸出型別由圖選擇、產碼明確轉換，Python metadata 無法區分 float／double、int／uint 的精確原生型別，因此不聲稱自動辨識精度。建立／修改共用來源表單與歷史機制；Expression／Bind／Export 的 POP 配置保留並在網頁唯讀。

原生限制實測：**已配置的 POP Attribute 不存在**，即使 Shader 沒讀它，TD 仍會讓整個 GLSL OP 報錯；這與「原生來源列已移除、圖留下未使用引用」不同。前者不能承諾不阻擋套用，必須提示使用者修正 TD 配置，不偷偷清除原生列、建立替代資料或偽裝成 GLSL 語法錯誤。TOP／MAT 分別驗證通過（MAT 包含驗證場景渲染，TOP 另抽查實際像素）。

2026-09-20 最新筆記：目前 POP／CHOP 仍由使用者自行建立。建立一個帶基本 Attribute 的預設 POP、之後由使用者修改，只是備選方案，未定案。TOP／MAT 宿主能力分開核對，共用已證實相同的欄位流程。**MAT 的渲染幾何體缺少 Attribute 時的原生預設行為**與 Buffers 頁面的 POP 綁定分開；使用者要求先完成來源能力，相關差異留到整體實際行為驗收，不以 Buffer 結果推定 MAT 幾何體規則。

0.8.129 子步驟：格式失配來源提供「採用 TD 儲存格式」與產品確認卡片。依原生設定更新同一來源宣告，保留所有接線，先作為瀏覽器草稿；不相容接線由既有檢查提示，合法後才能套用，不自動轉接讀取節點。Uniform Array 的長度只在採用時讀取，清單刷新不查 CHOP 樣本。歷史紀錄分辨格式失配與實體刪除，採用及 Undo／Redo 均保留原生列、CHOP 路徑與儲存設定。TOP／MAT 兩方向、草稿不覆寫 DAT、原生歷史及瀏覽器確認／撤銷已驗證。
