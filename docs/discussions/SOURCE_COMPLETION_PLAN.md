# 來源功能接續計畫

2026-09-20。整合本輪操作回報與[來源建構共識](SOURCE_ARCHITECTURE_REVIEW.md)。目前交付版為 0.8.123，第一輪已完成；本文件是接續工作與驗收清單，不表示以下功能已完成。分類仍以[來源選單分類表](TD_SOURCE_MENU_REVIEW.md)為依據。

## 已完成的基礎

- 共用來源資料表：編譯器、TD 初始化與 UI 讀取同一份預置資料；分類與初始化行為分開。
- 六個基本時間預置，只在建立時初始化，不覆寫既有 TD 值或模式。
- Parameter 面板使用一般數值控制的共用分量元件，按宣告顯示 1–4 格；Expression／Export 顯示模式，可寫 Constant／既有受支援 Bind 保留編輯。
- 上述功能已測試、同步 TD、保存 TOE 與 Git 提交。來源卡片、圖內 Uniform 控制、Buffer、MAT Attribute、結構作者 UI 尚未因此完成。

## 最新審查與原生證據

### 已確認的 UI 方向

- Common Sources 預置卡片預先可見，尚未建立時約半亮度、偏灰但保留類型色，仍可操作；首次新增／引用才初始化，之後使用同一來源。不得開啟面板便建立所有 Uniform。
- Custom Uniforms 保留 Values／Matrices／Arrays 三個 UI 分組；Uniform Array 的資料身分仍是 Uniform。一般新增入口不混入整份時間預置清單。
- 最新回饋傾向來源管理與圖上引用維持分開，避免將所有管理操作搬到引用節點。共用外觀及數值元件不代表兩者必須有相同右鍵動作；既有圖內數值編輯需求仍保留。
- 缺失狀態需在卡片收合時也能看到，不把長原因擠在名稱／型別同一行。偏灰背景、簡短獨立狀態列與警告圖示為設計方向，實際外觀待實作驗收。

### 這輪問題已定位，尚未修正

| 回報 | 已核對的原因／證據 | 待處理 |
| --- | --- | --- |
| Arrays 新增名稱及 CHOP 後沒有進清單 | 實際來源 `uNOISE` 為 Uniform Array，通知已到達；匯入端以產品的 1024 長度上限拒絕，來源未進清單，理由不夠可見。減少樣本後出現。 | 分開原生容量與編輯器自行建構陣列的限制；失敗項目仍可見並可理解原因。 |
| Spec Constant 拉到小數報「編譯錯誤」 | 型別機制本來支援 float，但新 TD Constants 列被一律匯入為 int；TD 的值控制是 Float，沒有原生型別欄位。整數宣告收到小數被我們自己的驗證拒絕。 | 明確決定新來源的型別入口／預設，保留既有宣告；區分來源驗證與真正 GLSL 編譯診斷。不因值變化擅改已接線型別。 |
| CHOP 選 Texture Buffer 後沒有來源 | 目前 Uniform Array 匯入會拒絕 Texture Buffer；相應的 Buffer 引用／讀取流程尚未實作。 | 實作獨立的 samplerBuffer／取值／長度能力，不偽裝成可直接複製、填值的一般陣列。 |

隔離 TD 2025.32820 探測 `tests/td/probe_source_limits.py`：float specialization 值 0.625、0.375 均編譯成功並讀到對應像素；int 宣告收到原生 0.625 時 TD 仍編譯成功，本次輸出 1.0，不能由此概括所有轉型規則。Uniform float Array 長度 1024、1025、2048、4096、10000 均無編譯錯誤，以執行期索引抽查輸出皆為 0.375。這證明 1024 不是本機的通用合法性界線，不證明任意長度／型別／GPU 都可用，也未測出硬體上限。

探測只建立並清除隔離的 8×8 GLSL TOP 與資料來源；既有圖與原生參數僅讀取。私人結果：`work/reports/source-limits/native/result.json`。本次沒有再次執行探測或更新產品版號。

## 缺失來源：建議規則，尚待本輪 UI 驗收

使用者已同意依本計畫執行。0.8.123 先完成既有卡片的獨立狀態提示、缺失來源停止新增引用及匯入失敗可見性；完整卡片外觀接續第二輪。

來源狀態至少區分：Common 預置尚未建立、可用、原有實體缺失、實體存在但配置／資料不合法或能力尚未支援，以及連線中斷而狀態未知。不能將後四者都當作「尚未新增」或空清單；也不能把所有配置錯誤都標成 GLSL 編譯失敗。

- 已有引用與接線保留，顯示不可用原因；不自動刪除、補零、建立替代來源或改接另一來源。
- 真正缺失的來源暫停新增引用，保留選取、Help 與適用的恢復／重新指定入口；此規則已確認，第一輪已實作新增引用的阻擋。
- 使用到缺失來源的有效輸出路徑，在套用 TD Shader 前攔截並指出來源／節點；未使用的缺失項目不應僅因留在清單便阻擋其他有效圖。須分開圖驗證、產碼與原生配置的範圍測試。
- 原碼引用不存在的識別名可能編譯失敗；有宣告但無有效資料時也可能通過編譯。因此不能只依 GLSL 編譯成功判斷來源是否可用。
- 現有套用流程已在圖產碼後、候選 Shader 部署前檢查使用到的 `sourceMissing` binding；沿用並補足診斷及各來源狀態覆蓋，不先宣稱所有失效情境都已攔截。
- 保留最後成功 Shader 程式不等於凍結畫面：使用者在 TD 移除已套用 Shader 依賴的資料，TD 仍可能報錯。UI 要如實呈現，不能承諾保留資料或最後畫面。
- 恢復依既有穩定來源識別與可確認的對應；模糊或衝突的同名來源不自動認領。來源管理面板處理恢復，圖上引用不各自持有另一份來源配置。

## 五輪執行與驗收

五輪可依序持續推進，各輪都有獨立驗收與 Git／TOE 檢查點，不要求使用者每輪重新授權。政策未定的部分以明確提案標示，不用大改混入已授權的基礎修正。

### 第一輪：匯入、型別與診斷

- [x] 修正原生 Uniform Array 的 1024 匯入限制設計，追查共同型別契約與 UI 限制，避免只放寬單一入口。
- [x] 整理 Spec Constant 的 int／uint／bool／float 匯入與編輯語意；不偷偷改既有 int 宣告為 float。
- [x] 來源存在但匯入失敗／尚不支援的項目仍可見，提供對應原因；錯誤用語區分來源、圖與 GLSL 編譯階段。
- [x] 核對 native 新增、改名、改型別、改儲存方式、缺失與恢復，以及已使用／未使用來源的失敗隔離。

驗收：使用者這輪的三個回報都有可見解釋；合法的大陣列不因無根據的 1024 規則消失；Spec 小數與整數宣告各有正確行為。Texture Buffer 完整使用在第三輪完成，第一輪不得因此標示它已可用。

### 第二輪：Common／Custom 來源 UI 與 Uniform 引用

- [ ] Common 預置卡片的未建立／可用狀態與首次初始化；Custom Uniforms 三個分組及共用卡片、Help、右鍵／觸控入口。
- [ ] 來源管理留在面板，圖上保留引用與逐分量數值控制；數值寫入同一 TD 實體，不複製成圖內值。
- [ ] 可見來源訂閱去重：同來源出現於面板與多個圖節點時共用資料，不因每個分身重複查詢。值更新只更新相關控制，不存圖、產碼或重建無關清單。
- [ ] 每個分量依 Constant／Bind／Expression／Export 呈現；需新增的 Bind 支援先確認寫入責任，不以解除綁定達成可編輯。
- [ ] 缺失狀態在卡片收合時可見，並與 Common 未建立／連線未知區分；套用經確認的引用與恢復規則。

驗收：首次建立不重複、再次引用不初始化；TD 與網頁雙向數值同步；面板及多個引用顯示一致，移除圖節點不刪除原生來源。

### 第三輪：Texture Buffer 與 POP Buffer

- [ ] CHOP Texture Buffer 原生配置清單、圖內引用、合法型別、取值及長度；與 Uniform Array 分開。
- [ ] POP attribute buffer 的路徑、Attribute class／name、Shader 名及讀取／長度／Attribute Array Size 能力。
- [ ] 空路徑、空資料、缺少 Attribute、變更儲存模式及來源恢復分別驗證，顯示原生診斷。
- [ ] 清單確實為空時提示使用者在 TD 建立並配置；不代建 CHOP／POP 或 Attribute fallback。

驗收：TOP／MAT 實際取值與宿主允許的 Stage 正確；同一 POP 可配置多個 Attribute；沒有「清單有項目但只能看不能讀」的半完成交付。

### 第四輪：MAT Attribute 與來源內容補齊

- [ ] MAT Attribute 名稱／型別／Array Size 的配置、引用、修改、產碼與 UI；共用數值型別及來源操作基礎。
- [ ] 常用內建 accessor 與需配置的具名 Attribute 分開，預置入口不代表提前建立所有原生列。
- [ ] 依來源總表逐項標示已支援、可沿用機制補齊、使用者自行新增及本輪不適用；涵蓋現有 TOP／MAT 與已支援 Stage。
- [ ] 整理 Texture 維度、共通來源及 TD 內建的分類／名稱；來源、運算、未支援 Stage 不混成同一份新增清單。

驗收：提供 TOP／MAT 可用能力表與實際產碼案例；不以新分類外觀冒充新能力，也不以來源研究表的總筆數作為完成數。

### 第五輪：結構編輯與整體收尾

- [ ] 左側結構清單／可收合卡片；新增與編輯使用彈出面板，名稱、欄位、型別與備註。
- [ ] 引用已建立結構、循環檢查、完整結構／欄位出口與 Array Create → Array[i] → 欄位的型別傳遞。
- [ ] 編輯前辨識使用處；穩定欄位識別與相容接線保留，不相容接口沿用明確的斷線／診斷規則，避免誤斷無關接線。
- [ ] 備註／外觀、型別配置、即時值各自更新；選單按需讀取最新定義，不為新增結構重建全圖。
- [ ] TOP／MAT、匯入舊圖、保存／重開、Undo／Redo、來源刪除／恢復、斷線／重連及已套用 Shader 保護回歸。

驗收：使用者能自行建立、修改並實際使用結構；最終交付清楚列出已完成能力、實測範圍與剩餘限制。

## 各輪共同要求

每個可交付子功能完成適當測試、Git 提交、TD 同步及 TOE 保存，頁首／About／runtime 版本一致；不強制重新整理使用者網頁。效能驗證針對實際更新成本與受影響範圍，不因功能擴充新增每幀全清單掃描。Loop、自訂程式碼作者介面、未支援 POP／Compute 宿主及先前暫緩的其他 UI 調查不插入此來源主線。
