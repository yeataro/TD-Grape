# 來源建構、型別與 MAT Attribute：討論共識

2026-09-20。接續[來源選單分類表](TD_SOURCE_MENU_REVIEW.md)與[來源命名總表](TD_SOURCE_NAMING_RESEARCH.md)。本頁記錄設計方向與待決項，不代表已完成來源重構或新增能力；產品基線仍為 0.8.120，交付狀態以 [STATUS](../development/STATUS.md) 為準。

本輪回到的主線是來源資料模型、共用建構方法，以及 MAT Attribute。延伸的 Loop／控制流程先收進[迴圈筆記](LOOPS_DISCUSSION.md)，不因此插入本輪實作。

## 1. 用資料擴充，行為由共用方法實作

- 節點表登記可加入的項目；來源實體及其引用可以另有來源表。是否合併實體檔案尚未定案。
- UI 分類／名稱與建構行為是兩種屬性。改分類不應要求改建構器、型別檢查或 GLSL emitter。
- 同類固定行為共用方法：直接建立圖節點、建立 Uniform、引用內建來源、配置 Texture Input 等；項目提供型別、名稱、初始化資料及適用範圍。
- 表格選擇明確的處理方法與參數，不先建立任意流程腳本語言。分類不向 TD 查詢，不為每一候選複製整張圖模擬接線。
- 宿主／圖種類與 Stage 分開描述有效組合，例如 TOP Pixel、MAT Vertex／Pixel；未來 POP 是圖種類，Compute 是 Stage。未支援組合不能因分類資料出現而變成可用。

目前節點庫已有 browser metadata，但 Inputs 預置、來源分組、部分可用性與建構分派仍分散於前後端；此次共識不是現況已全部資料化的宣稱。

## 2. 建立、引用、修改各有責任

| 操作 | 設計共識 |
| --- | --- |
| 建立來源 | 預置只描述首次初始化，例如型別、Value／Expression 模式與初始 expression；已有同名實體時拒絕重複建立並回報已存在，不默默改成修改或新增另一份。 |
| 建立引用 | 指向已存在的來源；不重做來源初始化、不覆蓋使用者修改過的 TD 值或模式。 |
| 修改來源 | 明確修改指定實體；型別、名稱、綁定等依各自規則處理，不借用重複建立來隱式修改。 |

預置 UI 的構想：尚未初始化時顯示有分類色的項目及新增入口，建立後變成可引用來源。後端仍查驗實際宿主實體，不只相信 UI 狀態。名稱可作為查找依據，但既有穩定來源身分與重新命名關係須保留；具體資料格式尚未定案。

TD-specific Expression、原生 Parameter 位置與相對求值環境由 TD 處理方法負責；不能因來源表共用就假裝它們與宿主無關。來源初始化不在 Open Editor、重新引用或 Apply 時反覆執行。

Uniform 的即時值／模式仍由 TD Parameter 持有；圖保存引用與必要配置，不複製高頻值進圖保存。Spec Constant 可以共用身分／型別／原生列配置等基礎方法，但特化 ID、支援型別與生效方式需保留；具體共用範圍尚待整理。

Texture 的程式入口可共用，再分派 TOP／MAT 各自方法。TOP 的 slot、實際輸入與連接管理，和 MAT 的具名 sampler 配置不是同一份實作；不為共用入口強迫它們完全一致。

## 3. 結構定義、接口與型別傳遞

- TD 內建、節點庫提供、圖內自訂的結構都能向共用型別機制提供定義。圖與節點庫在「提供定義」的能力上可共用格式，整體職責不等同；同名資料不能默默互相覆蓋。
- 接線比對穩定型別身分，不只比顯示名稱，也不因兩份結構欄位碰巧相同就當成同一型別。
- 型別的來源與宣告責任分開：TD 已宣告的結構登記後引用；圖擁有的結構需要時由產碼器宣告。共用型別檢查不抹除這個差別。
- 同一節點可同時提供「完整結構」與「一般欄位」出口。哪些欄位直接露出由接口設定決定，不強制所有來源都拆成另一顆 Field，也不要求所有欄位全部露出。
- 結構表提供欄位名稱／型別；節點定義選擇來源及出口；共用 emitter 產生 `value.field`。多出口引用同一函式結果時應共用結果，不因每個欄位重算函式。
- 自訂結構接入同型別入口；Array Create 的泛型規則接收合法、受支援的元素型別並建立 `T[N]`。並非自訂結構逐一列出能接哪些節點，也不是所有資源型別都能當一般陣列建構／填值。
- `Array[i]` 從陣列型別取得元素型別，例如 `Particle[N] -> Particle`；不用讀取元素值或先算出 N。要拆欄位時才查結構定義。
- 新增結構定義不自動賦予 Add 等運算語意，也不生成全部型別兩兩相容的巨大配對表；沿用同型別、陣列元素及欄位等共用規則。

這些是擴充方向。已有能力與限制見[陣列與結構](../features/ARRAYS_AND_STRUCTURES.md)；自訂結構作者 UI、所有內建來源的完整／欄位雙出口尚未因此完成。

## 4. 編輯器、產碼與錯誤邊界

圖可以視為結構化程式編輯器；可借鑑 IDE 的型別／名稱解析與診斷共用方式。「提示或阻擋」是編輯政策，與是否有產碼／編譯能力分開。

- 可直接判斷的接線／圖錯誤提前攔截；不為得到所有答案去模擬 GLSL 執行、求值常數鏈或持續同步宿主狀態。
- 圖到 GLSL 是一種程式表示轉換；完整 GLSL 編譯由宿主編譯鏈負責。編輯器不知道具體長度，不等於來源不能表達。
- 明確不合法的編輯可以拒絕；編輯草稿、成功產碼、最後成功的 Shader 是不同狀態。「回退」需要說明回退哪一層，不一律撤銷使用者內容。
- 未來自訂節點／程式碼以宣告接口供圖檢查；使用者負責自訂內容，我們仍負責包裝、產碼與編譯失敗處理。既有 GLSL Code 能力不因這份後續方向被說成不存在。
- 編譯診斷應追溯到節點與自訂碼行號，節點紅色圓圈叉號為使用者提出的呈現方向；保留內容供修正，執行端保留最後成功結果。具體 UI／映射覆蓋率未驗收。
- 編譯器指出的位置不保證是根本原因；不可把我們的產碼錯誤一律歸責使用者。沒有承諾零錯誤或以「千萬分之一」作為已量測機率。

## 5. MAT Attribute：回到來源主線的待辦

使用者要求列入來源整理：Attribute 配置主要是在描述要引用的幾何屬性名稱，而非由圖持有每個頂點的值；需要處理常用預置、使用者自訂名稱，以及對應型別／陣列大小。實際值仍來自宿主幾何資料。

### 初始來源仍待決

- 使用者傾向讓常用 Attribute 一開始可用，但「有哪些預置」「是清單已有可引用項目，還是建立 TD 配置列」尚未定案。
- 「定義了而未使用也沒差」先保留為使用者預期，不當成已驗證所有宿主配置都零成本、無名稱衝突或無相容性影響。
- 後續區分宿主本來就提供的 accessor，與需要使用者指定名稱／型別的 Attribute；不因顯示預置而重複建立原生資源。

### 官方介面核對

2026-09-20 核對官方文件，未操作 TD、未做新 Attribute 實機驗證：

| 官方項目 | 核對結果 |
| --- | --- |
| GLSL MAT Attributes 頁 | `attr` sequence 包含 Name、Type、Array Size；目前文件列 scalar／vector 的 float、double、int、uint 系列，size = 1 表示非陣列。 |
| 幾何 Attribute 存取 | MAT Vertex 可用 `TDAttrib_<name>(arrayIndex, vertexIndex)` 與陣列大小資訊；陣列大小指一個 Attribute 內的元素數，不是幾何頂點總數。 |
| 常用內建 accessor | `TDPos()`、`TDNormal()`、`TDTexCoord(layer)` 由宿主提供，不需要再次手寫宣告。 |
