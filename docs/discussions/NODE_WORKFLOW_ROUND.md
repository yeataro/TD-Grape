# 節點工作流程：0.8.84 決議

2026-09-17 使用者確認實作。此文件區分已決議範圍與後續筆記；實際交付與驗證見 STATUS／TESTING。

## 本輪

- Vector 2／3／4 先試作無輸入、手填分量、單一完整向量輸出。Combine／Split 各自維持用途。Replace 提供完整基底與分量覆寫，只有完整輸出；分量輸入不折疊，輸出另列。
- Vector／Color RGBA 的手填值可在緊湊同列與展開的具名分量列間切換。保留數字底色、Value Ladder、色條與調色盤，不把整顆節點折疊。
- 一般節點建立時分配唯一遞增名稱。工具列用「自訂名稱」文字按鈕切換預設名稱／自訂名稱；切換只改顯示。自訂名稱模式直接在標題編輯，Enter 或失焦提交、Escape 取消；空白转底線，識別字限制與重複檢查保護 GLSL，IME 組字完成後處理。
- Uniform／Graph Constant／Spec Constant 等來源引用以宣告名稱為主標題、種類為副標，不設另一個可獨立改名的別名。改名應編輯共用來源。
- 標題提供一個主要型別或模式快捷下拉，複用 Parameter 的資料與行為；不為每個參數再建立一排控制。型別切換造成接線不合法時，沿用現有未套用／診斷流程，不另設一套拒絕切換規則。
- Inputs 分類的建立入口用 New／新增，引用列仍可用加號放置節點。Graph Constants／Spec Constants 分開；Spec Const 短標搭配完整 Help。TD Built In／TD 內建來源提供既有來源的另一個尋找入口，不強制同色。Texture Coordinates 名称暫留，以 `vUV.st` 補充辨識，分類不當作 sampler 或常數。
- 導航併入工具列，移除 Graph 標籤；縮放與置中移至畫布角落。工具按組換行。工具列浮動為程式 flag，預設固定；浮動空白處可穿透操作。頂欄收合按鈕移至 Layout 左方。
- 使用者允許刪除舊統合式 Vector X 開發測試圖／定義兼容路徑：此次為 Alpha 前一次性例外，不對新 Vector 製作保留舊 I/O 的遷移。不能據此任意刪除其他使用者資產。新模板與預設圖必須同步。

## 不納入本輪

- Uniform／來源 Parameter 流程、Inputs 卡片內直接編輯來源值仍待後續；一般節點 Parameter 樣式與操作已依本頁最後決議完成。
- 原先列為待試作的整顆節點折疊、合併接孔顯示與 Comment 已在後續追加；Comment 的確定範圍見下方。多選工具列依最新獨立分組決議處理。
- 中途預覽、Canvas Backdrop：保留目標，等節點工作流程穩定；Backdrop 是後續確定要做的能力。
- TOP 其他貼圖維度、陣列與矩陣、完整整數向量管線：分開驗證型別、取樣索引與原生綁定，不在本輪混入。

名稱切換的正式圖示、來源卡片編輯位置、TD 內建項目的更完整分類仍可依使用回饋調整。本輪使用文字按鈕及現有分類邏輯。

## 2026-09-18 追加：Comment 註解節點

- 在新增節點／搜尋清單提供 Comment，可用 note、annotation、text、註解、備註尋找；沿用一般節點的命名、選取、拖動、調寬、收合、複製貼上、刪除與 Undo。分類色為中性灰，沒有輸入或輸出接孔。
- 畫布內文未編輯時使用透明底，融入節點 body；只有聚焦編輯時才顯示深色輸入底。未來 Markdown 預覽沿用 body 底色。
- 文字直接在畫布節點或 Parameter 的參數頁編輯。採純文字，保留換行，不解析 Markdown 或 HTML。失焦或 Ctrl／Command＋Enter 套用為一次 Undo；Esc 取消此次草稿。正常介面重繪保留正在輸入的文字與焦點，唯讀狀態禁止修改。
- 使用者後續確認 Comment 為第一個可同時調寬、調高的節點。沿用右下角拖曳把手，尺寸以圖座標保存於 `ui.width`／`ui.height`，一次拖曳只有一次 Undo；高度基準 180、最小 130、最大 1200。文字區填滿剩餘高度，過長內容可捲動；收合時只顯示標題，展開恢復保存的高度。其他節點繼續只調寬。
- 文字沿用 `ui.comment`，最多 2000 字；位置、寬度及收合狀態同樣放在節點 `ui`。不增加另一種畫布物件或獨立保存系統。一般節點既有的「註記」分頁保持，Comment 則直接以文字編輯作為主要內容，避免重複分頁。
- Comment 可隨其他節點一起轉換為子圖，文字及外观一併保留；子圖／個人庫／選取剪貼簿沿用既有資料路徑。註解不產生接孔，也不參與 GLSL、編譯 hash 或未接線警告；不把註解文字附加到產生的 shader。
- 這是新增 catalog 定義，既有節點的 revision、emitter ABI、shader shell 及圖 schema 不變。有完整舊 catalogSnapshot 的既有圖不需要版本升級；讀取 Editor state 時沿用既有相容性檢查，回傳目前定義的證據，不改寫舊 DAT。既有未經證明／損壞的版本證據仍走原審查流程。
- **群組框與 Markdown 仍待後续。** 群組框的自動尺寸、成員加入／移出與跨群組選取規則尚未定案；Comment 不提前承擔這些行為。Markdown 富文字也不在這次純文字版本中。
- Markdown 後續方向已補充：使用單一自然書寫的 Markdown 內容，**不設純文字／Markdown／GLSL 模式選單**；以 fenced `glsl` 程式區塊自動套語法色。保留 `ui.comment` 與 textarea 編輯，閱讀呈現採 Markdown；先確定 Markdown 子集或解析器，以及編輯／預覽的切換方式。現有 `markdown()` 只是簡易 inline 子集，GLSL 配色在 `renderGLSL()`／`#sourcecode`；後續可抽出共用 DOM highlighter 給 fenced code，不在本輪先加依賴或重構。屆時一併驗證文字安全、連結、圍欄語法與尺寸／換行。

## 2026-09-18 追加：工具列分組與選取操作

- Undo／Redo 固定在頂部。編輯工具組只含複製、貼上、刪除，可從齒輪独立關閉及重新顯示。框選使用虛線矩形圖示，自訂名稱維持文字，GLSL 保留獨立入口。
- 「選取工具列」有關閉、僅複選、單選與複選三態，預設關閉。關閉時編輯工具留在頂部，多選另顯示子圖／排列；僅複選時頂部編輯工具保持，選取上方只出現多選操作；單選與複選時，複製／貼上／刪除移入選取工具列，多選再加入子圖與排列。未選節點仍可由右鍵／觸控長按選單貼上。
- 選取工具列採橫列，放在選取範圍上方並對齊右緣，避免擋住節點右侧的輸出接孔。使用介面尺寸而不隨圖縮放，跟隨位置並限制在畫布可視區；極窄時按整組換行，組內仍橫排。平常不顯示持續的選取外框；hover 或鍵盤操作時才顯示虛線範圍。按鈕搬移原 DOM，不複製另一套命令。
- 基本排列提供齊左／水平置中／齊右、齊上／垂直置中／齊下、水平／垂直等距及格狀。依每個節點的實際尺寸計算，等距／格狀保留至少兩格（48 圖面單位）的間隔；等距需三個以上節點。每次只改位置並產生一筆 Undo。
- 齒輪依工具列與入口、節點與接線、色彩與顯示分組；原 floatingToolbar 儲存值不遷移，介面以反向的「顯示工具列底色」表達。Footer 單鍵帽圖示開啟可由 X／Esc／點外部關閉的快捷鍵列表，按鈕 tooltip 與右鍵選單共用快捷鍵資料。
- 群組框成員加入／移出、跨群組合併、依接線自動排列與快捷鍵重配尚未定案。Ctrl＋G 繼續轉換子圖；此次不放無作用的群組框按鈕，也不改檔案結構預先承擔群組框。

## 2026-09-18 手機觀察與本輪範圍

產品主要環境仍是 desktop。使用者只授權本輪改善 Node 與 Parameter 數值欄位的觸控操作：左右滑動調值、長按約 450 毫秒開 Value Ladder 且不自動 focus、雙點才進文字編輯。單點不呼叫鍵盤，已進文字編輯時保留游標／選字；初始上下移動保留捲動／畫布導航。以實際 touch pointer 區分，滑鼠與觸控筆沿用原操作；共用既有調值、提交、取消與 Undo 流程。詳細規則見 [觸控操作](../ui/TOUCH_EDITING.md#numeric-fields-on-nodes-and-in-parameter)，交付及驗證見 STATUS／TESTING。

以下只記錄觀察及候選方向，不是本輪實作或已定案方案：

- 使用者回報手機原生雙指頁面縮放會破壞操作版面。需區分瀏覽器頁面縮放與現有畫布雙指導航；畫布已設 `touch-action: none`，其他入口和浮動區域仍待實機定位。是否調整手勢區域或限制瀏覽器縮放，尚未決定，不先更改全頁 viewport 或封鎖全頁手勢。
- iOS 輸入框聚焦可能觸發瀏覽器自動放大；常見的字級方向是 16 CSS px，不是 16pt。現有 UI 縮放與節點縮放下，不能將「16px 再 scale」當作已驗證的解法；字級、縮放與鍵盤行為留待實機評估。
- 新增節點面板會自動 focus 搜尋框，使用者回報因此放大且難以恢復視窗。觸控開啟時先不 autofocus、點搜尋框後才輸入是候選方向，尚未採用；desktop 的即時搜尋優先保持。
- 使用者回報瀏覽器縮放後 Value Ladder 位置偏移。檢查發現 Ladder／Creator 定位尚未處理 `visualViewport`；頁面放大、平移與軟鍵盤引起的可見範圍改變可作為後續調查方向。尚未以 iPhone 實機確證原因，也未授權本輪修改這些定位規則。
