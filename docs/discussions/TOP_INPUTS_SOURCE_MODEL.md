# TOP Inputs 與 Sampler 來源整理（2026-09-16）

狀態：使用者於本輪後續授權保存目前版本後直接實作。最新修訂：Input 可全部刪除，第一個香蕉來源屬於模板；新增來源名稱應清楚對應 TD 實際引用。下文保留討論脈絡，執行方案與最新決策見末節，完成狀態以 STATUS 為準。

本文件補充並修訂 TOP 來源管理方向。較早的 [Inputs／Sampler 討論](INPUTS_AND_SUBGRAPHS.md) 與 [0.8.7 Inputs 實作紀錄](../features/INPUTS_WORKFLOW.md) 保留作為歷史背景，不能把舊版「獨立 Sampler 與 TOP 槽位並存」直接當作這輪的設計目標。

## 使用者回報與要解決的問題

- 新增 Sampler／TOP Input 節點時，Grape TOP 組件內會出現使用者未預期的新 Select TOP、預設圖與來源鏈；來源數量及排列不容易理解。
- TOP 同時承接舊獨立 Sampler 與受管理的 TOP Input 槽位，使用者認為早期共用 MAT／TOP 規則造成現在的操作混亂，需要重新整理。
- 在 Sampler 來源方式切換到「指定貼圖來源」後，使用者遇到錯誤與無法完成圖升級的狀態。具體失敗原因尚未定位，不能宣稱已修復，也不能只要求再次升級。
- TD 內部網路必須能供人類檢視：每個來源負責哪些節點、何時新增、如何排列，都要有可理解的規則。

## 已確認的管理原則

1. **Inputs 管理來源實體，畫布節點引用來源。** 新增或複製引用節點，不應因此新增來源清單項目、Select TOP 或額外的 TOPs 項目。
2. 每個 Shader 必須有可維護的來源清單。清單的儲存方式可另行決定，不能因為 TOP 沒有與 MAT 相同的原生 Samplers 頁，就失去來源管理。
3. 同一個來源可以被多個節點引用。Uniform 的預置快捷也是如此：反覆加入同一個預置來源時應引用同一實體，不應不斷建立同用途的新 Uniform。這不禁止使用者明確建立另一個獨立來源。
4. TOP 可採用原生 **TOPs** 參數管理輸入列表，以減少程式直接管理 Shader 接線的負擔。TOPs 必須由明確的來源順序產生，不能因為多放了引用節點便多出項目。
5. 來源名稱與對應關係要在新增入口及引用節點上清楚呈現；不能只看到 Sampler 而不知道它實際讀哪個 Input。
6. TD 內部每個 Input 及其預設來源要預留一列足夠的高度，新建節點的位置由程式計算，避免重疊與不可讀的排列。

## 理想初始狀態

使用者明確指定：新建 Grape TOP 時，就有第一個來源與可用的香蕉預設圖，不需先在畫布新增 Sampler 才產生它。

```text
香蕉 Movie File In TOP（可以經過 Select TOP）
                       ↓ 未接外部來源時使用
                    In TOP
                       ↓ 由 TOPs 引用
                    GLSL TOP
```

- Inputs 清單初始就包含這個來源；討論中稱為 **Input 1**。現行 UI 曾使用 Input 0，後續應統一顯示編號，同時區分 GLSL 的零起算索引。
- 外部 COMP 接線優先，未接線時使用該來源的預設圖。
- 預設可以是直接的 Movie File In，也可以經過 Select；重點是來源身分明確、鏈路精簡，並非指定只能使用某一種 TD OP。
- 香蕉是這個初始 2D 來源的預設內容；來源設定仍可選其他圖片、黑色、白色或指定 TOP。

**後續已修訂：** 第一個來源不強制常駐。Grape TOP 可以作為沒有貼圖輸入的產生器，來源清單允許為空；香蕉與第一個 Input 只存在於初始模板。來源刪除仍需處理既有引用、外部接線及依輸入決定解析度的行為。

## 來源、COMP 接口與引用的操作提案

以下為整理後的建議，細節仍可調整：

| 操作 | 建議結果 |
| --- | --- |
| 在 Inputs 明確新增 TOP 來源 | 新增清單項目與所需的 In TOP／預設來源 |
| 從來源清單拖入畫布或新增引用 | 只建立圖內引用節點 |
| 從一般新增選單加入 Sampler | 選擇既有來源；可以預選 Input 1，並清楚顯示來源 |
| 在 Sampler 參數中切換來源 | 從既有清單選擇，改變引用對象；不暗中建立新來源 |
| 刪除引用節點 | 保留來源實體 |
| 更換預設圖 | 更新同一來源的設定與必要 TD 節點，不增加 TOPs 項目 |
| 刪除來源 | 先指出既有引用及外部接線；可刪除最後一項，允許零輸入 |

使用者傾向以來源下拉選單選擇 Sampler 對象；最終入口與顯示方式仍待 UI 設計。從畫布快捷「建立新來源」若要保留，必須明確表達這是新增實體，並使用與 Inputs 相同的建立流程。

首版建議讓每個 TOP 來源一對一對應 COMP Input，再依清單順序把各 In TOP 寫入 Shader 的 TOPs。是否提供「指定 TOP 但不暴露 COMP 接口」的來源模式尚未定案；若保留，也應進入同一份清單管理。

MAT 與 TOP 可共用來源／引用的管理原則，但原生綁定不同：MAT 對應原生 Samplers 頁，TOP 對應 TOPs 輸入列表。這輪不要求把兩者強制實作成相同的 TD 結構。

## 原生行為：已在 TD 2025.32820 驗證

### GLSL TOP、GLSL Multi TOP 與 TOPs

- 一般 GLSL TOP 有三個固定接線口，但透過 TOPs 清單可超過三個來源；已測試五個來源並讀回像素。
- GLSL Multi TOP 提供多輸入接線介面；當來源全部由 TOPs 指定，兩者在本次輸入列表測試的結果相同。
- Shader 接線來源在前，TOPs 列出的來源接在後面。同一 TOP 同時接線又列入 TOPs 會重複計入，TD 不會自動去重。因此建議產品只用 TOPs 綁定這份受管理列表。
- 調整 TOPs 列表順序會調整輸入順序。實際數量上限仍受 TD／GPU 限制，不能由五個來源測試推導為無上限。
- 保留一般 GLSL TOP 與 Multi TOP 是否主要出於向後相容，是討論中的推測，未查得可直接確認其設計動機的證據。

### 混合 2D／3D

原生可混接，TD 依實際貼圖維度分組，再於各組按來源先後順序編號：

| Inputs／TOPs 總順序 | 實際維度 | GLSL 對應 |
| --- | --- | --- |
| Input 1 | 2D | `sTD2DInputs[0]` |
| Input 2 | 3D | `sTD3DInputs[0]` |
| Input 3 | 2D | `sTD2DInputs[1]` |

官方文件列出 2D、3D、2D Array、Cube 四組輸入陣列；不把語音討論中的「1D」直接當成已支援的 TOP 輸入種類。解析度／深度資訊也依對應維度的 `uTD*Infos` 陣列讀取。

另外以 COMP 的三個 In TOP 與原生預設輸入做隔離測試，確認：

| Input 2 狀態（Input 1、3 均為 2D） | 2D／3D 數量 | Input 3 的 2D 索引 |
| --- | --- | --- |
| 未接線，預設為 2D | 3／0 | 2 |
| 接入外部 3D | 2／1 | 1 |
| 拔線，退回 2D 預設 | 3／0 | 2 |
| 未接線，改用 3D 預設 | 2／1 | 1 |
| 保留 3D 預設，但接入外部 2D | 3／0 | 2 |

五個案例均完成原生編譯與像素讀回；此探針驗證數量、2D 來源索引與 In TOP 預設切換，不宣稱完成 3D 圖像內容或 Grape 多維度功能驗收。所有臨時測試節點已移除，沒有修改使用者圖。

**設計上的影響：** 3D 來源拔線後若退回 2D 香蕉，其他 2D 來源的索引也會位移。TD 自動重新編譯不會替 Grape 修正已產生的來源對應；必須處理型別與索引同步，避免編譯失敗或讀到另一個有效但錯誤的來源。

目前建議每個來源具有明確維度，且使用同維度的預設圖。不同維度接入時如何提示、是否允許明確改型、如何在 TD 原生接線改變時保護輸出，仍待決策及驗證；不能把「顯示型別不符」視為已解決 TD 即時重新編譯的行為。現行 Grape 的受管理 TOP Inputs 仍只支援 2D。

## 實作時建議遵守的邊界

- 固定來源 ID，將名稱、列表位置、COMP 接口位置與 GLSL 維度內索引分開。圖節點追蹤來源 ID，編譯器推算索引；排序時既有外部接線也應跟著來源，不能只重排 TOPs 字串。
- 保持一份可編修的來源定義；若另有 TD Table DAT 供檢視，應為衍生資料。Uniform 的原生參數同步與使用者 Expression／Bind／Export 仍須保留，不能藉此筆記改成所有值都由圖資料覆寫。
- 預置快捷可用固定預置身分查找現有來源；同名但型別或用途不同時需明確處理，不靜默改名或覆寫原值。兩個刻意建立的來源即使現在讀同一張圖，也不能只按路徑或內容自動合併。
- 每個 Input 有一個穩定終點及一列預設來源空間。檔案可用 Movie File In、純色可用 Constant、引用外部 TOP 可用 Select；只建立實際需要的層級，避免為每層再包一個 Select。
- 切換預設時更新／替換本列所需節點；清理只處理工具擁有且確定無用的節點，不因名稱相似刪除使用者內容，也不累积每次切換留下的舊資源。
- 新建時程式化計算間距，保留可讀名稱／標籤。一般套用應保留後续人工調整的位置；整體重排的觸發方式仍需設計。
- 舊獨立 Sampler、`input:0` 與現有 `topInputs` 的轉換需納入同一輪規劃，保留來源、圖內引用、外部接線與公開參數綁定。不能只讓新圖乾淨而把舊圖留在無法升級的狀態。

## 當時列出的待決策（實作結果見下節）

1. 不保留永久不可刪的第一個 Input；零輸入與跟隨輸入解析度的行為需實測。
2. 首版是否所有 TOP 來源都對應 COMP 接口；指定路徑但不暴露接口的能力如何呈現。
3. 一般新增 Sampler 的預選來源與清單 UI，以及明確新增來源的快捷入口。
4. 來源維度的宣告、改型與同維度預設；原生接線不相符時的實際處理方式。
5. 來源刪除／排序的操作邊界、舊圖遷移與失敗復原，以及 TD 內部最小結構和自動排列方式。

## 使用者睡前修訂與本輪執行方案

使用者授權先記錄可回退版本，再直接實作並清理相關遺留邏輯，以可操作的新版本繼續收斂設計。保留 TD 組件內部人類可讀、後續容易修改的大原則。

1. 保存目前工程與 Git 基準。來源清單允許零項，初始模板提供一個 2D 香蕉來源；驗證 TOPs 可否沿用 Common 的跟隨輸入解析度，以及無輸入時的退回尺寸。
2. TOP 使用單一受管理清單，既有 Sampler／TOP Input 引用統一指向來源；一般新增引用不建立來源。新建來源名稱對應 TD 的實際索引名稱，改名與引用身分分開。
3. 遷移舊 TOP 獨立 Sampler 與 input:0，保留原圖、公開參數及外部來源語意，修正來源切換導致無法升級的路徑。MAT 維持其原生來源模型。
4. 每項來源僅保留必要的預設來源與 In TOP，依列預留位置，清除已確認無用的工具資源；明確處理未知或人工建立的 TD OP。
5. 優先交付目前已支援的 2D；多維度仍保留擴充方向，這輪不宣稱已支援 3D／Array／Cube。完成核心、原生 TD 與網頁驗證，更新模板、保存新版並提交。
