# 下一輪 UI 與圖根操作筆記

這份文件記錄目錄遷移期間的使用者修訂。2026-09-12 UI 輪已實作面板／Layout、窄版頂列、畫布註解、Label 行尾產碼，以及原生 TOP／MAT 頁序；圖根恆常節點與 Viewer 所有權仍保留後續。具體完成狀態見 [本輪驗證](../development/UI_REFINEMENT.md)。具體外觀可在下一輪繼續調整。發生歧異時，回看原規劃並討論偏差原因；舊規則不是不可修正的限制。

## 圖根的恆常節點（設計方向）

- Uniforms／Colors、Constants、Buffers、Attributes、Samplers 等集合可以成為圖根恆常入口，類似 Color Output。按目標與 stage 提供對應集合，沒有模板的集合起始為空。
- 點擊後在 Parameter 面板編輯；節點上的 `+` 與面板新增走同一操作。
- 集合節點呈現現有定義，不另建一份資料。單項引用節點仍可並存。
- 恆常集合節點不能刪除、不能打包進 Subgraph；集合中的項目仍可刪除。一般引用節點可刪除，且不等於刪除來源。
- 打包時來源保留外層，建立必要 Input 並保留來源名稱，方便辨識。
- 空集合的緊湊顯示、隱藏方式、混合框選的回饋是待實作時檢視的細節。

## 末端灰點：新增 I/O 的快捷入口（後續研討）

使用者以 ComfyUI 子圖輸入／輸出清單末端的灰點截圖作為操作參考，希望採用相同的快捷新增概念，延伸到 Subgraph、Uniforms、Attributes、Color Output、Vertex Output 等適用入口。這是後續功能方向，尚未實作；預設命名、後續改名與排序的最佳體驗仍待研討。

- 灰點代表新增入口，不是已存在但未接線的正式端口。建立成功後加入正式項目，末尾繼續提供灰點；空集合也能有一致的操作入口。
- 新增仍編輯同一份來源／介面定義，沿用既有集合節點、單項引用、刪除與同步邊界，不因快捷入口產生第二份資料。
- 建議方案，尚未定案：從既有端口拖線到灰點，在該集合允許的規則下建立項目並接線，能判定時預填型別與名稱。點按灰點則在 Parameter 進入新增流程，也提供觸控可用的入口。
- 建議方案，尚未定案：預設名稱優先取相關來源／端口的語意，無合適名稱時使用該類項目的流水號。Parameter 維持統一的完整命名、型別及排序入口；是否另提供畫布行內改名，留待實作原型比較。
- 同一操作外觀不代表每類可任意新增或轉型。後續逐類釐清：Subgraph 介面、Uniform 定義、實際幾何 Attribute 選取、Color buffer 數量與固定型別，以及 Vertex Output 固定語意／可擴充項目的界線。不能僅由拖線便假設某個 Attribute 已存在。
- 建議新增與接線合為一次 Undo；取消時不留空定義。灰點須可辨認為可操作入口，並有適合觸控的點按範圍。
- 排序需區分顯示順序與有實際語意的索引（例如 color buffer）。改名／排序與既有連線的關係、名稱和 GLSL 識別字或 Label 的關係，不能藉此筆記代替尚保留的決策。

## 面板與 Layout

- 保持左側欄／中央網路圖／右側欄的整體結構，面板可以跨左右側欄移動。
- 拖拉分頁必須支援同組內排序，以及合併到另一組時選擇插入位置；提供清楚的插入提示，順序隨 Layout 保存。
- Layout 入口改為精簡按鈕或下拉選單，提供面板顯示狀態、切換預設及使用者配置、保存目前配置、管理配置。Wire 的預設名稱僅為操作參考，不代表照搬所有布局。
- 使用者先自行整理配置，再選定預設與其他選項。
- 作用中分頁不加底線，刪除為底線保留的高度；非作用中分頁變暗，標題列使用整體 UI 的中性色。
- Parameter 的節點底色標題四周不留 gap，高度降至與分頁列一致；一般 Parameter 內容需精簡。
- 左右側欄的快速收合入口各放一側。面板收合圖示需清楚、精簡。
- 連線刪除入口需改善可發現性。目前程式支援選取連線後按 Delete／Backspace；這不是新的已完成 UI。
- 畫布節點的註解直接顯示內容，移除「Comment・註記」標題與展開箭頭，取代先前畫布註解可折疊的做法。文字統一使用一般內文色，不跟隨節點色；此修訂指畫布節點，Parameter 編輯區未因此改動。

## 浮動新增面板：Uniform 辨識色（2026-09-13 已實作）

- 使用者截圖中搜尋 `mix` 時，一般運算節點 `Mix` 與現有 Uniform 引用 `mixfac` 都呈現紫色，沒有表達兩者的種類差異。
- Uniform 引用應沿用既有 Uniform 節點的辨識色；作用中／未作用中的回饋仍需清楚。
- 程式核對：浮動清單為來源引用使用 `input:<id>` 作為項目 key，但配色分類仍依原始節點 key 判斷，導致 Uniform 引用落入 Math 的預設色。已改為依實際來源種類配色，包含 Sampler 引用與 Time／Frame 預設。
- 已依使用者後續指示實作；來源名稱與分類皆屬 UI 顯示，不改寫節點定義版本。

## 浮動新增面板：Inputs 分類（2026-09-13 已實作）

- 使用者要求在浮動新增面板的分類欄加入 **Inputs** 主分類，並提供子分類，讓來源項目能透過分類瀏覽找到。
- 子分類依資料種類分組，與左側 Inputs 面板對應。本輪使用已支援的 Uniforms、Samplers 兩個子分類，Time／Frame 預設歸 Uniforms；其他來源種類待實作後納入。
- 延續既有流程：新增來源與引用現有來源仍是不同動作；分類只提供查找入口，不建立另一份來源資料。
- 已與 Uniform 配色問題一同實作，全域搜尋與接線的相容型別篩選保留。

## 輸入引用節點：以來源名稱顯示輸出端口（2026-09-13 已實作）

- 使用者要求 Uniform 等輸入類節點在畫布上清楚顯示來源名稱；採用輸出端口文字的位置，將泛用的 `out` 替換為實際來源名稱。
- 截圖範例：標題維持 `Uniform`，輸出列由 `out  float` 改為 `mixfac  float`，使引用來源與資料型別可以直接辨認。
- 顯示文字取自同一份來源定義，來源改名時引用節點隨之更新。實作應保留內部端口身分與既有接線，僅修改顯示名稱。
- 此項確認的是來源名稱在輸出端口的位置；Label 與 Library／本地來源資訊的其他畫布安排仍維持先前保留的決策。
- 已實作於 Uniform／Sampler 引用；來源改名同步更新可見端口文字，原有端口 ID 與接線保留。

## Label 產碼修訂

Label 改為對應程式行末的註解，拿掉 `Label:` 前綴，取代先前上方獨立註解的規則：

```glsl
vec4 sg_n_texture = texture(sTD2DInputs[0], sg_n_uv); // 中文?
// Comment 保持在下方
```

Label 不用作 GLSL 識別字，仍需防止換行或特殊字元改變程式語意。本輪實作採第一個有效程式行尾；沒有獨立程式行的節點與 Subgraph 邊界保留單行 `// 名稱`，不為註解新增變數。

Label、Library／本地來源資訊在畫布節點上的配置仍保留決策。

## 節點內數值與整合 Vector（0.8.82，已授權實作）

使用者確認接線規則後，以「OKGO」授權本輪實作，再透過操作回饋調整。完整向量與分量的結構會影響數字欄位排版，因此整合節點、inline 數值及 Value Ladder 同輪處理；不再只列為待辦。

- 新 Vector 支援 vec2／vec3／vec4：完整向量提供基底，分量線覆寫對應位置，全部輸出都代表最終結果。基底接線後手填值全部隱藏，分量接孔保留；該分量未接線且沒有基底時，才使用保存的手填值。
- 向量占用連續分量並合併接孔。例如 Y 接 vec2，Z 接孔消失。新線自動拆掉相交的整條舊分量線，來源節點及其他引用保留；原本 ZW 被新 YZ 替換時，W 恢復基底或手填值。先驗證，放開才修改，一次 Undo 恢復。
- Float、固定向量、Color RGBA 及適用的未接線數值可直接在圖上編輯，與 Parameter 共用資料。接線欄位隱藏；欄位、接孔與背景操作分開，保留全節點拖曳。
- 沿用 Value Ladder；拖動只暫存數字，放開一次提交，Escape／取消還原。處理焦點、圖更新、文字快捷鍵與觸控平移的邊界，不新增連續提交 Shader 的模式。
- 新 Vector 按真正生效的來源判斷常數性及產碼，包含只使用某個最終分量、基底完全被覆寫的情況。舊節點、舊圖及固定常數用途保留。
- Color Output 的雙語 Help 已同步目前共用串流、重新連線／電源與尺寸更新行為，移除 512 像素／每秒更新的舊說明。
- 詳細規則見向量功能文件；原生 TD 驗證、保存與版本提交由 STATUS／TESTING 記錄，不先宣稱完成。

## 節點緊湊呈現（0.8.83，2026-09-16）
