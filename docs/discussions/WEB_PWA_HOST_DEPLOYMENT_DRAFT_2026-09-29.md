# 網頁、PWA 與宿主部署草案

記錄日期：2026-09-29。

狀態：下一版產品的討論筆記／候選部署方案，尚未定案、未實作。使用者本次只要求保存筆記，保存後回到原本工作；本文不是啟動重構、修改現行產品、建立分支或部署服務的授權。

本筆記保存 2026-09-28 至 2026-09-29 的產品方向討論，以及 Codex 在「假設由你決策」前提下提出的具體部署方案。使用者提出的方向與助手建議分開列出，不把「請記錄」視為逐項接受。現行圖同步與保存行為仍以現行功能文件及 [GRAPH_SYNC_SAVE_PLAN.md](GRAPH_SYNC_SAVE_PLAN.md) 的實作狀態為準。

## 1. 使用者提出的方向

- 編輯器以沒有必要後端依賴的網頁應用為能力界線；GitHub／GitHub Pages 是明確入口，同一份前端也能放到使用者自己的靜態托管或區網網站。
- 圖的處理與產碼移到 JavaScript 前端，支援原生 WebGL 預覽與 ISF 輸出。TouchDesigner 不再托管編輯器或替前端產生圖的 GLSL，而是接收產出的 GLSL、Uniform／資源綁定資訊及參數更新；GPU 編譯與執行仍在宿主。
- 宿主帶入配對資訊開啟編輯器，可作為預設入口；宿主的 Editor URL 可以更換。也保留在現有編輯器貼上配對資訊的入口。
- 目標須辨認到實際執行實例。同一台機器可以有多個 TD 程序，同一區網也可以有多台 TD；未來可包含 Resolume 裡的 FFGL 插件實例。
- 可以透過列表管理已加入的實例及目前對應關係，不要求以整個區網自動探索為前提。
- 圖與機器不限定一次只有一個。沒有連線時仍能編輯和保存圖；使用者之後可以選擇要套用到哪個支援接收的 TD OP 或其他宿主實例。
- 儲存位置可以是瀏覽器、使用者自己的空間，或日後提供的資料庫。具體儲存選項及同步政策尚未定案。
- 保留輕量使用者「開網址就能編輯」的便利性。必須先安裝本機 Node.js／npm 才能使用，會改變產品定位，不能默認成必要條件。
- 社群提交／審查服務可以後做；發布後的資源傾向以靜態資產供使用者取得。
- 目前仍以責任、能力界線和可落實性規劃為主，不要求先完成一份巨大 API 框架。

## 2. 助手建議的部署構成

建議採「靜態網頁＋可選離線 PWA＋各宿主自己的連接元件」。這是候選方案，不代表已完成技術驗證。

| 部分 | 建議部署位置 | 責任 |
| --- | --- | --- |
| 編輯器、JS 產碼器、WebGL 預覽、ISF 匯出 | GitHub Pages；另交付相同版本的靜態檔案包 | 圖的編輯、驗證與產碼 |
| 離線程式、圖庫與已下載資產 | 使用者的瀏覽器／PWA | 離線啟動、自動儲存與工作恢復 |
| TD 連接元件 | 使用者的 TouchDesigner，以 `.tox` 交付 | 身分與能力回報、接收並驗證產物、參數／資源綁定、套用與回報 |
| FFGL 連接插件 | 後續的 Windows／macOS 原生插件 | 接入 Resolume 的插件實例、輸入貼圖和宿主參數 |
| 社群資源庫 | 後續版本化靜態資產 | 發布節點、範例與素材；提交／審查另設接口 |

Node.js／npm 可用於開發與建置，核心使用流程不要求使用者安裝。雲端帳號、資料庫、配對或轉送服務均不是首版核心編輯能力的必要依賴。日後是否提供可選本機工具，另行評估。

## 3. 網站交付與版本更新

- 一個固定正式網址，另設隔離的測試站；隔離網站資料與 Service Worker 範圍，避免測試版本覆蓋正式工作區。
- 每次正式發布，同時產生網站部署產物及可自行托管的靜態檔案包。需支援部署基底路徑與可設定的 Editor URL，不綁死官方主機。
- 正式托管使用 HTTPS。一般區網 HTTP 位址不能直接假設具備完整 Service Worker／離線能力；localhost 例外不能推廣到 iPad 存取其他電腦的情境。
- 更新先下載並確認完整的新版本，保存目前工作後再切換，不因新版上線就強制重新整理編輯中的頁面。
- 程式快取更新與圖庫資料分開處理；資料格式升級、失敗復原與版本相容性需要明確政策，不能藉更新清除使用者的圖。
- 網域、協定、port 或瀏覽器容器改變可能形成不同儲存空間。從官方站移到自架站，以及 Safari 分頁移到 Mac Web App，不應預設資料自動共用；需要匯入／匯出或日後的同步途徑。

## 4. PWA 與離線內容

PWA 安裝入口與離線資源準備是兩件事。可以設計成連續流程，但「加入主畫面／Dock」不等於瀏覽器已下載整個網站。

核心離線清單建議包含：

- HTML、CSS、JavaScript、必要 Worker，以及完整編輯與產碼程式。
- 內建節點定義、GLSL 模板、必要 JSON 設定及相依定義。
- 介面圖示、SVG、字型、基本貼圖、材質預覽所需的基本模型／場景資產。
- 如功能需要，包含瀏覽器可執行的 WebAssembly 模組。
- 基本範例圖及必要操作說明。

大型模型、環境貼圖與社群資產包可以另外選擇下載。圖片等資產可由建置流程產生清單，不必由使用者逐一指定。使用者的圖與匯入素材另外保存，不混進程式版本快取。

只有確認核心清單完整保存後才顯示「已準備好離線使用」。首次仍須取得這些檔案；保存圖片網址不等於保存內容。雲端服務、未下載的資源和宿主即時輸入，不能標成離線可用。

必須分開測試：

1. 完成下載後關閉編輯器，切斷網路，再重新啟動、建圖、產碼、WebGL 預覽、存檔、匯出。
2. 沒有網際網路但區網仍可用時，能否連到已配對的宿主。
3. 完全無網路時，核心編輯功能可用，宿主與雲端能力明確顯示不可達。

PWA 不會因此獲得 Node.js、TD 或原生 FFGL 的執行能力，也不會解除瀏覽器的網路、檔案與背景執行限制。宿主應在編輯器背景暫停或關閉時繼續執行最後成功套用的成果。

## 5. 圖的保存與執行目標

首版建議使用 IndexedDB 類的瀏覽器資料庫自動儲存，並提供可攜專案檔。專案檔保存可編輯的圖、必要資產與版本／相依資訊，不能只保存 GLSL。檔案格式與副檔名尚未決定。

瀏覽器儲存需處理容量不足、寫入失敗、持久儲存核准狀態與恢復流程；不能把它宣稱為永不遺失的備份。匯出／匯入是基本能力；使用者空間與雲端同步之後接入。

圖、儲存位置、執行實例、連線及套用關係分開辨認：

| 狀態 | 必須能回答 |
| --- | --- |
| 儲存 | 圖存在哪裡、最新修改是否寫入成功 |
| 連線 | 哪個宿主實例在線、離線或需要重新配對 |
| 套用 | 每個目標正在執行哪一版、是否有修改尚未套用或套用失敗 |

套用到某個 OP 不自動搬動圖的儲存位置。是否在 TD 工程內額外保留可編輯圖副本、重連是否自動套用、即時參數值的所有權及保存規則，均須另行決定。

同一張圖可以對應多個目標；各目標可有不同資源／參數綁定。目標相容性必須檢查，同一張圖不代表各宿主收到完全相同 GLSL，也不表示 TD 專有節點可以無條件在 WebGL／ISF／FFGL 上執行。

## 6. 宿主入口、配對與候選通訊方式

建議每個 TD 程序提供一個連接入口，入口管理其中可接收更新的實例／OP 清單，不要求每個 OP 占用獨立 port。前端可以加入多個入口。身分模型要分清機器、宿主程序、目標實例與圖；IP 和 OP 路徑只能作定位／顯示資訊，不能單獨承擔穩定身分。

預設入口候選流程：

1. 使用者從某個 TD 實例按 Open Editor。
2. 宿主開啟設定的 Editor URL，附上入口、目標實例與一次性配對資訊。
3. 編輯器確認宿主身分、協定版本與能力，完成配對。
4. 使用者選擇圖與目標，檢查綁定並套用；介面分別呈現儲存、連線和套用狀態。

現有編輯器可貼上配對資訊加入其他宿主；列表可以包含已配對／歷史入口，不依賴整個區網自動列舉。由宿主發起 Open Editor 不等於底層 TCP 連線反向；普通網頁仍不是等待原生程式連入的 WebSocket server。

助手建議首版先驗證 WSS（加密 WebSocket）直連。TD Web Server DAT 已提供 WebSocket 與 TLS 能力，可只承擔接收接口，不托管編輯器 HTML／JS。

這個選擇的實際代價與待驗證條件：

- 憑證必須受客戶端信任，並符合連接所用的名稱／位址。WSS 不是單純把 `ws` 改成 `wss` 就完成跨平台部署。
- 首次設定需考慮憑證配置／信任、本機或區網權限及必要的入站規則；不能承諾所有平台零設定。
- Safari 不能假設接受 HTTPS 網頁直連未加密 localhost；Chromium 的本機網路權限也不能忽略。不能以關閉瀏覽器安全機制作為正常部署方式。
- 憑證提供、更新與信任的具體流程尚未選定，必須用實機驗證後再定案；不能把文件查證當成已連線成功。
- 配對憑證與授權不混進可分享的圖檔。宿主應確認允許的編輯器來源、配對與目標操作範圍；具體授權 UI 與協定仍待設計。

宿主接收產物後，負責原生編譯／執行與結果回報；更新失敗保留上一個成功版本。前端產碼與宿主 GPU 編譯不是同一責任。

WebRTC、雲端配對／轉送及可選本機程式暫保留擴充接口，不先成為核心依賴。若直連的首次設定負擔無法接受，再比較便利服務的成本；WebRTC 本身仍需要交換協商資訊，跨網路直連也不保證成功。

## 7. 建議的驗證與推進順序

1. **部署接點原型**：最小 HTTPS／PWA 頁面連 TD，傳一份 shader 和一個參數。測 Windows Edge、Mac Safari、iPad Safari，驗證憑證、權限、首次設定成本、重連與背景恢復。分別覆蓋同機、跨裝置區網、無網際網路但區網仍可達情境。
2. **最小離線編輯流程**：少量代表性節點完成建圖、JS 產碼、WebGL 預覽、保存、冷啟動恢復與 ISF 匯出，先證明閉環再擴充。
3. **實例管理**：支援多 TD 程序、多機器、多 OP，以及各目標的能力、綁定和最後成功套用版本。
4. **現有能力遷移與第二宿主**：按功能盤點逐步遷移；以 FFGL 驗證協定是否真正可擴充。FFGL 的輸入／參數生命週期與動態參數結構需要獨立驗證，不能假設與 TD 相同。
5. **可選共享服務**：社群提交、雲端圖庫／同步、遠端配對與轉送另作後續。

以上是規劃順序，不是立即執行清單。沒有建立新分支／worktree、部署網站、修改現行連線、產碼、儲存或 PWA 功能。

## 8. 尚未收斂的決策

- TLS 憑證部署及信任流程能否符合目標使用者的便利性要求。
- 宿主／實例身分跨重啟、複製工程、OP 改名時的規則。
- 現有分頁與已安裝 PWA 的 Open Editor 路由與配對體驗。
- 專案檔格式、資產相依與版本升級、歷史保留及備份策略。
- 離線核心素材包的大小、選配下載與儲存容量政策。
- 重連後的套用行為、即時參數控制權，以及多編輯器對同一實例的衝突處理；多機／多實例不自動等於多人協作。
- 首版節點範圍、不同產碼目標的能力邊界、FFGL 的交付時點。
- 原倉庫分支／worktree 或新倉庫等重構落點，不因保存本筆記而定案。
