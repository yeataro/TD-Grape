# 架構不變量 (Architecture Invariants)

閱讀對象：實作 GrapeL 的 AI agent。與 Antigravity `AGENTS.md` 並列，皆為強制。
版本：2026-09-22

契約由 `templates/architecture-invariant.test.ts` 在 CI 執行。本文件只列原則、規則與你的義務；核查由測試完成，不要求你自律。

## 大原則（凌駕下列所有規則）

**一個節點型別 = 一個地方。** 新增或修改任一節點的行為，只准動它的定義資料；引擎、型別引擎、編輯器核心不得為此改動。

下列四條不變量只是這條原則**可被機器檢查的子集**，必然不完整——會有違反原則、但四條都抓不到的情況。**規則未涵蓋時，以本原則裁決，不以「測試沒紅」當通過。** 這一層對應 Antigravity `AGENTS.md` 三條紅線的正向表述：紅線說「不准硬編碼特例」，本原則說「節點的一切只在定義裡」。

## 四條不變量（大原則的可檢查子集）

| # | 規則 | 失敗信號 | 對應紅線 |
|---|---|---|---|
| 1 | 引擎與編輯器核心不得對特定節點 id/key 分支 | `node.id === '...'`、`switch(node.key)` | 一 |
| 2 | `emit.capability` 屬於封閉能力集（有數量上限） | 為單一節點發明新能力 | 三 |
| 3 | 節點完整行為僅由其定義資料決定 | 產碼需要定義表外的節點特例邏輯 | 一、三 |
| 4 | 節點身分只從定義目錄誕生，別處無平行清單 | 出現 `NODE_IDS`/`EMITTER_IDS` 等硬編碼清單 | 一（SSOT） |

## 義務

1. 第一階段單節點閉環完成後，立即把測試接上實際 API（見檔內 `[ADAPT]`），納入 CI。不變量意圖不可弱化。
2. 新增節點**只改定義目錄**。若需要動引擎核心 → 停：那是不變量 1 或 3 即將失敗。
3. 測試從第 1–3 個提交起存在，不是「之後補」。晚補只會把壞形狀固化。

## 不變量失敗時

不是障礙，是設計對話的觸發點。**禁止加特例讓測試轉綠。** 改為：

1. 回報這個節點揭露的能力集缺口；
2. 提出要新增的**泛型能力**（跨節點共用），非節點特例；
3. 待人類確認能力集擴充後再繼續。

## 前提

守全局的角色必須**獨立於動手的角色**：動手的注意力看不見自己的漂移。架構複審由獨立 context 的 agent 執行，不是叫 builder 自己檢查。

## 分工

- Antigravity `AGENTS.md`：架構應該是什麼形狀。
- 本文件 + 測試：形狀如何被機器持續驗證。
