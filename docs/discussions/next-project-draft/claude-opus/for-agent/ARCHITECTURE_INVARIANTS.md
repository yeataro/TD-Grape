文件版本：2026-09-22
閱讀對象：接手 GrapeL 專案實作的 AI agent。

---

## 這份文件為什麼不是一份「守則」

本資料夾原本有一份 `EXECUTION_CONTRACT.md`，內容是要 agent「在宣告完成前回答一串架構問題」。我在審查自己的產出時判定那份文件是**致命的自我矛盾**：它主張「架構約束必須活在測試與結構裡，因為文件無法在違反的當下報錯」，然後自己卻是一份靠 agent 自律的文件。一個正在漂移的 agent，正好就是不會誠實回答那串問題的 agent。

所以那份守則已被移除，換成你眼前的東西：一個**可執行的機制**（`templates/architecture-invariant.test.ts`）加上這份說明它為何存在、如何擴充的文件。本文件不要求你自我核查；核查由測試在 CI 完成。

---

## 機制本身

`templates/architecture-invariant.test.ts` 把 Antigravity `AGENTS.md` 的三條架構紅線，轉成四個會失敗的測試：

| 不變量 | 守住的紅線 | 違反時的信號 |
|---|---|---|
| 1. 引擎核心零節點身分特例 | 紅線一（禁止特例硬編碼） | 引擎原始碼出現 `node.id === '...'` 或 `switch(node.key)` 時，測試紅燈 |
| 2. emit.capability 屬封閉能力集 | 紅線三（泛型產碼） | 有人為單一節點發明新能力時，測試紅燈 |
| 3. 純資料產碼閉環 | 紅線一、三 | 某節點需要定義表無法表達的行為時，測試紅燈 |
| 4. 節點註冊表僅由定義目錄構成 | 紅線一（SSOT） | 別處出現平行的硬編碼節點清單時，測試紅燈 |

這四個不變量對應 TD-Grape 具體的病根：它的 `EMITTER_IDS`、`CONSTANT_EXPRESSIONS` 等 frozenset 與 `CATALOG` 是需要人工對齊的平行清單（不變量 4 擋這個），它的 `_compile_flat` 是 1,800 行以節點 key 分派的 if/elif 鏈（不變量 1、3 擋這個）。

---

## 你要做的事

1. **第一階段完成單節點產碼閉環後，立刻把這個測試接上實際 API。** 檔案中標記 `[ADAPT]` 的地方依 GrapeL 的模組路徑對接。不變量的意圖不可弱化，只可調整存取方式。
2. **讓它進 CI。** 不變量測試不是可選的；它和功能測試一樣是紅綠燈。
3. **每次新增節點，只改定義目錄。** 如果你發現自己為了新節點想動引擎核心，先停下——那就是不變量 1 或 3 即將失敗的時刻，也是 TD-Grape 走錯的那一步。

---

## 當不變量與眼前任務衝突時

如果某個節點的行為真的無法用現有能力表達，正確的反應**不是**在引擎裡加一個特例分支讓測試繞過，而是：

- 停下，回報這個節點揭露了能力集的缺口；
- 提出要新增的**泛型能力**（跨節點可共用），而非節點特例；
- 由人類確認能力集擴充後，再繼續。

不變量失敗是設計對話的觸發點，不是要你想辦法讓它變綠的障礙。這條規則本身也受不變量 2 保護：能力集有上限，你無法靠「每個節點發明一個能力」來規避。

## 與 Antigravity AGENTS.md 的分工

- Antigravity `AGENTS.md`：規定架構**應該是什麼形狀**。
- 本文件與測試：規定**如何讓形狀在每次 commit 被機器驗證**，不依賴任何人記得檢查。

兩者都是強制性的。
