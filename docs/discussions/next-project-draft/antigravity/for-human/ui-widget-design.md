## 一、 核心價值：「畫布即編輯（Canvas-First）」的體驗資產

在 TD-Grape 0.8.163 的探索中，最成功且具備靈魂特質的體驗是：**創作者不需要點開右側 Inspector 參數欄，直接在畫布節點卡片上就能調通 80% 的數值與著色**。

舊專案的致命傷不在於這個體驗，而是在於其**「以 500KB 命令式 DOM 拼接硬刻出這套體驗，導致零共用性與義大利麵代碼」**。新專案的目標是保留這套優秀的互動手感，但底層透過正交原子組件徹底重構。

## 二、 從真實截圖提煉出的「四大卡片幾何原型」

經檢視既有系統的 5 組節點實例截圖，畫布上的所有複雜節點本質上收斂為四種幾何原型：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 原型 A：常規運算型 (Mix, Subtract)                                          │
│ 標題列：標題 + Auto 多載選單 (右上角)                                       │
│ 接孔行：左側輸入孔、右側輸出孔。                                            │
│ 特徵：未接線的輸入孔，在同行自動顯示行內數值輸入框 (如 Subtract a=1)。       │
├─────────────────────────────────────────────────────────────────────────────┤
│ 原型 B：單純數值/Uniform 型 (Scalar, uValue)                                 │
│ 標題列：名稱 + 型別標籤                                                     │
│ 內容區：單一全寬階梯滑桿 (Single Wide Slider)。                              │
├─────────────────────────────────────────────────────────────────────────────┤
│ 原型 C：複合向量/色彩型 (uColor2, Color RGBA)                               │
│ 標題列：名稱 + Uniform 標籤                                                 │
│ 內容區：分量數值輸入框格網 (R, G, B, A) ＋ 底部即時顏色預覽條 (Color Bar)。   │
├─────────────────────────────────────────────────────────────────────────────┤
│ 原型 D：高階結構型 (Matrix)                                                 │
│ 標題列：名稱 + mat3 標籤                                                    │
│ 內容區：可折疊的欄列樹狀視圖 (Column 0, Column 1, Column 2 Accordion)。      │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 三、 三層原子積木架構（解決義大利麵代碼）

絕對不要為每個型別分別寫 Widget（如 `ScalarWidget`、`ColorWidget`、`MatrixWidget`）。所有數值微觀互動（滑動、雙擊全選、階梯拖曳）在物理上是同一件事。

```
┌─────────────────────────────────────────────────────────────┐
│ Level 1: <ChannelAtom> (單分量原子)                          │
│ - 唯一負責：1 個數值的渲染、點擊輸入、階梯拖曳手勢、上下限 Clamp  │
│ - 屬性：value, step, min, max, label (如 "R" 或 "X")        │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ Level 2: <VectorGroup> (分量群組)                           │
│ - 唯一負責：將 N 個 <ChannelAtom> 排成水平或垂直格網          │
│ - 屬性：values: number[], labels: ["X","Y","Z","W"]         │
└──────────────────────────────┬──────────────────────────────┘
                               │
                ┌──────────────┴──────────────┐
                ▼                             ▼
┌─────────────────────────────┐ ┌─────────────────────────────┐
│ Level 3-A: <ColorWidget>    │ │ Level 3-B: <MatrixWidget>   │
│ - 組合：                    │ │ - 組合：                    │
│   • 1 個 <VectorGroup>      │ │   • 3 個 <VectorGroup> (欄) │
│     (labels: RGBA)          │ │   • 外加折疊手柄 (Accordion)│
│   • 底部掛載 1 個色條預覽    │ │                             │
└─────────────────────────────┘ └─────────────────────────────┘
```

### 優勢：
1. **互動邏輯全世界唯一**：數值階梯演算法只寫一次（50 行），任何分量、向量、色彩、矩陣與行內接孔全部繼承。
2. **畫布與 Inspector 100% 共用**：畫布卡片本體掛載 `<ColorWidget>`，點選側邊欄時直接渲染同一個 `<ColorWidget>`，資料雙向綁定。

## 四、 經典案例：`Split` 的動態分量與 `Invert` 預設

### 1. `Split` 動態接孔標籤（XYZW vs RGBA）
* **現象**：接到一般向量時右側輸出 `X, Y, Z, W`；接到色彩時自動變為 `R, G, B, A`。
* **解法**：不寫任何 `if (key === 'split')`。在型別系統定義語意通道：`vec4` 通道為 `["x","y","z","w"]`，`color4` 通道為 `["r","g","b","a"]`。`Split` 僅聲明輸出接孔為 `$channels(input.value)`，由型別推導自動展開標籤。

### 2. 搜尋中的「主標題（預設級）＋ 副標題（真身節點）」
* **現象**：使用者搜尋 `Invert`，希望看到 `Invert`（主標題）與 `Subtract (1.0 - x)`（副標題）。
* **解法**：`Invert` 是 `subtract` 的預設配方（Preset）。建立節點時，本體依然是 `subtract`，但預填 $a=1.0$ 並鎖定。**產碼器零負擔，完全不需要為 Invert 寫 emitter！**
