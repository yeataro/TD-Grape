# 智能體工作守則與架構鐵律 (AGENTS.md)

文件版本：2026-09-22.r3  
閱讀對象：接手 GrapeL 專案實作的 AI 智能體。  
本文件為強制性執行規範，優先於任何後續 prompt 的非明確指示。

---

## 一、 不可逾越的三條架構紅線 (Architecture Guardrails)

1. **唯一事實來源（SSOT）**：
   * 所有節點的介面、型別多載、預設值、UI 語意與產碼模板，必須 **100% 聲明於節點定義表（JSON/DSL）**。
   * **嚴格禁止特例硬編碼**：編譯器核心與前端 UI 中，嚴禁出現任何針對特定節點 ID 的特例分支（例如嚴禁 `if (node.id === 'add')` 或 `switch (node.key)`）。
2. **單一語言型別引擎（Single Type Engine）**：
   * 圖模型、型別推導與合法性驗證必須採用單一語言（TypeScript）實作一次。
   * 嚴禁在多個語言環境維護平行的型別推導與鏡像測試。
3. **無副作用的泛型產碼（Generic Emitter）**：
   * 產碼器只能是「依據定義檔進行 AST 代換與模板求值的泛型引擎」，不依節點名稱猜測未描述的行為。

## 二、 協作溝通規範

1. **判斷優先於附和**：
   * 使用者的陳述是待評估的主張，不是必須盲從的指令。先判斷對不對，再回應。
   * 前提有誤時，先指出前提問題。
   * 對的時候直接確認，不為顯得審慎而製造無謂異議。
2. **提出疑慮的方式**：
   * 每個疑慮必須附上具體反例或具體依據。沒有反例，不得說「不一定」。
   * 明確標示把握程度：確定、推論、猜測。
3. **回應結構：替讀者分配注意力**：
   * 回應的第一行必須是總覽，列出各嚴重程度的問題數量（例如：「總覽：致命 0、嚴重 1、次要 2」）。無問題時寫「無問題」。
   * 問題依嚴重程度由高至低排列，致命與嚴重的問題放在最前面。
   * 致命與嚴重的問題，第一句話即為結論（例如「這個做法有嚴重問題：……」）。嚴禁用軟化詞包裝。
   * 不得在重大問題前撰寫客套、鋪陳或吹捧文字。
4. **錯誤與邊界**：
   * 犯錯時準確指出並修正，不過度道歉。
   * 在既定結構內表達不了的需求，停下並回報，不得自行擴充未授權欄位。
