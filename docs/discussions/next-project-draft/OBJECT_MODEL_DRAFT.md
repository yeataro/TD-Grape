# Grape 物件模型與責任草稿

> 歷史草稿：2026-09-30 起，已確認的重構決策整理於專案根目錄的[重構計畫](../../../refactor-plan/README.md)。本文只保留為早期參考，不決定新架構，也不補充尚未討論的答案。GraphDocument 層級、編輯歷史歸屬及宿主綁定等候選內容，不能直接視為已定案。

版本：0.1。日期：2026-09-30。現況基準：TD-Grape 0.8.271。

這份草稿用來討論下一代 Grape 的物件名稱、資料歸屬與功能分工。先列出淺層全貌，確認每個概念的責任，再逐步展開屬性、方法與操作流程。本文的英文名稱與成員名稱皆為候選，尚不是已實作的 API，也不變更現行格式、介面或行為。

## 設計方向與草稿範圍

本輪討論已確認的方向：

- 以 TypeScript 作為重構的主要語言，共用核心保留在瀏覽器與 Node.js 執行的能力。
- 建立有明確身分、資料與操作介面的物件。接受為了清楚分工增加程式碼與檔案。
- 節點表集中描述適合資料化的計算規則；特殊節點與宿主能力有明確的實作入口。
- 先確認名稱與責任，再展開完整方法簽章、事件、序列化格式及錯誤清單。

以下物件的切分是**本稿建議**。Electron 是桌面部署候選；WebGL 預覽、ISF 輸出與多宿主是規劃方向，不表示現行版本已具備，也不要求每種節點在所有目標都可用。

這裡的「物件」包含領域物件、資料記錄與提供操作的模組。具體採用 class 或其他 TypeScript 實作方式，留到下一輪；資料歸屬與操作入口則必須明確。

## 淺層責任樹

這是責任分組，不是繼承樹，也不表示上一列持有下一列。物件之間的擁有與引用關係見後面的表格。

```text
Grape
├─ 圖與連線          GraphDocument · Graph · NodeInstance · Port · Edge
├─ 定義與共用資料    NodeDefinition · NodeRegistry · SubgraphDefinition · SourceDeclaration · DataType
├─ 編輯與介面        EditorSession · GraphView · ValueEditor · WorkspaceLayout
├─ 驗證與產碼        TypeSystem · GraphCompiler · CodeGenerator · CompilationResult
├─ 保存與資源庫      DocumentStore · LibraryStore
└─ 宿主與預覽        HostConnection · ExecutionTarget · TargetBinding · PreviewSession
```

## 圖與連線

以下資料名稱只說明歸屬，不是完整欄位表。對外讀取狀態與修改狀態的入口分開；介面不能直接改集合而跳過圖的規則。

| 候選物件與命名理由 | 擁有的資料 | 提供的功能與邊界 |
| --- | --- | --- |
| **GraphDocument 圖文件**：Document 表示完整可保存單位 | 文件身分、格式版本、Stage 與根圖的對應、文件內共用定義、隨圖保存的編輯資訊 | 管理圖與文件內定義的生命週期、查找引用。文件與磁碟路徑、TD OP 分開辨認 |
| **Graph 圖**：一份具體接線網路 | 節點與接線集合；由 GraphDocument 或 SubgraphDefinition 持有 | 加入／移除節點、建立／移除接線、查詢相鄰節點；移除節點時一併處理其接線。連線型別交由 TypeSystem 判定 |
| **NodeInstance 節點實例**：與可重複使用的節點定義區分 | 實例 ID、定義引用、設定、未接線輸入值；來源／子圖節點另持有對應引用 | 讀取與修改自身設定、取得目前接孔。外部連線由 Graph 管理；繪製與 GLSL 字串不放在實例內 |
| **Port 接孔**：沿用現有術語 | 所屬節點、穩定接孔鍵、方向、型別規則與解析狀態 | 表達可連接端點；由定義及實例設定建立或解析。陣列、矩陣與動態接孔同樣使用此概念，實際解析型別不作為另一份可任意修改的真相 |
| **Edge 接線**：沿用既有圖論用語，避免與宿主 Connection 混用 | 接線身分、來源與目的端點引用 | 表達資料流關係。端點以節點 ID 與接孔鍵引用；Wire／Link 樣式存於編輯資訊，不改變運算關係 |

**擁有關係建議**：GraphDocument 持有根圖與文件內定義；Graph 持有 NodeInstance 與 Edge；NodeInstance 提供接孔。SubgraphDefinition 持有自己的 Graph，多個呼叫實例引用同一份定義。根圖的 Stage 由文件指定；子圖可用 Stage 另有約束，不把每份子圖永久綁成單一 Stage。

動態接孔被移除時如何處理既有接線、複製節點時哪些 ID 重建，留待局部規格細修，不由此表暗中選定。

## 定義與共用資料

| 候選物件與命名理由 | 擁有的資料 | 提供的功能與邊界 |
| --- | --- | --- |
| **NodeDefinition 節點定義**：描述一種節點的能力 | 定義 ID 與版本、顯示資訊、設定描述、接孔規則、行為角色、Stage／目標需求 | 描述如何建立與理解實例。普通計算可用資料規則；特殊行為引用已登記的實作，不要求全部寫成一張巨大規則表 |
| **NodeRegistry 節點登記庫**：Registry 強調按身分查找 | 可用定義、版本與對應行為實作 | 登記、查找與解析定義；報告缺少或不相容的版本。新增選單的用途分類不決定產碼方式 |
| **SubgraphDefinition 子圖定義**：保留 Subgraph 用語 | 子圖 ID、名稱、介面、內部 Graph 與來源資訊 | 提供多個實例引用及編輯介面。保留文件內共用副本與資源庫來源的區別；編輯文件內副本不回寫內建庫 |
| **SourceDeclaration 來源宣告**：與畫布上的來源引用區分 | 來源 ID、種類、型別、名稱、宣告值或初始化預設 | 描述 Uniform、常量、Sampler 等共用來源；引用節點只保存來源引用。TD 執行中的目前值由宿主狀態回報，與文件預設值分開 |
| **DataType 資料型別**：與節點種類及 UI 控制種類區分 | 純量、向量、矩陣、陣列、結構、資源的型別描述；具名型別有身分與定義來源 | 描述值的形狀及身分，供 TypeSystem 使用。認得某型別不代表每個運算或目標都支援它 |

**特殊行為的入口建議**：NodeRegistry 登記定義及其行為實作；GraphCompiler 從該入口取得節點的計算、來源需求或效果描述。共用型別判定仍由 TypeSystem 負責，目標語法仍由 CodeGenerator 負責。行為介面的名稱與方法簽章下一輪再定。

現行終端節點規則需要保留：Discard、Depth Output 與 TDAlphaTest 即使沒有輸出接孔，也能成為依賴追溯的根。放置中的子圖實例會帶入其終端效果，僅保存但未放置的子圖定義不會。不能以輸出接孔數或家族顏色判斷這些行為。

## 編輯與介面

| 候選物件 | 擁有的資料 | 提供的功能與邊界 |
| --- | --- | --- |
| **EditorSession 編輯工作階段** | 目前文件與圖的引用、選取、未完成手勢、編輯歷史 | 將一次操作組成可 Undo 的修改，協調 Graph／NodeInstance 的操作，通知視圖更新。關閉介面不等於刪除圖文件 |
| **GraphView 圖視圖** | 畫布容器、座標換算、繪製與互動狀態 | 顯示節點、接線與註記，將手勢交給 EditorSession。無介面程式也能透過相同模型完成建圖 |
| **ValueEditor 值編輯器** | 綁定的資料位置、顯示格式、編輯草稿、滑桿／天梯等互動狀態 | 在畫布與 Parameter 面板共用值編輯能力；讀取同一份權威值，提交走相同修改入口。拖曳範圍與資料合法範圍分開描述 |
| **WorkspaceLayout 工作區配置** | 停駐與浮動面板、大小、收合狀態、版面預設 | 讀取及套用版面配置。保存到使用者偏好，與 Shader 圖的運算資料分開 |

**值的歸屬建議**：節點設定及未接線值由 NodeInstance 持有；共用來源資料由 SourceDeclaration 持有；宿主目前值由宿主連線狀態提供。ValueEditor 只持有編輯中的草稿，提交成功後重新讀取權威值。先不把這些不同生命週期的值全部包成一種通用 Value 物件。

節點位置、收合、註記、群組與 Wire／Link 樣式，建議隨圖文件保存於獨立的編輯資訊中。選取與未完成拖線屬於 Session。視角位置及跨次啟動的工作恢復範圍仍待確認。

## 驗證與產碼

| 候選物件／模組 | 擁有或接收的資料 | 提供的功能與邊界 |
| --- | --- | --- |
| **TypeSystem 型別系統** | DataType、定義中的型別約束、圖的接線關係 | 解析接孔型別、判定相容性、明確列出需要的轉換。編輯時檢查與產碼前檢查共用此規則 |
| **GraphCompiler 圖編譯器** | 文件快照、節點定義、產碼目標需求 | 驗證結構、解析型別、展開子圖、收集終端依賴，建立待產碼的計算描述，再協調 CodeGenerator。產生診斷，不直接修改宿主 |
| **CodeGenerator 產碼器** | 計算描述、產碼目標及其可用功能 | 處理宣告、運算與效果的目標語法。TD、WebGL、ISF 由目標實作負責差異；缺少能力時回報限制 |
| **CompilationResult 編譯結果** | 成功狀態、診斷；成功時含各 Stage 程式、綁定需求、來源對照與文件版本識別 | 明確描述本次產出的結果，讓介面、預覽與宿主使用。不把「成功產生 GLSL」當作「宿主 GPU 已編譯成功」 |

中間計算描述先保留為 GraphCompiler 與 CodeGenerator 的交接概念，不在第一版設計完整 IR 指令集。診斷需能定位到圖、節點或接孔；子圖內錯誤應能追溯到呼叫實例。

產碼不以目前 UI 選取、DOM 順序或節點位置決定語意。畫布操作與宿主回應也不能在產碼途中改動它正在讀取的文件快照。

## 保存與資源庫

| 候選模組 | 管理的內容 | 提供的功能與邊界 |
| --- | --- | --- |
| **DocumentStore 文件儲存介面** | 文件資料、儲存位置與寫入結果 | 載入、保存、匯入、匯出及回報失敗。瀏覽器儲存與桌面檔案可有不同實作；保存不自動套用到 TD |
| **LibraryStore 資源庫介面** | 內建、個人或其他來源的子圖／範本條目與來源資訊 | 列出、讀取、匯入文件；可寫資源庫另提供發布或更新。匯入的共用副本與資源庫原件分開辨認 |

建議保存可序列化的資料記錄，載入時經格式驗證再建立工作物件；class 方法、DOM、連線與快取不直接寫入圖檔。序列化格式、素材封裝、升級與備份政策留到後續，不因選用 TypeScript 就視為完成。

## 宿主與預覽

| 候選物件 | 擁有的資料 | 提供的功能與邊界 |
| --- | --- | --- |
| **HostConnection 宿主連線** | 宿主端點、身分、連線狀態、回報能力與實例清單 | 連接、斷開、列出可用目標，傳送套用與參數更新請求，接收結果。協定與配對方式尚未選定 |
| **ExecutionTarget 執行目標** | 特定實例的識別、宿主關係、定位資訊與可用能力 | 指認實際執行位置，例如某個 TD 程序中的某個 OP。IP 或 OP 路徑不足以單獨承擔永久身分 |
| **TargetBinding 目標綁定** | 文件與執行目標的對應、來源對照、目標參數值與最後成功套用紀錄 | 管理這張圖如何套用到這個實例，協調連線送出更新並記錄結果。同圖對多目標時各自持有對應資料 |
| **PreviewSession 預覽工作階段** | 預覽模式、使用的編譯結果或執行目標、預覽設定與狀態 | 協調未來的本機 WebGL 預覽或宿主 Viewer。預覽場景設定與使用者的 Shader 圖分開管理 |

**三種目標分開命名**：產碼目標（Code Target）決定輸出環境；HostConnection 表示與哪個宿主端點連線；ExecutionTarget 指定該宿主中的實際執行實例。產碼目標的型別或物件名稱下一輪再定，先避免全部縮寫成一個含義不明的 target。

**綁定分工建議**：CompilationResult 描述程式需要哪些來源；TargetBinding 記錄這些來源在某個目標如何取得；宿主端執行原生配置、GPU 編譯及結果回報。編輯器、儲存或連線失敗，各有自己的狀態；失敗的新版不能覆蓋最後成功套用的程式與綁定。

即時參數的控制權、重連後是否自動套用，以及同一實例被多個編輯器操作的衝突處理，仍待討論。本文的 PreviewSession 也不等同先前暫緩的 Preview 快捷節點，沒有順帶決定其實作。

## 第一輪命名規約

以下是供討論的共通規約，不批次更名現行程式或圖檔。

| 名稱 | 建議意義 |
| --- | --- |
| id | 穩定識別；顯示名稱改變時仍能引用原物件。範圍與格式另外定義 |
| definitionId／sourceId／subgraphId | 指向哪一種物件要寫清楚；需要固定版本的引用另外攜帶版本，不只看 ID |
| key | 定義範圍內的穩定成員鍵，例如接孔鍵。翻譯或顯示順序改變不應改鍵 |
| name／label | name 用於作者可命名的實體，label 用於介面顯示／翻譯文字。兩者都不充當永久身分 |
| symbol | 確實需要對外指定的 Shader 符號；遵循目標語言規則。一般節點顯示名稱不直接拿來當 GLSL 變數名 |
| settings／inputValues | 前者是操作配置，後者是未接線輸入值；例如 Voronoi 模式與未接線 Scale 值分開表達 |
| value／defaultValue／currentValue | 使用時標明歸屬。文件的初始化值、輸入本地值與宿主目前值不可互相默默覆蓋 |
| 方法名稱 | 動詞說明操作；例如 Graph.connect、NodeInstance.setSetting。名稱仍為示例，本版不定參數與回傳簽章 |

對外屬性用於查詢狀態；會改變圖的操作要有明確方法與驗證入口。衍生值應標明來源，例如「解析後的接孔型別」由 TypeSystem 計算，不能又被 UI 當作獨立設定保存。

## 用一條流程檢查分工

本版只走責任，不展開 API 簽章：

1. DocumentStore 載入資料並驗證格式，建立 GraphDocument；EditorSession 開始編輯其中一份 Graph。
2. 加入節點時，NodeRegistry 解析定義，Graph 建立 NodeInstance，依定義與設定提供 Port。
3. 拖線時，GraphView 提交端點；EditorSession 組成一次操作，Graph 使用 TypeSystem 檢查並建立 Edge，歷史記錄與視圖一起更新。
4. 修改數值時，畫布與 Parameter 面板的 ValueEditor 都提交到同一個資料擁有者；一次連續拖曳如何合成 Undo 留到下一輪。
5. GraphCompiler 讀取文件快照並協調 CodeGenerator，回傳 CompilationResult。
6. 使用者可分別保存文件、交給 PreviewSession 預覽，或透過 TargetBinding 與 HostConnection 套用到 ExecutionTarget。介面分別呈現保存、產碼與套用結果。

第一輪要確認的是：物件名稱是否能表達意義、資料是否只有明確的擁有者、功能是否有直接入口，以及是否有任何模組負責過多事情。這些確認後，再優先展開 Graph、NodeInstance、Port、Edge 與 TypeSystem 的局部規格。
