## 接線：先區分四件事

1. Auto 推導：從合法簽名中選擇運算型別。
2. 接線自動轉換：不放 Convert，產碼在輸入處加入必要 constructor。
3. Convert：圖上明確表示轉換；來源型別推導與目的型別選擇是兩個設定。
4. 自動插入 Convert：新增、接好一個節點的快捷操作。

現行接線轉換表允許數值家族 float／int／uint 同分量互轉，以及數值純量轉數值向量；同家族純量展開包含 bool → bvecN。數值與 bool 不跨家族自動接線。向量組拆功能另外要求吻合的接孔型別。這是現況，不表示使用者已批准它作為最終統一策略。

Ceil 接 int 時使用浮點簽名並轉換輸入；If 的 Condition 固定 bool，Auto 用於兩個分支與結果。差別不是 If 漏做一份 Ceil 的功能，而是簽名與接線規則共同作用。Grape 的自動接線也不等同 GLSL 語言的隱式轉換。

### 推薦的下一步

| 項目 | 推薦 | 必須先明示的影響 |
| --- | --- | --- |
| 同家族純量展開 | 維持統一規則與接孔提示 | 複製到每個分量，不補零 |
| 數值家族互轉 | 先列完整來源→目的表，再决定保留哪些自動轉換 | 小數捨棄、符號與可表示範圍的語義 |
| 數值↔bool | 預設維持明確 Convert；是否允許自動接線另決 | 零／非零判斷，不等於一般大小比較 |
| Convert 來源 | 建議新增 Auto，依接線讀取實際來源；保留明確指定來源 | 固定來源可刻意表達中間轉換，不能默默刪除此能力 |
| Convert 目的 | 明確選擇 | Auto 來源不能同時讓目的隨線漂移 |
| 自動插入 Convert | 有需要時作明確快捷命令 | 不因拖一條線就無提示增加節點或改变圖意圖 |
| 向量大小改變 | 由 Combine／Swizzle 等表達；若擴充 Convert 需定義補值／選取 | 不把任意截短或擴張稱為 splat |

目前 Convert 的 fromType 與 toType 固定。int 接入預設 float→int 的 Convert 可生成 int(float(x))；這是兩次轉換，不是無條件等同 int(x)。來源 Auto 的設計應直接使用實際來源，並用產碼／數值案例驗證是否移除非預期中間轉換。此次入口／Compare 整理尚未改動 Convert。

參考：[GLSL 4.60 型別轉換](https://registry.khronos.org/OpenGL/specs/gl/GLSLangSpec.4.60.html#implicit-conversions)、[建構式](https://registry.khronos.org/OpenGL/specs/gl/GLSLangSpec.4.60.html#constructors)。

## TD：讀取、編輯與持續執行分開

2026-09-18 的 Uniform 專題已另作[連續編輯與按需同步評估](UNIFORM_LIVE_EDITING.md)，補入瀏覽器閃動重現、數值手勢與原生 Binding 的適用界線。下列背景調查保留，不代表該重構已實作。

對 f737912 的原始碼排查發現：

- 來源輪詢會走整圖 Python 驗證／產碼；不是每次都等同 GPU 重新編譯。
- native row 查找在每個來源重掃，history 又讀一遍；來源數與原生列數同增時，該查找部分可呈平方增長。
- 自訂參數快照可建立持續存在的 Parameter Execute DAT，監看 Grape 參數的值／模式。
- Bind 回呼為既有控制關聯保存最後值並處理控制改名／消失；關掉網頁不會自動移除它。它不是大整數精度回退器。
- 多個 Editor 各自輪詢；自訂參數輪詢尚未依該面板顯示狀態縮小範圍。

以上是程式碼中的路徑與複雜度，不是實測耗時，也沒有證明造成先前 TD 掛起。額外整數精度限制已獨立撤銷，這些背景機制尚未因此調整。

### 建議分批處理

1. **保持行為的讀取優化**：單次請求共用來源索引與快照，避免重複掃描；測試輸出資料、衝突判斷、Undo 及原生外部變更相同。
2. **切分讀值與結構同步**：單純讀目前值不重新驗證整圖；結構變更有明確失效機制，再決定是否編譯／建立歷史。不能只加快取而漏掉原生變更。
3. **按介面需求輪詢**：只為正在使用的資料安排請求，離開／隱藏時停止，恢復後立即取最新值；保留編輯衝突與資料同步能力。
4. **Binding 恢復另作決策**：先選擇是否要持續保存最後值、刪除控制時要發生什麼，再決定必要回呼的範圍與生命週期。不可在效能整理中偷偷刪除這項既有行為。

前三批也要先寫出前後契約與驗證範圍；尤其 GET 目前可能同步結構與改 revision，不能假設它本來完全唯讀。避免每個新增功能再掛一個常駐 Python 檢查。

本機開發橋接有自己的檔案輪詢，是臨時開發工具；正式 TOE 保存會排除它。Native viewer、下游 cooking 與 Remote Panel 串流各有生命週期，不能混作 Editor 輪詢。
