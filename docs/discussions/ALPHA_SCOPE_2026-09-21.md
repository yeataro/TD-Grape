## Help 的共同完成條件

2026-09-21 使用者補充：所有內建來源／內建函式都要能在 Help 查到對應說明，並連到官方文件的相應章節。

- 依實際來源或函式提供基本用途、值／输入輸出的意義，以及必要的 TOP／MAT／Stage 限制；來源分類的簡短 hint 不能當成完整 Help 已完成。
- 文件連結定位到對應函式頁或章節，實作時查證網址與錨點，不只放官方首頁或整份指南。GLSL 對應標準官方文件，TD 對應 Derivative 文件。
- 共用節點實作不共用成一段籠統說明：例如 Built-in Source 選 `sTDNoiseMap` 時，Help 應解釋該來源；換選其他來源後，說明與文件連結同步改變。
- 既有入口也納入檢查；不能把「節點已存在」當成 Help 已驗收。函式 overload／動態家族可以共用適用的說明，但要能辨識目前操作及相關限制。
- 使用者後續釐清：主要缺口是使用者看不到具體來源的說明，不要求每個來源各有獨立 Help 頁。相關來源可共用同一章節或分類說明，只要能找到當前項目的用途與對應文件；陣列直接取值入口則是操作便利性，不自動列為能力缺口。

## Built-in Source 現況查核（不是新的互動定案）

使用者提供的截圖為 Parameter 中的 `Built-in Source`，「引用來源」目前選 `sTDNoiseMap`。查核 0.8.163：

- 多個內建來源共用 `builtin_source` 定義，各顆圖節點在 `params.source` 保存選中的來源。來源面板的具體項目會建立已預選該來源的引用節點，不是所有引用共用同一個選取值。
- Parameter 的「引用來源」選單列出當前 Target／Stage 可用的來源；不只限原先的 Shader 資訊或輸出資訊分類。切換是修改此節點的來源與型別，由既有型別變更流程處理；不是執行 Shader 時動態切換的 Switch。
- 編譯器按選中的來源輸出對應 GLSL expression；索引輸入、輸出型別及結構欄位也由該來源定義決定。
- Help 目前依 `help.builtin_source` 顯示通用說明，沒有依 `params.source` 對應專屬內容。來源 catalog 有部分短 hint，不能據此宣稱已完成來源 Help。
- 是否讓每個具體来源在介面上固定身分、保留或限制這個切換，以及 Inspector 標題是否顯示來源名稱，尚未由使用者定案；本次只回答現況並記錄 Help 要求。

程式依據：[節點定義](../../src/library/node_catalog.json)、[來源定義](../../src/library/source_catalog.json)、[來源入口與動態接孔](../../src/editor/graph_ui.js)、[Parameter／Help](../../src/editor/inspector.js)、[產碼](../../src/core/sgrape_core.py)。

### 為何共用，而不是每個來源獨立實作

查核 Git，`builtin_source` 在 2026-09-18 的陣列／結構批次 `60f71f8` 引入；當時文件列出五種 TD 內建陣列來源。後续[來源架構紀錄](SOURCE_ARCHITECTURE_REVIEW.md)明確採「項目提供名稱、型別、初始化與適用範圍，同類行為共用方法」，並把 UI 分類／名稱與建構、型別檢查、產碼分開。

因此可由紀錄支持的主要理由是共用來源引用、型別與產碼規則，減少重複實作；沒有找到「節點表容量／效能不足，所以必須合為一顆」的依據。來源資料表本來仍逐項登記，UI 也已有各自的來源項目。

分析建議（尚未定案）：使用者看到的具名來源節點與底層共用 `builtin_source` 可以同時成立；每種來源有自己的名稱／Help，不必複製一套編譯器。Parameter 的跨來源切換是額外的 UI 能力，不是共用實作的必要條件。若之後決定固定來源身分，仍需設計舊圖呈現與更換來源方式，不能把本次詢問當成已授權移除切換。

### 後續釐清：Help 缺口與取值快捷分開

使用者澄清不是要求拆開節點，也未將陣列來源加 index 的快捷方式視為缺功能；希望先理解現有選擇的目的。可考慮按類型分組並共用章節，尚未定案。

- 現況不是所有 Built-in Source 都沒有輸入：`TDBoneMat(boneIndex)` 輸出 mat4；`uTDLights` 無輸入、輸出 TDLight 陣列；`uTDEnvLightBuffers.shCoeffs` 接 lightIndex、輸出 vec3[9]。有無資料選擇輸入，與結果是否為陣列，是兩個獨立條件。
- 共用引用／取項的設計保留宿主資料形狀：來源提供整個陣列，Array[i] 選元素，Field 取欄位。同樣的陣列操作可用於不同來源，不必為每種來源各做一套取項規則。常用的來源＋取項／欄位可以另有便利入口，但不要求所有來源都融合或都拆開。
- Help 目前按 definition 的 descriptionKey 查找，是實作方式，不是只能「一種節點共用一段文字」的產品限制。建議依選中來源的識別查基本說明及文件，搭配共用類型說明；切換來源時更新 Help。沿既有來源資料表提供內容，可避免每個來源寫專用判斷。這是待實作方案，並未修改產品。
- 分組建議以用途與操作方式為主，例如輸出資訊、Shader 資訊、Texture 資源、Camera／Light 資料；現有來源 path 可作依據。文件同章可共用連結，但不以文件章節直接決定節點型別，以免不同操作只因文件位置而被合併。
- 優先解決 Help 可取得具體說明的缺口；不以 Help 為理由先改固定／可選來源身分、重做序列化，或大量新增取值快捷節點。分組與快捷形式保留討論，待 Alpha 需求收集完成一起安排。

## 來源與運算的分類原則

使用者最新界線：有資料輸入並進行計算的歸運算；只輸入 index／layer、用來挑選 TD 已有資料的仍可歸來源。分類看輸入的用途，不能只算接孔數量。

- `TDBoneMat(index)`、`TDInstanceMat(index)`：來源；索引是選哪筆資料。
- `TDDeform(position)`、`TDInstanceColor(index, color)`：運算；有待處理的資料。
- 光照函式同時接燈光 index、位置／法線等：运算，不因有 index 改歸來源。
- `TDCheckDiscard()` 等無回傳值的宿主操作：另標示執行／輸出流程，不能因沒有輸入而當作來源。
