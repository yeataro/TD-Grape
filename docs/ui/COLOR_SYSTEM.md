# 新編輯器的顏色系統

適用：`src/editor-react/` 的所有介面。決策來源：design-interview Q43（人類 2026-10-08）。人類把細節交給 agent，以通用的設計系統原則（design tokens）自我約束；本文件就是那份約束。**尚未實作**，實作時照此執行。

## 最高原則

**只定義少數主色；其他所有顏色都由主色以 `color-mix` 或半透明疊層組出來。** 新顏色先問「能不能用現有主色的深淺組出來」，不能才考慮新增名字。

外觀數值參考舊產品（UX/UI 設計書 §5.2、§5.4 與 `current-dark-cool.tokens.partial.json` 的實測值），結構不參考舊產品（舊產品同樣的顏色寫成多個色碼、分類寫在前端依節點 key 判斷）。

## 三層名字（design tokens）

| 層 | 是什麼 | 例 | 誰可以寫色碼 |
| --- | --- | --- | --- |
| 1. 調色盤 primitive | 少數主色 | `--palette-ink`、`--palette-violet`、`--palette-green` | **只有這一層有色碼** |
| 2. 用途 semantic | 依用途命名，指向調色盤或由它組出 | `--surface-panel`、`--group-output`、`--text-title` | 只能引用第 1 層與強度常數 |
| 3. 元件 component | 元件的樣式 | `.node-title { background: … }` | **只能引用第 2 層，永遠不寫色碼** |

元件不跳過第 2 層直接用調色盤：用途名字讓「把輸出改成別的顏色」只動一處，又不影響其他也用同一主色的地方。

## 命名

- 依**用途與層級**命名，不依顏色本身：寫 `--surface-floating-raised`，不寫 `--panel-light`（換淺色主題就對不上）。
- 同一個字只有一個意思（GLOSSARY 命名對齊原則）；顏色組名與節點模組宣告的名字一致（如 `--group-logic` 對 `colorGroup: 'logic'`）。

## 深淺怎麼組出來

兩種方式，各有用途，強度都集中定義：

| 方式 | 寫法 | 用在 |
| --- | --- | --- |
| 從主色算 | `color-mix(in srgb, var(--surface-panel), black var(--shade-1))` | 某一種東西本身的底色（深的面板、淺的面板） |
| DOM 疊半透明 | `background: var(--overlay-up)`，其值如 `rgb(255 255 255 / 0.06)` | 東西裡面的層次（標題列、輸入框、hover） |

- 強度常數只有少數幾級（如 `--shade-1`、`--shade-2`、`--overlay-up`、`--overlay-down`），全專案共用，調整層次對比只改這幾個值。
- 節點標題：顏色組主色以固定透明度（如 `--title-alpha: 80%`）疊在卡片底色上，由 DOM 疊出，不預先算好色碼。
- **層級（elevation）**：浮得越高的面板在深色主題越亮（越近光源）；淺色主題可改以陰影表現。元件只說自己在哪一層（`data-level`），不決定怎麼表現。
- 文字一律白（或淺色主題的黑）加透明度分層：primary .88、title .85、value .74、secondary .72、soft .62、muted .54、faint .32（沿用舊產品實測）。

## 對比（可讀性底線）

層疊讓對比舒服，但不能低到看不清。採通用標準 WCAG：一般文字對背景至少 **4.5:1**，大字與介面元件（邊框、圖示、接孔）至少 **3:1**。新增或調整主題時以工具檢查。

## 主題

- 官方主題寫成 CSS，一個主題一檔：`dark.css`（產品預設，寫齊所有名字）、`light.css`（獨立一套，**必須寫齊調色盤**）、`td.css`（像 TD，**繼承 dark**，只寫要改的）。繼承靠 CSS 的覆蓋順序，不另寫程式。
- 回退順序：使用者微調 → 該主題 → 它繼承的主題 → 產品預設。顏色回退到錯的主題就是錯（不像翻譯回退英文還看得懂），所以獨立主題要寫齊，由自動測試在建置時把關。
- 使用者的主題：「另存」＝讀出目前生效的所有變數存成 JSON（名字與官方相同）；只存差異；屬個人偏好、存瀏覽器、可匯出（Q36；換存放位置先問人類）。
- 外觀樣式主題（圓角、陰影、間距等）與顏色主題分開，可各自切換。

## React 與 React Flow

- React 元件只用 CSS 類別與變數；換主題不需 React 重新繪製。
- React Flow 自己的 `--xy-*` 變數接到我們的用途名字（如 `--xy-edge-stroke: var(--wire)`），`colorMode` 由主題決定，不寫死。
- 少數用程式指定顏色的元件（如 MiniMap）也回傳 `var(--名字)`，不回傳色碼。

## 分層界線

- 節點模組只宣告**顏色組名字**；能從行為推出的就推（stage 出口、終點、所引用來源的種類），推不出的才宣告（Q42）。
- **核心與產碼器永遠不讀顏色或顏色組**；顏色組是只給畫面用的 tag。
- 之後要加顏色：只改顯示層（主題檔、CSS 變數、元件），核心、模組、存檔不動。

## 新增一個顏色名字的步驟

1. 先確認不能用現有主色的深淺組出來。
2. 在產品預設（dark）定義；在每個獨立主題（目前 light）定義；繼承型主題（td）視需要覆寫。
3. 跑主題完整性測試（獨立主題寫齊、元件 CSS 不含色碼）。
4. 在本文件對應段落補一行說明它的用途。

## 禁止

- 元件 CSS 或 TSX 裡出現色碼（`#xxxxxx`、`rgb(…)` 固定值）——強度常數與調色盤除外。
- 以「深／淺」「亮／暗」命名用途。
- 為了相近的顏色新增色碼而不是用深淺組合。
- 核心、節點模組、存檔讀取或保存顏色。
