# Workspace layout and column creator

The editor retains left sidebar, central graph and right sidebar. Panel titles can move across sidebars. Drop on a group's upper/lower edge to stack it, or its body to combine tabs. Drop on a tab strip to insert at the shown vertical marker, including reordering within the same group. The top 3px of a strip remain a stacking target. Overflowing strips scroll near their edges. Escape or releasing outside a target cancels a move.

Panel headings select and expand their panel in both single-panel and tabbed groups. Repeated clicks never collapse an open panel; the separate right-hand chevron controls collapse. Keyboard activation follows the same rule, and title dragging still moves panels.

The compact Layout menu offers panel visibility, default/named presets, Save layout and Manage layouts. Management supports group placement, tab order, named preset save/apply/update/rename/delete and JSON transfer. It remains usable by keyboard and touch. User-selected groups and preset names stay independent of product defaults.

There are six panels: Add Node, Parameter, Inputs, Custom Parameters, Preview and Help. Hiding a panel retains its group and relative position; revealing it makes its group and sidebar available again. Defaults restore all panels. Layout state is local to each browser, independent of Shader JSON, undo history or compilation.

`grapeWorkspaceV1` holds groups, active tabs, collapse state, widths, desktop sidebar visibility and an optional `hidden` panel list. `grapeWorkspacePresetsV1` holds named configurations. Every panel remains assigned exactly once, even when hidden; malformed imports are rejected before application. Older four/five-panel layouts gain the new tool panels and older layouts without `hidden` remain valid.

Panel tabs use cool neutral UI colors. Active tabs share the content background and use stronger text; inactive tabs are darker. There is no selection underline or reserved underline height. Tabs and selected-node identity headers are 32px high. Category colors apply only to the selected node identity. Collapse controls use a 14px stroke chevron and localized accessible names. Left/right sidebar toggles stay at opposite ends of the location row. All three location-row visibility buttons have transparent backgrounds and borders, retaining hover color and keyboard focus outlines.

The header is visible by default and can be folded with the dedicated icon immediately left of Layout. The project/path can use the remaining location-row width without reserving an empty center column. The preference is local to this browser (`sgrapeHeaderVisible`); the footer always remains visible. The desktop header is 52px high. The 28px logo and 20px TD-Grape name form a group with an 8px gap; the small `tagline · version · About` text follows with 20px of separation. Metadata uses 11px text with restrained letter spacing. The brand stays on one line when space permits; at very narrow effective widths its metadata can wrap within the text group. The name and metadata form a separate text group sharing an alphabetic baseline, while the logo is centered beside that group. This keeps smaller text aligned with the name without moving the name above the logo. A half-pixel upward optical adjustment compensates for the header logo artwork's asymmetric SVG padding; the shared logo asset is unchanged. At widths up to 600px the tagline is omitted while the version and English About remain. At widths up to 480px the complete brand takes the first header row and actions wrap below it, without shrinking text or icons. At widths from 481px through 980px, the brand stays left and Apply Shader right, while Language, Import, Export and Save TD project occupy a right-aligned second header row. Header buttons and selects are consistently 32px high. Narrow screens retain sidebar overlays.

The canvas toolbar combines stage controls, Subgraph breadcrumbs, Undo/Redo, Copy/Paste/Subgraph/Delete, Box select, Show Custom Names and GLSL. Thin separators distinguish command groups, which wrap as complete units. Stage is shown once; the separate Graph navigation strip is removed. On phones, icon buttons, text buttons and Pixel/Vertex controls share a height. `EDITOR_DEV_SETTINGS.floatingToolbar` defaults to false; when enabled, the toolbar overlays the canvas with a transparent, pointer-transparent outer surface. Actual controls remain interactive. Zoom and Fit sit together at the canvas lower right and consume no layout row.

The footer keeps the persistent graph-saved, Shader-applied or pending state separate from temporary operation messages. A repeated saved/applied message is displayed once; ordinary operation messages cannot hide errors. Matching successful retries clear their error. The location row and footer are each 32px high, with 3px vertical padding and 24px-high controls. The location row has 8px horizontal padding. The footer keeps its refresh icon at a 3px left inset and appearance controls at an 8px right inset. Page refresh and Reload applied graph form the left action group, followed by persistent state and transient messages; interface size and theme controls stay at the right. Long status messages truncate within the remaining space; their full text remains available in tooltips. At narrow widths, routine transient text gives way to persistent graph state. Errors take priority over the persistent badge.

A small page-refresh icon sits at the far left of the footer, followed by Reload applied graph and persistent status. Reload applied graph always opens an explicit warning explaining that it retrieves the last applied TD graph, replaces the editing content, discards unapplied changes and clears Undo/Redo. Cancel is focused initially; Escape cancels. Unfinished field drafts and writes in progress block the action. A queued automatic apply pauses while the warning is open and resumes after cancellation; only the confirmed action fetches the replacement graph. Failed reads retain the current graph and history. The footer remains a single row at every width; long status messages truncate visually and retain their full text in the tooltip. The location row also stays on one line, with project and path text truncating as needed. Page refresh reloads the complete editor page, independently of Preview reconnect and the existing applied-graph reload action. Unfinished numeric/text fields and open dialog drafts block refresh until completed or canceled. In-flight writes also block refresh. If the graph is unsaved, the action verifies a tab-local session draft before confirming reload, then uses the existing explicit draft-review recovery after reconnecting; storage failure leaves the page open.

The footer’s right-hand shortcuts provide interface size, appearance and browser fullscreen. Standard size and Dark appearance are the defaults. Aa opens a compact size popover with Standard/Comfortable presets; the moon/sun button opens the matching Dark/Light appearance popover. Both have presets on the first row, then a minus button, thin range track with a round thumb, and plus button. The native popovers dismiss one another when opening the other control. Both theme presets retain their original palette at the center. Dark and Light retain independent adjustments when switching, including reselecting the active preset. Right-clicking or double-clicking the range resets only the active mode to the center. The range responds immediately to pointer or keyboard input; the appearance minus/plus buttons move it in ten-point increments. Escape closes it and returns focus to the opener; clicking outside uses native popover dismissal. Accessible names and localized value text describe the current mode and relative adjustment. The size range is 75–125%, centered at 100%, with one-percent keyboard/drag increments and five-point minus/plus buttons. Standard and Comfortable share one scale adjustment; changing the preset keeps the same percentage. Right-click or double-click resets the shared value to 100%. The two dedication lines in About are centered.

Comfortable enlarges editor chrome: the desktop header is 68px high, the location row and footer 42px, and toolbar controls and their labels are larger. At 100%, graph nodes, graph zoom, panel tabs and panel content retain their existing dimensions. The additional whole-page scale uses root CSS zoom, so rendered nodes and panel content scale together while stored graph scale, positions and authored sizes stay unchanged. Viewport-length CSS values are compensated by the UI factor; pointer positions and drag distances are converted to local CSS/graph units. Native browser zoom remains independently available. Light appearance uses neutral light surfaces throughout the workspace, including a soft gray canvas, light nodes and pastel category headers. Typed ports and wires retain their hue distinctions with deeper colors for contrast on the light canvas; RGBA component hints, selections, errors and numeric editors follow the same palette. Shader preview pixels are not recolored, and source code retains its separate syntax palette. The preference change does not apply a Shader, add Undo history or rebuild node editors.

`localStorage.sgrapeAppearanceV1` stores `{size, theme, tones: {dark, light}, scale}` on the current device, for this browser profile and Editor address. Each tone is a relative integer from -100 to 100, with 0 preserving the selected preset exactly. Existing `{size, theme}` settings load both tones at 0; the previous single `tone` migrates to its active theme only. Invalid tone values recover to 0 and finite out-of-range numbers are clamped. Missing or invalid scale values default to 100%; finite values are rounded and clamped to 75–125%. If the scalar scale is absent, the former per-preset scales map migrates the currently selected preset’s value into the shared scalar; a present but invalid scalar recovers to 100%. The preference is independent of Shader JSON and the TD project. If local storage cannot be written, the controls still work for the current page.

Tone is calculated from immutable base-theme color tokens and applied through root CSS variables, without a page filter or DOM recoloring pass. The main UI surfaces, text, fields, node palettes and graph background follow a restrained tonal curve. For weighted RGB brightness L and slider s in [-1, 1], the target is `pow(L, exp(-strength*s))`. The adjustment strength is 1.5 times the previous range. Brightening uses strength 0.48, blended with the original by `smoothstep(0, protection, L)`; protection is 0.35 in Dark and 0.10 in Light. These are shadow-protection thresholds, not fixed middle-gray anchors. Darkening uses strength 0.60 in Dark and 0.825 in Light without the protection blend. The shared proportion toward white or black retains channel ordering and alpha. Returning to 0 removes all tone overrides. Theme and tone changes remain immediate. A 0.5-second CSS color-transition experiment was removed after a 200-node browser probe showed substantial animation overhead; the user explicitly preferred omitting damping over added cost or complexity. There is no animation loop, delayed color state, layout transition or preview filter. Preview image pixels, authored color swatches and GLSL syntax colors remain independent. Tone dragging does not rerender nodes or wires, change layout/graph zoom, add Undo steps or send API writes. Moving focus away from a numeric field still follows its ordinary blur-commit behavior; appearance updates do not add an extra graph edit.

The floating Add Node browser uses category, result and detail columns. Authored categories currently reach two levels; additional depth adds fixed 170px columns, with horizontal scrolling on small screens. Search crosses category paths; source/type and connection compatibility are independent filters. Double-click and wire-to-blank creation place the browser horizontally centered on the pointer, with its header midpoint at the pointer height; viewport bounds take precedence near edges. Dragging the header repositions only the browser, retaining the original graph insertion point and optional wire. Search/category updates retain the dragged location; reopening starts from the new invocation point.

The canvas stage/count/help text sits at the lower left. At the lower right, the zoom percentage opens an upward preset menu with 25, 50, 75, 100, 125, 150 and 170 percent, retaining the existing 25–170 percent limits. Selecting a preset zooms about the canvas center without editing the graph or adding history. The controls handle their own pointer events without starting a canvas gesture.

The location row shows the current TOE filename and component path. Export offers full-graph JSON download, TD-folder JSON and PNG with embedded graph data. General node names have a canvas-wide Show Custom Names display preference (`sgrapeCustomNamesV1`); changing it does not mutate the graph, history or Shader. Parameter identity stays original node name on the left and custom name on the right in either mode. Source references always show their declaration name. See [this round’s decisions](../discussions/NODE_WORKFLOW_ROUND.md).

Numeric fields use decimal drag increments: 0.01 by default, 0.001 with Shift, 0.1 with Ctrl and 0.0001 with both. Whole viewport-pixel steps avoid fractional pointer noise; reversing direction restores the same value at the same position. Manual numeric entry retains finer precision, and dragging adds increments relative to that value. Integer inputs keep whole-number steps and unsigned minimum bounds. The subdued numeric fill uses ranges 0–1, 0–10, 0–100 and subsequent powers of ten according to magnitude. Negative ranges run from -1, -10 or -100 up to 0; the bright fill remains on the left and the dark remainder on the right. Exact negative lower bounds show zero fill, exact positive upper bounds show full fill, and zero uses the positive range. This is display mapping only; values and drag increments stay unchanged. Integer-specific display ranges remain a follow-up design note. Plain right-click opens compact numeric presets: 0, 1, 0.5, -0.5 and -1 for floating fields, 0, 1 and -1 for integer fields, filtered to the field’s minimum/maximum (unsigned fields omit negatives). Selection uses the existing commit/Undo path. Escape, Tab and the first click outside dismiss the preset menu and return to the field without committing a draft; subsequent field navigation retains normal commit behavior. Read-only fields cannot open presets, and entry removal or a graph/stage change invalidates the menu. Middle-button and existing Value Ladder behavior/layout remain unchanged.

These tests use the portable editor-state fixture. Windows Chromium is verified; physical touch devices and macOS remain unverified.

Live delivery uses `tools/dev/jobs/refresh_sources.py`, preserving Shader state and the connection session. Saving the formal development TOE is a separate step through `save_source_project.py`.


### 全螢幕與專注編輯

Footer 的最右側按鈕呼叫瀏覽器原生 Fullscreen API，以 `fullscreenchange` 同步實際狀態；不支援時停用按鈕，請求被拒絕時保留目前介面。網路圖「置中」右側的「專注編輯」只隱藏周圍介面，讓現有網路圖與工具列填滿視窗，不進出瀏覽器全螢幕；按「還原介面」回到原先配置。兩種模式可以獨立使用。進入專注編輯時，網路圖右下角會出現全螢幕按鈕，便於在專注模式直接切換；一般圖面不顯示這個快捷。

專注編輯不重建或搬動節點與面板 DOM，也不改動 Layout、圖、Undo 或縮放／平移。Esc 優先取消輸入、接線、選單或對話框，再還原專注模式；瀏覽器全螢幕的 Esc 由瀏覽器處理。視窗大小與全螢幕切換只重畫連線，保留目前視點，需要重新取景時使用「置中」。專注模式是本次頁面的臨時狀態，不寫入儲存的 Layout。
