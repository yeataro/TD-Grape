# Workspace layout and column creator

The editor retains left sidebar, central graph and right sidebar. Drag a panel title to a sidebar group's upper/lower edge to stack it, or its center to combine tabs. A tab can be dragged out again. Empty sidebars accept drops. Escape or releasing outside a target cancels a move. A Layout dialog provides equivalent controls for keyboard/touch use, alongside the existing width and height dividers.

Layout contains the browser, node Parameter, Preview and Help panels. Named configurations can be saved, applied, updated and deleted. Restore default always recovers the original arrangement. The current configuration can be exported/imported as JSON to transfer between browsers or submit a proposed product preset. Preset names and future default groups are deliberately not fixed. Shader-specific Uniform/Attributes/custom-parameter panels have not been implemented by this work.

Storage is local to each browser: `grapeWorkspaceV1` holds current groups, active tabs, collapse state, width preferences and desktop sidebar visibility. `grapeWorkspacePresetsV1` holds named configurations. Each panel must occur exactly once; imports are validated before application. Layout is independent of Shader JSON, semantic history and compilation. Narrow screens preserve sidebar overlays and offer the Layout dialog as an alternative to cross-sidebar dragging. The two sidebar visibility icons sit at opposite ends of the component/status row.

The floating Add Node has category columns, a results column and a details column. Default authored categories currently reach two levels, but the data model permits additional levels. Each category level has a fixed 170px column; adding depth increases total width. A viewport constraint introduces horizontal scrolling instead of squeezing columns. Search spans all category paths; source/type and wire compatibility remain independent filters. Pointer hover and keyboard selection show details; click or Enter inserts with the existing connection planner. Canvas title Label/provenance layout remains undecided.

The location row displays the current TOE filename from TouchDesigner's read-only `project.name` through the existing shader-list response; its component path remains beside it. See [Derivative Project Class](https://docs.derivative.ca/Project_Class). The browser refreshes the filename periodically, without changing project state. Export adds a direct full-graph JSON download while retaining TD-folder export and PNG-with-data export.

Validation: 7 focused workflow checks, 6 regression checks and 9 existing node identity checks. Coverage includes real pointer docking, tab selection, reload persistence, presets, JSON transfers, duplicate-panel rejection, pane sizing/collapse, moved Parameter editing, forward/reverse connection creation and mobile horizontal scrolling. These use Chromium; physical iPad/Safari remains unverified.

Live delivery uses canonical source via the existing legacy bridge. UI DATs are refreshed without saving or restarting the project. The shader-list filename addition is applied to its existing function object so the running server's module, queues and port survive. The legacy embedded runtime source is not replaced; the canonical runtime source contains the addition for the pending bootstrap/TOE migration. Shader state and GLSL preservation are checked during the refresh.

Panel headings use the existing UI’s cool neutral palette, not achromatic gray. Active tabs share `--panel-content-bg` with their pane body, so the selected tab and content form one surface. Inactive tabs use the existing darker canvas tone and muted text. Multi-tab groups additionally mark the active tab with semibold text and a thin neutral underline; single-pane and collapsed headings have no selection underline. Hover never adopts the selected-tab treatment. They do not use category colors or a permanent purple selection stripe. Category color remains on the selected node identity inside the Parameter pane. Library source-tab CSS is scoped so it cannot recolor workspace tabs moved into the left sidebar.

Collapse controls use a centered 14px stroke SVG chevron with the existing full-height hit area: down when expanded and right when collapsed. The button keeps localized expand/collapse names and a keyboard focus outline.
