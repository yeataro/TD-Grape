# Workspace layout and column creator

The editor retains left sidebar, central graph and right sidebar. Panel titles can move across sidebars. Drop on a group's upper/lower edge to stack it, or its body to combine tabs. Drop on a tab strip to insert at the shown vertical marker, including reordering within the same group. The top 3px of a strip remain a stacking target. Overflowing strips scroll near their edges. Escape or releasing outside a target cancels a move.

Panel headings select and expand their panel in both single-panel and tabbed groups. Repeated clicks never collapse an open panel; the separate right-hand chevron controls collapse. Keyboard activation follows the same rule, and title dragging still moves panels.

The compact Layout menu offers panel visibility, default/named presets, Save layout and Manage layouts. Management supports group placement, tab order, named preset save/apply/update/rename/delete and JSON transfer. It remains usable by keyboard and touch. User-selected groups and preset names stay independent of product defaults.

There are six panels: Add Node, Parameter, Inputs, Custom Parameters, Preview and Help. Hiding a panel retains its group and relative position; revealing it makes its group and sidebar available again. Defaults restore all panels. Layout state is local to each browser, independent of Shader JSON, undo history or compilation.

`grapeWorkspaceV1` holds groups, active tabs, collapse state, widths, desktop sidebar visibility and an optional `hidden` panel list. `grapeWorkspacePresetsV1` holds named configurations. Every panel remains assigned exactly once, even when hidden; malformed imports are rejected before application. Older four/five-panel layouts gain the new tool panels and older layouts without `hidden` remain valid.

Panel tabs use cool neutral UI colors. Active tabs share the content background and use stronger text; inactive tabs are darker. There is no selection underline or reserved underline height. Tabs and selected-node identity headers are 32px high. Category colors apply only to the selected node identity. Collapse controls use a 14px stroke chevron and localized accessible names. Left/right sidebar toggles stay at opposite ends of the location row. All three location-row visibility buttons have transparent backgrounds and borders, retaining hover color and keyboard focus outlines.

The header is visible by default and can be folded with the dedicated icon immediately left of Layout. The project/path can use the remaining location-row width without reserving an empty center column. The preference is local to this browser (`sgrapeHeaderVisible`); the footer always remains visible. The desktop header is 52px high. The 28px logo and 20px TD-Grape name form a group with an 8px gap; the small `tagline · version · About` text follows with 20px of separation. Metadata uses 11px text with restrained letter spacing. The brand stays on one line. The name and metadata form a separate text group sharing an alphabetic baseline, while the logo is centered beside that group. This keeps smaller text aligned with the name without moving the name above the logo. A half-pixel upward optical adjustment compensates for the header logo artwork's asymmetric SVG padding; the shared logo asset is unchanged. At widths up to 600px the tagline is omitted while the version and English About remain. At widths up to 480px the complete brand takes the first header row and actions wrap below it, without shrinking text or icons. At widths from 481px through 980px, the brand stays left and Apply Shader right, while Language, Import, Export and Save TD project occupy a right-aligned second header row. Header buttons and selects are consistently 32px high. Narrow screens retain sidebar overlays.

The canvas toolbar combines stage controls, Subgraph breadcrumbs, Undo/Redo, Copy/Paste/Subgraph/Delete, Box select, Custom Names and GLSL. Thin separators distinguish command groups, which wrap as complete units. Stage is shown once; the separate Graph navigation strip is removed. On phones, icon buttons, text buttons and Pixel/Vertex controls share a height. `EDITOR_DEV_SETTINGS.floatingToolbar` defaults to false; when enabled, the toolbar overlays the canvas with a transparent, pointer-transparent outer surface. Actual controls remain interactive. Zoom and Fit sit together at the canvas lower right and consume no layout row.

The footer keeps the persistent graph-saved, Shader-applied or pending state separate from temporary operation messages. A repeated saved/applied message is displayed once; ordinary operation messages cannot hide errors. Matching successful retries clear their error. The location row and footer are each 32px high, with 3px vertical padding and 24px-high controls. The location row has 8px horizontal padding. The footer keeps its refresh icon at a 3px left inset and appearance controls at an 8px right inset. Page refresh and Reload applied graph form the left action group, followed by persistent state and transient messages; interface size and theme controls stay at the right. Long status messages truncate within the remaining space; their full text remains available in tooltips. At narrow widths, routine transient text gives way to persistent graph state. Errors take priority over the persistent badge.

A small page-refresh icon sits at the far left of the footer, followed by Reload applied graph and persistent status. The footer remains a single row at every width; long status messages truncate visually and retain their full text in the tooltip. The location row also stays on one line, with project and path text truncating as needed. Page refresh reloads the complete editor page, independently of Preview reconnect and the existing applied-graph reload action. Unfinished numeric/text fields and open dialog drafts block refresh until completed or canceled. In-flight writes also block refresh. If the graph is unsaved, the action verifies a tab-local session draft before confirming reload, then uses the existing explicit draft-review recovery after reconnecting; storage failure leaves the page open.

Two icon buttons at the right of the footer provide direct access to interface size and appearance. Standard size and Dark appearance are the defaults. The Aa button switches between Standard and Comfortable; the moon/sun button switches between Dark and Light. Accessible names and tooltips state both the current setting and the next action, and the selected state is exposed with `aria-pressed`. No additional panel is needed. The two dedication lines in About are centered.

Comfortable enlarges editor chrome: the desktop header is 68px high, the location row and footer 42px, and toolbar controls and their labels are larger. Graph nodes, graph zoom, panel tabs and panel content retain their existing dimensions. Light appearance uses neutral light surfaces throughout the workspace, including a soft gray canvas, light nodes and pastel category headers. Typed ports and wires retain their hue distinctions with deeper colors for contrast on the light canvas; RGBA component hints, selections, errors and numeric editors follow the same palette. Shader preview pixels are not recolored, and source code retains its separate syntax palette. The preference change does not apply a Shader, add Undo history or rebuild node editors.

`localStorage.sgrapeAppearanceV1` stores only `{size, theme}` for this browser profile and Editor origin. It is independent of Shader JSON and the TD project; another device can use different preferences. Unknown or unreadable stored values fall back to Standard/Dark. If local storage cannot be written, the controls still work for the current page.

The floating Add Node browser uses category, result and detail columns. Authored categories currently reach two levels; additional depth adds fixed 170px columns, with horizontal scrolling on small screens. Search crosses category paths; source/type and connection compatibility are independent filters.

The canvas stage/count/help text sits at the lower left. Zoom text lets pointer actions pass through; the adjacent Fit control handles its own pointer events without starting a canvas gesture.

The location row shows the current TOE filename and component path. Export offers full-graph JSON download, TD-folder JSON and PNG with embedded graph data. General node names have a graph-wide display preference (`sgrapeCustomNamesV1`); changing it does not mutate the graph, history or Shader. Source references always show their declaration name. Validation: `tests/browser/test_ui_appearance.cjs` covers both preference controls, localization and keyboard access, reload/storage recovery, unchanged graph and draft state, and all four size/theme combinations at desktop and narrow widths. `tests/browser/test_editor_chrome.cjs` covers header reopening, desktop/half-width/coarse-phone toolbar layout, persistent states, matching error recovery, unfinished field/modal drafts, in-flight writes and page-reload draft recovery. `tests/browser/test_workspace_layout.cjs` covers existing docking, presets and transfers. `tests/browser/test_ui_refinement.cjs` adds pointer insertion/reorder, hidden-panel persistence, rename, compact Parameter controls, local Subgraph copies and Chinese narrow headers. These tests use the portable editor-state fixture. Windows Chromium is verified; physical touch devices and macOS remain unverified.

Live delivery uses `tools/dev/jobs/refresh_sources.py`, preserving Shader state and the connection session. Saving the formal development TOE is a separate step through `save_source_project.py`.
