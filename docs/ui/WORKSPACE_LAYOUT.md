# Workspace layout and column creator

The editor retains left sidebar, central graph and right sidebar. Panel titles can move across sidebars. Drop on a group's upper/lower edge to stack it, or its body to combine tabs. Drop on a tab strip to insert at the shown vertical marker, including reordering within the same group. The top 3px of a strip remain a stacking target. Overflowing strips scroll near their edges. Escape or releasing outside a target cancels a move.

Panel headings select and expand their panel in both single-panel and tabbed groups. Repeated clicks never collapse an open panel; the separate right-hand chevron controls collapse. Keyboard activation follows the same rule, and title dragging still moves panels.

The compact Layout menu offers panel visibility, default/named presets, Save layout and Manage layouts. Management supports group placement, tab order, named preset save/apply/update/rename/delete and JSON transfer. It remains usable by keyboard and touch. User-selected groups and preset names stay independent of product defaults.

There are six panels: Add Node, Parameter, Inputs, Custom Parameters, Preview and Help. Hiding a panel retains its group and relative position; revealing it makes its group and sidebar available again. Defaults restore all panels. Layout state is local to each browser, independent of Shader JSON, undo history or compilation.

`grapeWorkspaceV1` holds groups, active tabs, collapse state, widths, desktop sidebar visibility and an optional `hidden` panel list. `grapeWorkspacePresetsV1` holds named configurations. Every panel remains assigned exactly once, even when hidden; malformed imports are rejected before application. Older four/five-panel layouts gain the new tool panels and older layouts without `hidden` remain valid.

Panel tabs use cool neutral UI colors. Active tabs share the content background and use stronger text; inactive tabs are darker. There is no selection underline or reserved underline height. Tabs and selected-node identity headers are 32px high. Category colors apply only to the selected node identity. Collapse controls use a 14px stroke chevron and localized accessible names. Left/right sidebar toggles stay at opposite ends of the location row. All three location-row visibility buttons have transparent backgrounds and borders, retaining hover color and keyboard focus outlines.

The header is visible by default and can be folded with the dedicated icon immediately left of Layout. The project/path can use the remaining location-row width without reserving an empty center column. The preference is local to this browser (`sgrapeHeaderVisible`); the footer always remains visible. The desktop header is 52px high. The 28px logo and 20px TD-Grape name form a group with an 8px gap; the small `tagline · version · About` text follows with 20px of separation. Metadata uses 11px text with restrained letter spacing. The brand stays on one line when space permits; at very narrow effective widths its metadata can wrap within the text group. The name and metadata form a separate text group sharing an alphabetic baseline, while the logo is centered beside that group. This keeps smaller text aligned with the name without moving the name above the logo. A half-pixel upward optical adjustment compensates for the header logo artwork's asymmetric SVG padding; the shared logo asset is unchanged. At widths up to 600px the tagline is omitted while the version and English About remain. At widths up to 480px the complete brand takes the first header row and actions wrap below it, without shrinking text or icons. At widths from 481px through 980px, the brand stays left and Apply Shader right, while Language, Import, Export and Save TD project occupy a right-aligned second header row. Header buttons and selects are consistently 32px high. Narrow screens retain sidebar overlays.

The canvas toolbar combines stage controls, Subgraph breadcrumbs, Undo/Redo, Copy/Paste/Subgraph/Delete, Box select, Show Custom Names and GLSL. Thin separators distinguish command groups, which wrap as complete units. Stage is shown once; the separate Graph navigation strip is removed. On phones, icon buttons, text buttons and Pixel/Vertex controls share a height. `EDITOR_DEV_SETTINGS.floatingToolbar` defaults to true; the toolbar overlays the canvas with a transparent, pointer-transparent outer surface. Actual controls remain interactive. An explicitly saved false preference stays docked; missing preferences and Reset defaults use floating mode. Disabled floating action/stage buttons use an opaque, darker surface with muted foreground instead of lowering the opacity of the whole button, so underlying nodes do not show through. Command groups wrap right-aligned. At an available toolbar width of 700 CSS pixels or less, the command rows come first and Stage plus the graph breadcrumb share the following row; long paths scroll within their remaining space. A container query follows the toolbar width, including narrow graph panes on wide screens, without JavaScript layout logic. Zoom and Fit sit together at the canvas lower right and consume no layout row. Plain H invokes the same Fit action while editing the graph; editable fields, menus, dialogs, IME composition and active graph/numeric gestures retain their own keys. The footer keeps the persistent graph-saved, Shader-applied or pending state separate from temporary operation messages. A repeated saved/applied message is displayed once; ordinary operation messages cannot hide errors. Matching successful retries clear their error. The location row and footer are each 32px high, with 3px vertical padding and 24px-high controls. The location row has 8px horizontal padding. The two dedication lines in About are centered.

At 100%, graph nodes, graph zoom, panel tabs and panel content retain their existing dimensions. Light appearance uses neutral light surfaces throughout the workspace, including a soft gray canvas, light nodes and pastel category headers. Typed ports and wires retain their hue distinctions with deeper colors for contrast on the light canvas; RGBA component hints, selections, errors and numeric editors follow the same palette. Shader preview pixels are not recolored, and source code retains its separate syntax palette. The preference change does not apply a Shader, add Undo history or rebuild node editors.

`localStorage.sgrapeAppearanceV1` stores `{size, theme, tones: {dark, light}, scale}` on the current device, for this browser profile and Editor address. Each tone is a relative integer from -100 to 100, with 0 preserving the selected preset exactly. Existing `{size, theme}` settings load both tones at 0; the previous single `tone` migrates to its active theme only. Invalid tone values recover to 0 and finite out-of-range numbers are clamped. Missing or invalid scale values default to 100%; finite values are rounded and clamped to 75–125%. If the scalar scale is absent, the former per-preset scales map migrates the currently selected preset’s value into the shared scalar; a present but invalid scalar recovers to 100%. The preference is independent of Shader JSON and the TD project. If local storage cannot be written, the controls still work for the current page.

Tone is calculated from immutable base-theme color tokens and applied through root CSS variables, without a page filter or DOM recoloring pass. The main UI surfaces, text, fields, node palettes and graph background follow a restrained tonal curve. For weighted RGB brightness L and slider s in [-1, 1], the target is `pow(L, exp(-strength*s))`. The adjustment strength is 1.5 times the previous range. Brightening uses strength 0.48, blended with the original by `smoothstep(0, protection, L)`; protection is 0.35 in Dark and 0.10 in Light. These are shadow-protection thresholds, not fixed middle-gray anchors. Darkening uses strength 0.60 in Dark and 0.825 in Light without the protection blend. The shared proportion toward white or black retains channel ordering and alpha. Returning to 0 removes all tone overrides. Theme and tone changes remain immediate. A 0.5-second CSS color-transition experiment was removed after a 200-node browser probe showed substantial animation overhead; the user explicitly preferred omitting damping over added cost or complexity. There is no animation loop, delayed color state, layout transition or preview filter. Preview image pixels, authored color swatches and GLSL syntax colors remain independent. Tone dragging does not rerender nodes or wires, change layout/graph zoom, add Undo steps or send API writes. Moving focus away from a numeric field still follows its ordinary blur-commit behavior; appearance updates do not add an extra graph edit.

Search crosses category paths; source/type and connection compatibility are independent filters. Dragging the header repositions only the browser, retaining the original graph insertion point and optional wire. Search/category updates retain the dragged location; reopening starts from the new invocation point.

Numeric fields share one left-drag gesture across the graph and Parameter panel. The current displayed decade and the initial rendered field width determine sensitivity: within a range, one field-width of motion changes one span, quantized to one thousandth of that span. Ctrl multiplies speed and increment by ten, Shift divides both by ten, and Ctrl+Shift divides both by one hundred. The range follows the current value throughout a held drag, including when reversing across a boundary; only field width stays fixed. Continuous piecewise travel accounts for all crossed ranges inside one pointer event, so fast and finely sampled movement agree. Manual baseline precision is preserved. Whole-number fields retain integer increments. One release makes one Undo entry; cancellation writes nothing. The proportion fill keeps its existing signed decade mapping. Touch uses the same numeric scrub through horizontal dragging, a 450 ms hold for Value Ladder without autofocus, and a double-tap to enter text editing; a single tap does not focus the field. Initial vertical motion retains pane scrolling or graph navigation. Mouse and pen behavior is unchanged; see [Touch editing](TOUCH_EDITING.md#numeric-fields-on-nodes-and-in-parameter).

### 全螢幕與專注編輯

Footer 的最右側按鈕呼叫瀏覽器原生 Fullscreen API，以 `fullscreenchange` 同步實際狀態；不支援時停用按鈕，請求被拒絕時保留目前介面。網路圖「置中」右側的「專注編輯」只隱藏周圍介面，讓現有網路圖與工具列填滿視窗，不進出瀏覽器全螢幕；按「還原介面」回到原先配置。兩種模式可以獨立使用。進入專注編輯時，網路圖右下角會出現全螢幕按鈕，便於在專注模式直接切換；一般圖面不顯示這個快捷。

專注編輯不重建或搬動節點與面板 DOM，也不改動 Layout、圖、Undo 或縮放／平移。Esc 優先取消輸入、接線、選單或對話框，再還原專注模式；瀏覽器全螢幕的 Esc 由瀏覽器處理。視窗大小與全螢幕切換只重畫連線，保留目前視點，需要重新取景時使用「置中」。專注模式是本次頁面的臨時狀態，不寫入儲存的 Layout。

### QR sharing

The footer QR button sits immediately before interface size (Aa). Its centered modal dialog lists the current origin and actual listener addresses from the authenticated, read-only `share-links` endpoint. From a loopback page it initially selects an available LAN address; otherwise it retains the current origin. It carries the effective Shader route and current session token in the link fragment. LAN-disabled listeners expose no LAN choices; missing transferable tokens suppress unusable alternate origins. Discovery failures leave the current-page link usable. No LAN setting, firewall, graph or history changes are made.

The QR code is encoded locally by the vendored MIT qrcode-generator and rendered as a high-contrast SVG with a four-module quiet zone. Copy uses the browser clipboard when available, then legacy copy on HTTP LAN pages, then selects the URL and asks for manual copying if neither succeeds. Chrome-specific Send to devices is omitted. The 360px-wide dialog and 288px QR are larger for scanning another screen; width and height adapt to narrow or short viewports. A close button, Escape or a backdrop click dismisses the dialog and returns focus to the opener. Background UI stays inactive while sharing is open. Addresses are candidates, not a reachability guarantee. QR/link contents are not persisted separately.

`test_ui_share.cjs`, `test_qrcode_roundtrip.cjs` and `test_share_links.py` cover rendering/independent decoding, source selection, clipboard fallbacks, narrow layouts and existing authentication boundaries. Refresh-preserved Undo/Redo remains an optional future improvement; page reload currently resets the in-memory history.

2026-09-17 color investigation (no palette change): Dark location/navigation and the normal graph toolbar share `--ui-tone-chrome: #1c1b23` (RGB 28, 27, 35), whose base gray already has a slight blue-violet bias. The active stage and breadcrumb text are also violet-tinted. Tone adjustment blends the original channels toward neutral black/white without adding a separate purple overlay; these surfaces have no backdrop filter. The floating-toolbar flag reveals the canvas beneath its transparent surface. Light chrome remains the cool gray `#e7e9ed`. Whether to neutralize these colors is deferred for visual review.

Colored Inputs source rows, including TOP inputs, constants, uniforms and TD Built In, use a smaller shadow than canvas nodes: `0 2px 6px #0003` in Dark and `0 2px 6px #29384d18` in Light. It belongs to the complete row, retaining the existing category background, dimensions, focus/selection outlines and drag behavior.

## Experimental UI preferences

The footer gear precedes QR, size, appearance and fullscreen. It opens a small rounded popover with every current `EDITOR_DEV_DEFAULTS` entry: ten checkboxes, the Arrow/Move cursor choice and the Professional/Cool/Excellent/Legendary/Godlike style choice. Labels and hover descriptions are bilingual. The panel shares the appearance popover placement and UI scale, supports keyboard focus/Escape and light dismissal, and scrolls in short viewports. Reset defaults restores all current defaults.

| Preference | Default |
| --- | --- |
| Canvas trash | Off |
| Floating toolbar | Off |
| Drag nodes by their body | On |
| Node drag cursor | Arrow |
| Node resize hint | On |
| Triangle on expanded nodes | On |
| Triangle on collapsed nodes | On |
| RGBA component colors | On |
| All vector component colors | Off |
| Disconnect newly incompatible wires | On |

Changes apply immediately and are stored in browser localStorage under `sgrapeExperimentsV1`; malformed or unknown values fall back to the known defaults. Graphs, Layout, Shader data and Undo are not rewritten. Existing numeric/name fields keep their DOM and drafts; active edit gestures are canceled before changing behavior, while an active mouse pan/box selection must finish first. The same toolbar DOM moves reversibly between its fixed and floating positions. Hidden resize/collapse hints do not remove the underlying resize or context-menu actions. All-vector tinting uses component order for XYZ/W, UV and other vector labels, and includes RGBA even if its narrower switch is off. The RGBA switch continues to work independently when all-vector tinting is off. Automatic disconnection affects future type changes only. The enabled trash target sits at lower right above the view controls, with a gap in both desktop and touch layouts.

Experimental controls are chosen case by case from the current discussion. Adding a feature does not itself require a flag; the gear lists those settings that have been deliberately registered.

The Visual Capability / 表現能力 style selector defaults to Professional (the existing appearance). Glow is limited to Dark mode, with four additive tiers:

- Cool adds glow only to colored wires, selected-node outlines, the grape logo (also in About) and Apply Shader. Unselected nodes, node names, ports and the main product title retain their Professional appearance. Selected outlines use the selection color; selected nodes with errors keep the error color.
- Excellent retains all Cool effects and adds category-colored outer glow around whole nodes and their names, colored ports, the main TD-Grape title (also in About), Parameter category titles/names, colored Input rows/names, the active Pixel/Vertex stage and pressed toolbar controls.
- Legendary retains the Excellent scope and adds a slow four-second breathing glow after the one-second entry fade, cycling alpha from 33% to 50% and back.
- Godlike retains the same scope with a stronger 50% halo whose direction circles the outside every 4.8 seconds. CSS animates an angle and derives the halo offsets with sine/cosine: 7px for surfaces, 2.8px for wires/logo and 2.1px for names. The elements themselves never move and category/type hues stay unchanged.

Cool/Excellent glow alpha is 33%; node/Parameter/Input halos use a broad 20px blur, main names use 12px, and the grape logo uses 8px. In Excellent and higher tiers, nodes glow around the entire card, deriving hue from the category background with boosted saturation/lightness (a CSS color-mix fallback is provided). Gray body fills and original depth shadows remain unchanged; there is no added inner glow. Selected/error nodes retain their state-colored outline with the same category-colored halo; pending deletion retains its existing warning cue. Small or faintly colored metadata stays unchanged. The isolated CSS rules reuse existing color tokens; no new rendering layer or graph fields are introduced. The animated tiers use registered CSS percentage/angle properties and root keyframes. No JavaScript animation loop, renderer layer, DOM wrapper, node-ID grouping or graph metadata is added. Switching back to Professional removes the effects. Light mode keeps its original appearance for every tier and remembers the preference for Dark. Existing saved Cool preferences remain Cool under the narrower scope. Only changing the visual mode transitions for one second. Three inherited CSS intensity levels control common accents, detailed accents and the Cool selection halo; the root transitions these levels and the base glow alpha. The elements themselves have no shadow/filter transitions, so selection, hover, pressed buttons, wire targets and enabled/disabled states react immediately, including during a mode fade. Transparent halo definitions remain in Dark Professional so the inherited intensity can fade all the way to zero. Legendary/Godlike keyframes continue to animate their existing alpha/angle; animation phases do not require a separate handoff system. Pure style/clock changes and theme changes preserve wire DOM; geometry-changing preferences still redraw wires. Light and reduced-motion preferences disable mode transitions; reduced motion also stops the glow animations and centers the static halos. No JavaScript animation trigger or timer is needed, and the former transparent-filter interpolation workaround is removed because filter itself no longer transitions.

The optional system clock is a plain local 24-hour `HH:mm` display in the footer, immediately before the fullscreen control. It starts no timer while disabled. When enabled, one timeout updates at the next minute boundary; returning to a visible page refreshes the displayed time. Disabling it clears its timer/listener, and the graph-focus view does not add a separate clock.
