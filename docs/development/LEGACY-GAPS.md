# 舊產品漏接清查

舊產品＝`legacy` 分支 `90a946b`（0.8.276，凍結）。舊產品的 STATUS 記的是**演進過程**：同一能力可能先做 A、後改 B。本頁以「功能」為單位，只寫**最終狀態**，演進只留一兩句當出處；最終狀態以舊產品程式為準，文件與程式不一致時標出。

判定：✅ 新架構已接上｜❌ **漏接**｜⏸ 刻意不做或已另案處理（附出處）｜❓ **不確定／待人類判斷**。

**人類只需看 ❌ 與 ❓**，回覆「對／不對／要討論」即可；確認後 ❌ 轉入 [CURRENT](CURRENT.md) 待處理。分批進行，每批約 10 條。

**排程原則（人類 2026-10-07）：** 重構的目標不是一次做出完整產品，而是**先把核心功能全部做完，再處理 UI/UX**。清查出的 UI/UX 漏接照樣記在本頁，標「核心完成後」，不排進目前各輪。
