# 向量、節點內數值與常數

本輪把建立數值、組合、替換及拆分分開，讓接孔直接表達用途。正式版本、原生驗證與保存結果以 [STATUS](../development/STATUS.md) 及 [TESTING](../development/TESTING.md) 為準。

## 功能分工

| 節點 | 輸入 | 輸出 | 用途 |
| --- | --- | --- | --- |
| Scalar（`scalar`） | 無接孔；手填數值 | 一個純量 | 可選 float／int／uint／bool |
| Vector（`vector`） | 無接孔；手填分量 | 一個完整向量 | 可選四種數值家族、2～4 分量 |
| float／int／uint／bool | 無接孔；手填數值 | 名稱所示的固定型別 | 直接建立固定型別的純量值 |
| vec2～4／ivec2～4／uvec2～4／bvec2～4 | 無接孔；手填分量 | 名稱所示的固定型別 | 直接建立固定型別與維度的向量值 |
| Combine | 相同家族的純量或連續向量分組，未接部分可手填 | 一個完整向量 | 接線組合資料 |
| Replace | 完整向量基底及分量覆寫 | 一個完整向量 | 替換既有向量的一部分 |
| Split | 一個完整向量 | X／Y／Z／W 等分量 | 拆分資料 |
| Swizzle | 一個完整向量 | 選取、重排或重複後的結果 | 表達 `.yx`、`.xyxy` 等操作 |
| Color RGBA | 無接孔；手填 RGBA 與調色 | 一個 vec4 | 建立色彩數值 |

新增清單提供 16 種固定型別入口，同時保留 Scalar 與 Vector。固定入口共用 Scalar／Vector backend，保存 `params.fixedType` 與相同的 `params.type`；核心拒絕兩者不一致，畫布標題與 Parameter 都不提供型別切換。固定身分隨 JSON、剪貼簿與 Undo／Redo 保存。舊 `float`／`vec2`／`vec3`／`vec4` 定義仍可辨識，但新增清單只提供新的固定入口。

Generic Scalar／Vector 的標題固定為 **Scalar／Vector**，更改型別或維度不重新命名。搜尋 `int` 會找到 `int` 與 Scalar，搜尋 `vec3` 會找到 `vec3` 與 Vector；alias 只影響搜尋。一般新增時 Scalar 使用 float、Vector 使用 vec2，查詢文字不暗改預設配置。明確從接孔新增仍可依連線上下文選擇相容型別；固定入口始終維持其型別。使用者的自訂名稱保持獨立。

舊的完整輸入、覆寫與拆分共存的 `vector` 介面已移除。使用者明確允許這次 Alpha 前例外，不建立舊 Vector 圖遷移或相容分支；含舊接孔的圖需刪除或重建，不靜默改變計算結果。這不延伸為 Alpha 以後的相容性政策。

## Vector 與 Color 的分量編輯

Vector 保存 `params.type`（vec／ivec／uvec／bvec 的 2～4 分量型別）與四分量 `params.components`。有效維度決定顯示與產碼，generic Vector 縮小後仍保留其餘手填分量，之後放大可以恢復。固定向量使用相同的分量編輯、標籤、Split 快捷與數值行為，只限制型別切換；Color RGBA 保留現有獨立色彩編輯入口，不增加新的 fixed type。

- 收合時數值同列排列，提供緊湊但可直接編輯的欄位。
- 展開時每個分量各占一列，附上 X／Y／Z／W 或 R／G／B／A 名稱。
- Color 保留 RGB 調色入口與 Alpha，不因展開與收合改變值。
- `ui.componentsExpanded` 只改畫布呈現，不改接線、常數性、GLSL 或套用語意；Subgraph 內相同。
- 一般多分量輸入不增加一整排內嵌欄位；完整值仍在 Parameter 編輯。

Replace 分量維持展開，輸入與完整輸出分列。主輸入預設 Auto，僅依完整基底推導向量型別，亦可手動鎖定；未接基底時保留目前型別。手填分量與零初值維持，接上基底後未覆寫分量沿用基底。

## Replace：基底與連續覆寫

完整輸入 `value` 必須和節點型別一致，提供所有分量基底。個別接線覆寫對應位置；沒有分量線時沿用基底，基底也沒接線才使用保存的手填值。唯一 `out` 是覆寫後的完整結果。

例如基底 `vec4(1, 2, 3, 4)`，Z 接 float 9，輸出 `vec4(1, 2, 9, 4)`。如需 Z 的值，將結果接到獨立 Split。

vec2／vec3 從指定位置占用連續分量，只保留起始接孔，以 XY、YZ、ZW 顯示範圍。vec2 接 Y 後形成 `YZ · vec2`，獨立 Z 接孔消失，X、W 保留。要單獨接 Z，先拆掉或縮小 YZ 接線。

新接線可取代占用範圍內整條舊分量線：

- 原本 Z 接 float，新 vec2 接 Y：移除 Z 線，改由 YZ 提供。
- 原本 ZW 接 vec2，新 vec2 接 Y：整條 ZW 線移除，W 恢復基底或手填值。
- 只移除衝突線；來源節點、其他接線與完整基底保留。
- 拆線、接線與接孔合併是一次圖操作，一次 Undo 完整恢復。
- 不自動截斷或複製分量，例如 vec3 不能從 vec4 的 Z 接入。

2026-09-17 使用回饋確認：Combine 與 Replace 共用直接接線的覆蓋規則。vec3 接 X 可取代 X／Y／Z 原有的線、保留 W；vec3 接 Y 可取代 Y／Z／W、保留 X。若和舊向量線部分重疊，仍移除那整條舊線，釋出的分量恢復手填值。拖曳预覽標出涵蓋範圍及將被替換的原線，取消不改圖，放開才以一步 Undo 提交。反向拉線與從接孔建立新節點也使用同一規劃。只有明確直接連入此節點才會覆蓋；上游 Auto 推導不因此偷偷踢掉其他線，超出維度、隱藏接孔、迴圈與常數限制仍會拒絕。

## 標題、名稱與快捷型別

一般節點保存獨立的 `node.name` 作為可讀識別字，與穩定 `id` 分開。建立時給不重複的遞增名稱；工具列「顯示自訂名稱」只切換畫布原始種類／自訂名稱的顯示，不改產碼。Parameter 標題固定左側原始節點名、右側自訂名稱編輯欄，不受此開關影響；來源引用右側顯示來源名稱，不建立獨立別名。Uniform、常數、TOP Input 等來源引用跟隨來源名稱，不能獨立建立別名。

自訂名稱在畫布標題原地編輯，Enter 或失焦提交，Escape 取消。畫布編輯框沿用原標題的行高與字型，錯誤訊息浮出顯示，不增加標題高度或推移接孔；Parameter 的名稱欄維持原尺寸。空格整理成底線、非法字元攔截；輸入法組字完成後才處理。名稱須符合目前的安全 GLSL 識別字規則，在所在圖中唯一；保留字、保留前綴和重名不能提交。

編譯器以名稱生成 `sg_n_<名稱>` 等局部符號。已命名 Subgraph 呼叫展平後，內部名稱加上呼叫路徑，例如 `sg_n_Tint_Apply_Tint`、巢狀 `sg_n_Outer_Tint_Apply_Tint`；輸入 relay 使用 `<路徑>_input_<接孔>`，輸出使用 `<路徑>_<接孔>`。真正重名時沿用穩定消歧後綴，合併連續底線並對過長路徑加穩定短碼。未命名的舊呼叫保持原產碼，穩定 node ID、接線及錯誤 sourceMap 保持。實際改名影響圖指紋與 GLSL；位置、分量展開與名稱顯示模式不影響。

標題副欄提供既有 Parameter 型別或主要模式的快捷下拉，兩處寫入同一參數，選項與錯誤處理一致。明確修改節點型別或接孔形態時，先讓 Auto 下游推導。`EDITOR_DEV_SETTINGS.autoDisconnectInvalidEdges` 預設開啟，只移除本次變更造成的新失效接線，與型別變更合為一次 Undo；其他既有失效線保留。關閉 flag 時保留原接線與未套用草稿，缺失分量顯示停用接孔及虛線。一般接線／數值修改不因此清線。一般編譯錯誤不顯示成版本升級，也不鎖住圖；TD 保留上次成功輸出。接線本身的範圍、迴圈與常數檢查仍依原有流程；直接勾選「必須為編譯期常數」仍拒絕執行期來源，來源宣告編輯的既有規則也不因此放寬。

## 節點寬度

標題型別快捷以透明無框文字呈現，開啟時也不增加直角焦點框。預設名稱模式只保留既有型別快捷；自訂名稱模式補回原始節點用途，例如 `Vector · vec3`、`Combine · vec4`，不堆疊 GLSL／Constant 分類。沒有型別快捷的 Float 只補原始節點名。來源引用始終顯示種類與型別；Texture Coordinates 在 TOP 顯示 `vUV.st`，在 MAT 顯示第一組貼圖座標 `UV 0`。副標文字、中點與選單共用字型、字級、字重與亮度，以文字基線對齊。有無選單的標題列維持同高；Texture Coordinates 的來源提示位於右側副標，保持單行。Uniform 與 Vector 系列的完整輸出統一顯示 `out`，來源名稱保留在標題。

拖曳節點右下角可水平调寬。最小寬度維持原有基準（一般節點 190px，手填分量類 230px）；未手動指定寬度時，依整顆節點的標題、副標、接孔名稱和數值計算能讀清內容的預設寬度。手動可縮到最小值，文字空間不足時省略，但型別選單不壓縮到被箭頭遮住。最大寬度先採寬鬆的 1200px（畫布單位），沒有獨立調高把手。

副標整組靠右；型別快捷的目前值也靠右，Auto 與指定型別共用文字到箭頭的間距，不因選單為其他選項保留寬度而讓短型別停在左側。

程式設定 `EDITOR_DEV_SETTINGS.nodeDragCursor` 預設為 `default`，可改成 `move` 試用十字移動游標；不影響文字、選單與調寬游標。`nodeResizeHint` 預設開啟，顯示與右下圓角同圓心的內縮圓弧；關閉只隱藏提示，不移除調寬操作。兩項均可在 footer 齒輪的「實驗功能」即時切換；游標提供一般箭頭／移動。設定只保存在目前瀏覽器，不寫入圖資料。

寬度保存在 `node.ui.width`，與圖一同保存、匯出及復原；它只影響排版，不改型別、接線或 GLSL。拖動時接孔與接線跟隨，放開只記一筆 Undo。Escape、失焦或手勢取消恢復原寬度；唯讀圖保留尺寸但不能拖曳。置中與錯誤定位使用目前節點尺寸。

## 節點收合

名稱左側的三角形收合／展開整顆節點；右鍵也可處理所選節點，混合選取時先全部收合。`nodeCollapseExpandedHint` 與 `nodeCollapseCollapsedHint` 分別控制兩種狀態的三角形，預設皆開啟，關閉後仍可由右鍵恢復。

輸入、輸出各按解析後接孔數判斷：單孔保留型別色及完整接線能力；多孔以中性摘要點匯集既有線，展開後才能新增接線；零孔不顯示點。收合不刪線，原有線仍可選取與移除。`node.ui.collapsed` 隨圖保存及 Undo／Redo，複製／匯入保留；展開寬度另保存在 `node.ui.width`，收合不覆寫它。這是排版操作，不改 GLSL，也不使外部 Subgraph 自動在地化。

## 內嵌數值與 Value Ladder

固定 Float、Vector、Color 與一般節點適用的未接線 float 入口，和 Parameter 共用同一份值。

- 節點數字框為一致中性底色、左對齊、無常態框線，保留聚焦／錯誤輪廓。RGBA 可由程式 flag 淡染數字。
- Enter 或失焦提交，Escape 還原；空白、非有限數字不寫入圖。
- 所有數值欄位（包含向量與 RGBA 各分量）在未進入文字編輯時可左鍵水平拖曳調值，點放進入文字編輯；已聚焦時保留文字選取。浮點拖曳以目前比例底範圍及按下時的實際欄寬換算：同範圍內水平走一個欄寬約改變一個範圍，最小增量為目前範圍的千分之一；Ctrl 將速度與增量乘 10，Shift 除 10，Ctrl＋Shift 除 100。持續按住跨過 1／10／100 時，速度與增量立即跟隨新範圍；反向拖回也改回較小範圍。跨界前後的位移分段換算，數值連續，快速或分多次移動得到相同結果。增量加在原值上，保留手填精度；整數仍採整數步進。
- 比例底按 0～1、0～10、0～100 等十進範圍顯示；負值改用對應負範圍到 0，始終左亮右暗、向右增加。範圍邊界沿用原本重新映射，不限制實際值。
- 中鍵、Alt＋右鍵，或按住約 450 毫秒使用 Value Ladder；列表只有 10、1、0.1、0.01、0.001 五級，中央 0.1 對齊按下位置，靠近視窗邊緣時限制位置。上下選級距，左右調值時改為欄位上方的「目前值＋Δ 級距」提示（上緣不足時放下方），使用介面尺寸、不受圖縮放影響。開始左右調值後鎖定級距；原列表不再命中或重新出現，下一次手勢才重新選擇。沒有標題、說明或亮邊；欄位 tooltip 分行呈現，階梯啟動期間暫時隱藏，Help Panel 維持節點說明。Ladder 原有每 8 螢幕像素一級距的調值規則保持。
- 拖動暫存，放開一次提交、一次 Undo；取消還原，不沿途反覆套用 Shader。
- 數值編輯不觸發節點拖曳、接線或畫布快捷鍵。來源、節點或圖改變時取消失效草稿。
- 觸控單點不進文字編輯，雙點同一欄位才開啟；左右滑動沿用同一套數值拖曳，長按約 450 毫秒開階梯且不自動 focus。開始調值前的上下移動保留 Parameter 捲動／畫布導航。已進入文字編輯時保留原生游標與選字；滑鼠／觸控筆維持原操作。詳見 [觸控數值操作](../ui/TOUCH_EDITING.md#numeric-fields-on-nodes-and-in-parameter)，實機驗證限制以 TESTING 為準。

一般節點 Parameter 採名稱、型別、值同列：固定三角形槽，名稱欄靠右、型別欄靠左，數值／連線來源共用其餘右側欄位。欄位起點不隨各列文字長短移動；数值框為 24px 高、無常態外框並共用上述操作。vec2／vec3／vec4 可展開具名分量，同時保留原完整數值列，兩處同步預覽與提交；展開偏好只存在目前面板狀態。輸出型別仍在內容上方，註記移入獨立分頁；Settings、Uniform／來源引用的編輯流程維持。

## 拆分快捷與常數性

向量輸出的拆分快捷建立已接線的 Split，已有對應 Split 就選取它；不再建立萬用 Vector。UV／RGBA 分量名稱可沿用；顯示別名與淡色 flag 不改型別、不自動傳染到下游。

只改 UV 的 V，可以使用 Texture Coordinates → Split → Add，再將完整 UV 接 Replace 基底、Add 接 Y。不把最終輸出繞回本身輸入。

型別與常數性分開：Vector、Color 與合法常數運算可形成常數表達式；Uniform、UV 等不會被凍結。「必須為編譯期常數」仍由 UI 與編譯器檢查，包含 Subgraph。GLSL Code 函式呼叫不因傳入常數就成為合法常數表達式。

Replace 基底被全部覆寫時，不單為休眠基底生成 Uniform binding 或使結果失去常數性。只覆寫部分而其餘依賴執行期資料時，完整結果仍是執行期值；現在沒有獨立分量輸出。

Spec Constants 是另外的來源類別，對應 TD Constants 頁面，不與 Graph Constants 混為同一種常數表達式推導。原生同步與歷史操作見 [Inputs 工作流程](INPUTS_WORKFLOW.md)。

## 驗證

`test_unified_vector.py` 驗證 value-only Vector／Replace 的接孔、群組、基底、斷線、有效常數、Subgraph、迴圈與展開狀態；`test_node_names.py` 驗證名稱合法性、可讀產碼、重複 Subgraph 與多輸出符號碰撞。既有 138 份基礎節點產碼指紋仍須通過。

`tests/td/test_unified_vector.py` 使用可刪除的 TOP／MAT 區域，驗證實際像素、分組替換、獨立 Split、常數陣列界限與可讀名稱的原生編譯，清除測試區並確認使用者 Shader 原樣保留。當輪實際結果由 TESTING 記錄。

Texture Coordinates 與 TD Position 使用共同 Attribute／屬性來源色系，包含畫布標題、Parameter 身分列與 Inputs 來源列；TD Deform／To Clip 等處理函式不因此改色。深色為低飽和暖灰褐、明亮模式為淡米灰，集中由 `--node-attribute-bg`／`--node-attribute-fg` 管理。此為視覺角色，不改新增節點分類、編譯行為或接孔／線條型別色。


2026-09-17 內建 Subgraph 名稱：Tint、Invert、Contrast、Color Clamp 的 20 個內部節點均有合法、唯一的 `node.name`，例如 Apply_Tint、Invert_RGB、Restore_Pivot。來源 ID 保持，內容版本隨名稱更新；新加入的預設子圖帶有名稱，保存過的舊快照維持原狀。名稱隨匯入、在地化與個人資產保存。
