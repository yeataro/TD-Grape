# 向量、節點內數值與常數

0.8.82 開發版。本輪把完整向量、分量覆寫與節點內數值編輯做成可操作原型，後續依使用回饋調整。原生 TD 驗證、正式保存與提交狀態以 [STATUS](../development/STATUS.md) 及 [TESTING](../development/TESTING.md) 為準。

## 入口與相容

| 節點 | 用途 | 分類 |
| --- | --- | --- |
| Vector（新 `vector` 定義） | 選擇 vec2／vec3／vec4；完整輸入、分量覆寫、組合與拆分共用一個節點 | Vector／Data |
| Float／Vector 2／Vector 3／Vector 4 固定值 | 無輸入接孔的固定值來源；保留舊定義與圖的行為 | Data |
| Color RGBA | vec4 固定值，保留色彩編輯介面 | Color |
| Split／Combine／Swizzle | 保留既有拆分、組合與分量重排節點 | Vector／Data |

新 Vector 的畫布標題依型別顯示 Vector 2／3／4。它是新的定義，不把舊固定值或 RGBA 節點轉換成另一種語意；新增本身不代表所有舊圖需要升級。

## Vector：完整值與分量

完整輸入 `value` 必須和節點型別一致，提供所有分量的基底。個別分量接線覆寫對應位置；沒有分量接線時沿用基底，基底也沒接線才使用保存的手填值。完整輸出 `out` 與 X／Y／Z／W 輸出都代表**覆寫完成後的結果**。

基底接線後，所有手填欄位隱藏，可接線的分量接孔仍保留。拆掉分量線後恢復基底；再拆掉基底才重新顯示原本手填值，不清空保存值。例如基底是 `vec4(1, 2, 3, 4)`，Z 接入 `float 9`，完整輸出是 `vec4(1, 2, 9, 4)`，Z 輸出是 `9`。

## 連續分組與替換

vec2／vec3 從指定位置占用連續分量，只保留起始接孔，名稱明示 XY、YZ、ZW 等範圍。vec2 接 Y 後形成 `YZ · vec2`，獨立 Z 接孔與手填欄位消失，X、W 保留。要單獨接 Z，先拆掉或縮小 YZ 那條線。

新 Vector 的新線自動取代占用範圍內的整條舊分量線：

- 原本 Z 接 float，新 vec2 接 Y：拆掉 Z 的線，改由 YZ 提供。
- 原本 Z 接 vec2、占用 ZW，新 vec2 接 Y：整條 ZW 線移除，W 恢復基底或手填值。
- 只移除連線；來源節點、它的其他線及完整向量基底保留。拖曳時預示受影響範圍，放開才修改。
- 先驗證新圖，再一次完成拆線、接線及接孔合併；一次 Undo 完整恢復。型別、範圍、迴圈或常數要求不合法時，原圖不變。

不自動截斷或複製分量，例如 vec3 不能接到 vec4 的 Z。縮小型別若會破壞既有連線也會拒絕。舊 Combine 保留 0.8.80 的邊界：支援所有合法 float／vec 組合，但不會自動拆掉其他已接線分組；新規則不改寫舊圖。

## 節點內數值與 Value Ladder

Float、固定向量、Color RGBA，以及適用的未接線數值輸入，都可在節點上直接編輯，與 Parameter 使用同一份資料。接線後欄位隱藏，解除後恢復保存值。UV 等原本具有隱含來源的入口不會被換成數字預設。

- 點數字輸入，Enter 或離開欄位提交，Escape 還原；空白、非有限數字不寫入圖。
- 中鍵、Alt＋右鍵，或按住約 450 毫秒開啟 Value Ladder；上下選精度，左右調值。階梯使用畫面座標，不隨圖的縮放改變靈敏度。
- 階梯拖動只暫存數字，放開才提交；取消還原，一次提交一次 Undo，不沿途反覆套用 Shader。
- 數字欄位不啟動節點拖曳、接線或雙擊新增；編輯鍵盤事件不交給畫布。無關畫面更新保留焦點與草稿；來源、節點或圖已變更時取消失效草稿。
- 觸控短按輸入、長按使用階梯；長按成立前滑動則取消階梯並平移畫布。多指、失焦及取消事件不得遺留拖曳狀態；實機驗證範圍另見 TESTING。

本輪不新增 Uniform 即時值的第二份畫布編輯資料，也不改它既有原生同步方式。

## 拆分、重排與快捷

Split、Swizzle 保留依 vec2／vec3／vec4 顯示接孔的規則。Swizzle 可取出、重排或重複 1–4 個有效分量，例如 YX、YXY、XXXX。Settings 的 XYZW／RGBA／UV 別名只改文字，不改接孔身分或型別。

向量輸出旁的分支快捷現在新增接好的 Vector；已有對應 Vector／Split 時選取它。UV／Color 的別名隨新增沿用。接線新增選單優先適合當前型別的 Vector 等常用操作。

只改 UV 的 V，可用上游 Vector／Split 取出 V → Add → 下游 Vector 的 Y 覆寫，完整 UV 接下游基底。不能把同一 Vector 的最終 Y 輸出繞回自己的 Y 輸入，因為那會形成迴圈。

## 編譯期常數與有效來源

型別與常數性分開。固定值與合法常數運算保留常數性，Uniform、UV 等來源不會被凍結。Settings 的「必須為編譯期常數」由 UI 與編譯器檢查，包含 Subgraph 邊界；GLSL Code 使用者函式不屬於常數表達式。

- 基底被全部分量接線覆寫時，不因保留的基底線而失去常數性，也不單為這條失效依賴生成程式或 Uniform binding。
- 單獨讀取已由常數覆寫的 X，其他執行期分量不會污染 X，也不只為它們產碼。完整輸出若仍含執行期分量，仍是執行期值。
- 分組向量來源仍保守以整個來源輸出的常數性判斷；本輪不是任意 GLSL 表達式的完整分量推導器。

沒有使用新能力的舊圖保持既有產碼。int／uint、Specialization Constants、陣列／Buffer 編輯與完整常數視覺系統不在本輪範圍，仍見 [數值型別計畫](../discussions/NUMERIC_TYPES_PLAN.md)。

## 驗證

Python 語意測試涵蓋分組、基底、斷線、替換、最終分量、有效常數、Subgraph、迴圈與識別字衝突；原有 138 份產碼指紋保持一致。瀏覽器 inline 操作與 TD TOP／MAT 原生數值測試已加入；當輪實際通過項目、實機限制及版本保存結果由 STATUS／TESTING 記錄，不以 0.8.80 的驗證代替本輪結果。
