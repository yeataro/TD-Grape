# 匯入檢查與明確接受 — 0.6

2026-09-21 校正：本文保留 JSON 匯入初期紀錄。下面「PNG 未實作」的歷史筆記已由 [PNG 圖交換](PNG_EXCHANGE.md) 完成；圖封存包含節點實作與相依資產仍是另一項提案。

在編輯器按 **匯入圖** 選擇 JSON 後，會先開啟檢查視窗。此時不改目前的圖、Undo／Redo、TD 狀態或輸出。檢查只使用共用核心做資料與產碼驗證；TD 的真正 Shader 編譯在接受後才進行。

## 使用方式

- 有效檔案：查看檢查結果，按 **接受並匯入**。這會取代目前圖，並沿用自動編譯流程。若 TD 編譯失敗，仍保留最後成功輸出。
- 可以明確修復的檔案：視窗列出變更，可展開「原始 JSON」與「修復後的 JSON 預覽」。按 **接受修復並匯入** 才會使用修復版本。
- 無效 JSON、較新格式、未知節點或其他阻擋問題：接受按鈕停用，原始內容仍可查看及下載。關閉視窗繼續原有工作。
- 接受匯入後，一次 **Undo** 還原匯入前的圖；**Redo** 重新套用匯入圖。關閉檢查視窗不增加歷史。

檔案上限為 512 KB。下載原始檔使用所選 File 的原始位元組，保留 BOM 等資訊；不將修復後 JSON 偽裝成原檔。瀏覽器暫存草稿在使用者選擇恢復後，也會進入相同檢查流程。草稿的下載是圖資料的 JSON 表示，並非另一份原始磁碟檔案。

檢查期間若目前圖已改變，接受會被拒絕並要求重新選檔檢查，避免較舊的操作覆蓋新的編修。較新 Shader 元件的唯讀保護仍適用。

## 目前會提出的修復

1. 補上缺少的空宣告清單，讓未使用宣告的圖可以被編輯器讀取。
2. 為缺漏或無效的畫布座標提出規則排列位置；此項不改 Shader 語意。
3. 在 Shader 圖或本地 Function 中，移除明確找不到節點／已知 port 的連線。報告保留來源、目的及圖路徑，讓使用者知道哪一條線將被移除。

函式庫來源中的語意損壞不自動修補，以免改寫唯讀來源快照。未知定義的 port 不能被可靠推斷，相關連線會保留作為資料。重複 ID 的歸屬、循環、型別不合與缺失 Function 不由工具猜測；這些情況會阻擋匯入。

## 原始規格尚未完成的部分

目前的 repair view 是原始／建議 JSON 與檢查報告；尚不是可直接操作未知節點錨點的圖形修復畫布。未提供舊 schema 的 migration chain、deprecated／archive 歷史解析、重複 ID 的互動重接，或直接修復被外部手改的 TD state DAT。現有圖格式沒有較舊的遷移鏈可供宣稱已測。

內嵌 archive 目前只保留為資料，該內容不會被執行或參與節點定義解析。所有匯入都需要明確接受，沒有外來 archive 的自動部署。

## 服務契約與驗證

寫入端點僅接受 `application/json`（允許 charset）及 JSON object，並保留原有 token、Host／Origin、512 KB 和佇列限制。匯入檢查端點本身沒有修改 TD 的副作用。

40 個核心／文件測試、編輯與匯入操作模型、192 個中英文鍵通過。TD 有 18 項 MAT／TOP 原生檢查，HTTP 有 12 項檢查；真正的瀏覽器驗證包括損壞檔、修復接受、Undo／Redo、未知節點、較新格式、正常檔取消、中英文，以及下載檔案逐位元組雜湊。完整證據見 `VERIFICATION.md` 與 reports。
