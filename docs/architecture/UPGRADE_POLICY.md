# 節點運算行為升級政策

## 已確認的產品決策

2026-09-10，使用者選擇：**先提示差異，確認後才升級；確認前保留上次成功輸出。** 這項決策取代先前「舊 revision／migration 政策待決」的筆記。

當新版 TD-Sgrape 改變舊 Shader 所用節點的運算行為，先顯示受影響節點與新舊差異，讓使用者決定是否接受。取消、稍後處理或尚未確認時，保留上次成功的 GLSL、參數關聯及輸出連線。這表示沿用原 Shader，並非額外把動態影像凍結為靜態截圖。

已經有充分資料證明運算相容的歷史定義，可以沿用。無法確認舊版行為時，必須明示不確定性並要求 review，不能將它當作已知相容，也不能悄悄採用新運算。

確認升級後，仍先由 TouchDesigner 編譯驗證候選結果；成功才提交。編譯或提交失敗時，保留／恢復原 Shader。確認只適用於當次已顯示的差異；圖、版本資料或目標元件若已變更，舊確認不能套用到新的候選結果。

Function 升級限定目前 Shader 的資料，不回寫 TD-Sgrape 共用庫或個人來源資料夾。需變更唯讀來源內容時，要提供目前 Shader 的本地版本，並在差異中說明。具體本地化／舊快照保存方式仍須在實作中驗證，不冒稱已完成。

## 實作與驗收追蹤

0.8.1 封存不變；0.8.2 候選已接入確認流程並通過核心、瀏覽器和原生 TD 驗證，詳見 UPGRADE_REVIEW.md。產品重載／封存進度以 IMPLEMENTATION_STATUS.md 為準。

1. 比對舊 Shader 已保存的 catalog／產碼版本與目前定義，涵蓋根圖和 Function；資料不足、定義移除及介面不相容要明確列出。
2. 準備不修改 TD 輸出的差異預覽與升級候選；不自動猜測接線遷移，不執行外來 archive 程式。
3. 在開啟工程、註冊、Update Shaders、一般套用及匯入等入口核對政策，避免從其他入口繞過確認。
4. 接受前核對目標身分、圖 revision、已展示候選與版本資料；接受後使用現有候選驗證／失敗恢復流程。
5. 用真實 MAT／TOP 驗證：未確認與取消不變更輸出；過期確認被拒；成功才替換；編譯失敗保留原結果；多 Shader 及唯讀來源互不污染。

完成這條版本界線後，再繼續依賴它的新型別、節點與產碼擴充。左側分類已另外確認為節點／圖函式／範例，詳見 LIBRARY_UI_PROPOSAL.md；Auto 型別仍待使用者決策。
