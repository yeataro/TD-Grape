# 已儲存 Shader 資料保護

2026-09-10，0.7.0 封存之後的開發檢查點。

state DAT 被手改成無效 JSON、空白、遺失、含重複欄位／非法 revision，或 Graph 需要修復時，編輯器會進入清楚的保護畫面。它不自動改寫 DAT、不部署空圖、不把修復建議直接當成已接受內容。既有 TD GLSL、Uniform 與渲染保持原樣。

重新註冊已有 Shader 時，空白／缺失 state 不再被當成新元件自動初始化；只有新建立的 Shader 可初始化。損壞 manifest 也會轉成保留原資料的錯誤，不阻止其他 Shader 的管理服務啟動。

## 檢視與還原

- 保護畫面可顯示錯誤、TD DAT 路徑及原文預覽；原文透過獨立的本機認證 GET 讀取，一般 state 回應不攜帶原文。
- 下載保留完整 DAT 文字，沒有重新整理 JSON 或刪掉未知欄位。下載前核對原文 hash；TD 內容已改動時要求重新載入。
- 原文預覽限制 12,000 字元。檢查上限 1 MiB，下載上限 16 MiB；更大的資料需直接在 TD 保存 DAT。原 DAT 不被刪除。
- 編輯、匯入接受、圖匯出、Uniform／texture 寫入和個人 Function 儲存受保護；伺服器亦拒絕直接呼叫，無法只靠舊頁面繞過。
- 瀏覽器既有草稿保留，保護模式不自動還原草稿。使用者在 TD 修復／還原後，Reload 可恢復正常編輯。
- Uniform 的背景輪詢不增加完整 Graph 檢查；保護模式暫停它。完整檢查發生在載入及相關寫入前。

這是安全載入／原文保留，不是圖形化修復或版本 migration；那些項目的既有待決範圍未變。
